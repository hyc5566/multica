STEP 01

先建立你的帳號與工作區

  1. 開啟 註冊／登入頁面，使用自己的電子郵件地址依畫面指示登入；首次使用會建立帳號。
  2. 若畫面要求電子郵件驗證碼，前往信箱收取後輸入；收不到時先檢查垃圾郵件，再聯絡管理員確認寄信服務。
  3. 依引導建立自己的工作區，或透過邀請加入團隊。進入面板後，可以管理議題、Agent 與專案。
瀏覽器出現憑證警告？

s90 使用內網 CA。請向管理員取得並核實公開 CA 憑證，再依組織規範加入瀏覽器／系統信任。不要直接略過警告。App 內建 s90 信任，但不會替瀏覽器安裝憑證。

完成標準：能用自己的帳號進入工作區面板。這一步還沒有替你安裝 AI 工具。

STEP 02

看得到面板，還需要一台能工作的電腦

s90 Server 負責帳號、工作區與派送任務。註冊並不會自動取得 s90 上其他人的 Agent 執行權限或 AI 額度。即使面板已經出現 Mika，也仍需要可用的執行環境（runtime）。若管理員沒有另行提供共用環境，請連接自己的電腦。

① Server10.1.24.90
保存與派送任務
② 你的 daemon在你的電腦上
接收並執行任務
③ Agent CLI例如 Claude Code、Codex
使用你已登入的 AI 帳號

Agent 是角色，runtime 是執行工具，daemon 是連接兩者的本機程序。只修改人設不會讓電腦上多出可執行的工具。

自動偵測能使用的 agent

Agent CLI（codex cli / claude code / antigravity cli / grok cli / hermes / … 等）需先在同一作業系統帳號下安裝，daemon 再透過環境變數 PATH 偵測。

電腦關機、休眠、離線或 daemon 停止時，這台電腦就無法繼續承接工作。AI 工具的訂閱、API 權限與費用由你使用的服務決定。

STEP 03 / 路線 A

用 App 連接自己的電腦

適合想使用圖形介面的使用者。App 內含 Multica CLI，但 Claude Code、Codex 等 AI 工具仍需自行安裝與登入。

目前提供 Apple Silicon Mac 版本

本站下載版本為 0.4.43-zh-tw.7。Intel Mac、Windows 與 Linux 桌面版目前未提供相同的已驗收成品。App 使用 ad-hoc 簽章、尚未完成 Apple 公證，macOS 可能阻擋開啟；請先核對來源與校驗碼，依管理員指引處理，不要關閉整台電腦的 Gatekeeper。

  1. 到 繁中版下載中心，下載 Apple Silicon ZIP 與對應的 SHA256SUMS，核對校驗碼後解壓縮，將 App 放入「應用程式」。
  2. 開啟 Multica，確認連線位置是 https://10.1.24.90:45671，使用剛才的帳號登入並選擇工作區。
  3. 在同一台 Mac、同一個作業系統帳號下，安裝並登入至少一種支援的 AI CLI。先在終端機確認工具能正常啟動與完成簡單請求。
  4. 開啟 App 的設定，找到 daemon／守護程序控制，手動啟動 daemon。不要同時再用終端機啟動另一份 daemon。
  5. 回到工作區的 Agent／runtime 選擇畫面，確認看到自己的電腦，以及偵測到的工具，即可確認這台電腦已連接至工作區。

下載 App 不等於 daemon 已啟動；daemon 運行也不等於 AI 帳號已登入。兩項都要確認。

此版 App 會從固定 GitHub 公開 HTTPS 來源檢查 CA 更新；離線時保留已驗證的憑證。daemon 只在沒有執行中或等待中的任務時，透過原子檢查安全重新啟動套用。

STEP 04 / 路線 B

不裝 App，也能用 CLI 啟動 daemon

適合 Linux 主機、遠端 SSH，或偏好終端機的使用者。安裝器支援 Linux x86_64／ARM64 與 macOS Intel／Apple Silicon；Windows 請先向管理員確認可用方案。

1. 準備自己的個人 API token

先在 Web 登入，在設定中的個人 API token 管理畫面建立自己的 token。稍後在終端機提示時貼上，勿貼到議題、聊天或指令參數中。

2. 在要執行工作的電腦下載安裝器

以下指令適用於全新安裝；Linux 若要常駐，請先看下方常駐服務選項，選擇 --service 取代 --login。腳本從 GitHub 的此版本發行資產下載，CLI 成品則從 s90 下載；執行前請開啟 install.sh 檢查來源與內容。

curl -q --fail --location --proto '=https' --proto-redir '=https' \
  https://github.com/hyc5566/multica/releases/download/zh-tw-v0.4.43-zh-tw.7/install.sh \
  -o install.sh

# 檢查 install.sh 後執行
bash install.sh --login

依提示貼上 token。--login 會完成安裝、登入並啟動 daemon。安裝器會下載 s90 公開 CA，核對固定 SHA-256 後才使用，並校驗 CLI 成品。如果公司代理需要額外 CA，請向管理員取得公開憑證後依詳細安裝文件設定。

既有安裝請勿直接覆蓋

若安裝器回報已有 ~/.multica/config.json、profile、launcher 或版本目錄，請保留現有設定，依升級流程處理。不要為了讓安裝成功而刪掉舊設定。

3. 確認狀態與偵測到的工具

"$HOME/.local/bin/multica" daemon status
"$HOME/.local/bin/multica" runtime list

確認 daemon 顯示運行中，並在 Web 選擇同一工作區，檢查自己的 runtime 是否在線。若尚未安裝 AI CLI，先完成該工具的安裝與登入。

只安裝、不立即登入，之後怎麼啟動？
bash install.sh
"$HOME/.local/bin/multica" login --token
"$HOME/.local/bin/multica" daemon start
"$HOME/.local/bin/multica" daemon status

CLI 安裝於 ~/.local/bin/multica；成品位於 ~/.local/share/multica-zh-tw/<version>/；預設設定在 ~/.multica/。使用完整路徑不需要先修改 PATH。

Linux：讓 daemon 常駐接單

常駐表示由 Linux 的 systemd 使用者服務管理 daemon，不必一直開著終端機。電腦關機、休眠或離線時仍無法接單。以下僅適用於有 systemd 使用者服務的 Linux；macOS 請沿用 App 或一般 CLI 啟動方式。

全新安裝：檢查下載的腳本後，以這個指令取代 bash install.sh --login，兩種方式擇一，不要接著重複執行：

bash install.sh --service

這會完成安裝、互動登入、建立並啟用 multica.service。腳本預設行為維持不變，由你選擇是否安裝常駐服務。

已經用 --login 安裝，如何改成常駐服務？

不必重新安裝或刪除設定。以下限預設路徑、預設設定的手動 CLI 安裝；App、具名 profile、自訂安裝路徑或既有服務請先確認原管理方式，勿直接套用。

  1. 確認目前使用者有可用的 systemd，且 CLI 已登入。先查看是否已有服務；如果已存在，直接使用後面的服務管理指令，不要覆蓋。
systemctl --user show-environment >/dev/null
systemctl --user cat multica.service
"$HOME/.local/bin/multica" daemon status

只有 multica.service 顯示找不到，才需要新建；如果是無法連到 user bus，請先請管理員協助。確認沒有執行中的任務後，停止原本手動啟動的 daemon：

"$HOME/.local/bin/multica" daemon stop
mkdir -p "$HOME/.config/systemd/user"

用文字編輯器新建 ~/.config/systemd/user/multica.service，貼入以下內容；若檔案已存在，先停止並檢查，勿覆蓋：

[Unit]
Description=Multica user daemon
After=network-online.target

[Service]
Type=simple
ExecStart="%h/.local/bin/multica" daemon start --foreground
Environment="PATH=%h/.local/bin:/usr/local/bin:/usr/bin:/bin"
Restart=on-failure
RestartSec=5
TimeoutStopSec=90

[Install]
WantedBy=default.target

%h 會由 systemd 換成你的家目錄。若 Agent CLI 位於其他目錄，請將該目錄的完整路徑加入上面的 PATH；不要把 token 寫進服務檔。保存後執行：

systemctl --user daemon-reload
systemctl --user enable --now multica.service
systemctl --user status multica.service
"$HOME/.local/bin/multica" daemon status

確認服務為 active (running)，並在工作區看到自己的 runtime 在線。若啟動失敗，先用 journalctl --user -u multica.service -n 50 檢查；需要退回手動管理時，先執行 systemctl --user disable --now multica.service，再執行 "$HOME/.local/bin/multica" daemon start。

關閉終端機、登出、重新開機，有什麼不同？

服務啟用後，關閉終端機不會停止它；預設會隨使用者的 systemd 工作階段啟動。若要登出後繼續運作、重新開機後不登入也接單，還需要管理員依主機政策為該使用者啟用 linger。

loginctl show-user "$USER" -p Linger

Linger=yes 表示已啟用；若為 no，請管理員為你的帳號執行 loginctl enable-linger 使用者名稱（可能需要管理權限）。此設定不會讓休眠或關機的電腦繼續工作。

之後如何停止、重啟或取消常駐？

改由 systemd 管理後，使用下列指令；每一行代表不同操作，請選需要的那一個。停止或重啟前，先等執行中的任務結束。

# View status
systemctl --user status multica.service
# Stop now
systemctl --user stop multica.service
# Start again
systemctl --user start multica.service
# Restart after configuration changes
systemctl --user restart multica.service
# Stop and disable automatic start
systemctl --user disable --now multica.service

停止 daemon 不會刪除帳號或議題。不要同時用 App、手動 CLI 與 systemd 啟動多份 daemon。
