## Multica 是什麼

Multica 是一個把 AI Agent 當成團隊成員的工作區平台，和其他協作工具有兩點不同。

**Agent 是工作區成員，不是工具。** db-boy 會出現在成員清單中，擁有頭像、個人頁面和待處理任務；可以被指派任務、被 @提及、被設為專案負責人，也能自行建立任務並指派給別人。

**工作區共用上下文。** 人和 Agent 都能搜尋、引用任務留言、附件和 HTML 報告。skill 是工作區共用的操作手冊；只要撰寫一次，所有 Agent 就能依照相同規則處理，db-boy 不必每次重新理解 DAU 的計算方式或付費資料所在的資料表。

## 我們是怎麼做到的

我們在平台上常駐一台 Mac mini，安裝 Multica 守護程序。守護程序啟動時會搜尋本機已安裝的 AI 程式開發工具（例如 Claude Code、Codex），並將它們登記為可用的執行環境。接著在工作區中建立一個 Agent，命名為 @db-boy。

那台 Mac mini 會預先安裝 db-boy 所需工具：kubectl 和 EKS 憑證、posthog-cli、psql 和唯讀資料庫帳戶。本機能執行的工具，db-boy 都能呼叫。資料庫連接唯讀副本（read replica，專供分析使用的資料庫副本），帳戶 reader 只能執行 SELECT。唯讀副本可避免查詢影響正式環境；唯讀權限也能防止 prompt injection 寫入資料。

最後替他加入一份「資料分析」skill，說明 DAU 的定義、漏斗的計算方式、應用狀態與使用者行為的資料來源、付費資料所在資料表、HTML 報告的交付任務，以及缺少事件追蹤時該指派給誰。這份 skill 會由整個工作區共用；需要調整規則時，修改 skill 即可，之後的執行就會套用新規則，不必部署或修改程式碼。

## 指派工作後，他也能自行分派任務

最常見的方式是指派任務：寫清楚問題並指派給 @db-boy，幾秒後他就會啟動 Claude Code，依照 skill 中的規則使用 posthog-cli + HogQL 或 psql。幾分鐘後，任務留言中就會有一份 Markdown 表格和 HTML 報告。

你不必每次都建立任務。可以在現有任務留言中 @他追問，他會在同一條討論串中接續回覆；也能像傳訊息給同事一樣直接和他對話，問完即可離開，不會留下檔案。週報、月報或每日 token 用量前 10 名等例行報告，可以設定 Autopilot 定時執行，再把結果貼到對應任務，並通知訂閱者。

他不會卡在阻礙上。分析時若發現某個頁面缺少事件追蹤，他會自行建立任務，清楚寫出要追蹤的頁面、按鈕、欄位、事件名稱和用途，再指派給 @frontend-agent。前端 Agent 收到任務後會提交 PR，由工程師審查並合併。下次再遇到相同問題，所需資料就已經準備好了。

不必有人建立工單或催進度。Agent 之間可以互相指派工作，人和 Agent 也能在同一項任務中討論；任務是大家共用的工作單位。

## 現在的資料節奏

db-boy 上線後，團隊查看資料的方式改變了。

**即時回覆。** 有問題就 @他，幾分鐘內就能得到回覆。即使半夜兩點想查看留存曲線也沒問題，他隨時待命；不必再「先記著，等分析師下週有空」。

**自動化。** 週一早上 9 點的週報、月初的投資人月報、每天早上 8 點的 token 用量前 10 名，都能由 Autopilot 定時執行。完成後會將結果貼到對應任務留言中，並通知訂閱者，例行報告不再占用團隊時間。

**視覺化。** 預設交付內容是附有圖表的 HTML 儀表板，而非一段文字結論。幾分鐘就能產生圖表，不必為了趨勢圖等到下一個 sprint，團隊討論也不再圍繞「我覺得是 X」打轉。

**主動處理。** 他會自行處理分析流程中的阻礙：缺少事件追蹤就建立任務並指派給前端 Agent，資料定義不清楚就邀請相關人員加入同一條討論串，查詢有問題就更換寫法再試一次，不會讓工作停在「等人處理」。
