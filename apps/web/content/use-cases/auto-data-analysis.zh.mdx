## Multica 是什麼

Multica 是一個把 AI agent 當員工來用的工作區平臺。它跟其他協作工具有兩點不一樣。

**Agent 是工作區成員,不是工具。** db-boy 在成員列表裡有頭像、有個人頁、有待解決的任務,能被分配 task、被 @、被設為 project owner,也能自己開任務派給別人。

**Context 在工作區裡共享。** 任務評論、附件、HTML 報告,人和 agent 都能搜、能引用。skill 是工作區一份的操作手冊,寫一次所有 agent 共用一套口徑,db-boy 不用每次重新理解 DAU 怎麼算、付費資料查哪張表。

## 我們是怎麼做到的

我們在平臺上常駐一臺 Mac mini,裝上 Multica daemon。daemon 啟動時會掃一遍本機的 AI 程式設計工具(Claude Code、Codex 這一類),自動登記成可用的 agent 執行時。然後在工作區裡新建一個 agent,起名 @db-boy。

那臺 Mac mini 上提前裝好 db-boy 要用的工具:kubectl + EKS 憑據、posthog-cli、psql + 只讀資料庫賬號。本機能跑的,db-boy 都能調。資料庫連的是隻讀從庫(read replica,專門給分析用的副本資料庫),賬號用 reader 只能 SELECT。從庫隔離意味著他怎麼查都不影響生產,只讀許可權意味著哪怕 prompt injection 也寫不進任何資料。

最後給他掛一份"資料分析"skill。Skill 寫明:DAU 怎麼定義、漏斗按什麼口徑、應用狀態走 PG、使用者行為走 PostHog、付費資料查哪張表、HTML 報告交付到哪條任務、缺埋點要派給誰。寫一次全 workspace 共享;口徑要改回去改 skill 那一行,下次自動用新口徑,不用部署、不碰程式碼。

## 找它幹活,他還會自己派活

最常見的方式是分配任務:寫清問題、assign 給 @db-boy,幾秒後他啟動 Claude Code,按 skill 裡的路由走 posthog-cli + HogQL 或者 psql,幾分鐘後任務評論裡多一條 markdown 表格和一份 HTML 報告。

也不用每次都開任務。在已有任務評論裡 @ 他追問一句,他在同一條執行緒接著回。像 DM 同事一樣直接 chat 也行,問完即走不留檔案。例行報告(週報、月報、每天的 token 用量 top 10)配一次 Autopilot,到點自動跑,結果貼到對應任務裡,訂閱者收到通知。

他不會卡在堵點上。分析時發現某個頁面沒埋點,他自己建一條新任務:標題寫"補 X 頁面 Y 按鈕的點選埋點",欄位、事件名、為什麼需要都寫清,assign 給 @frontend-agent。前端 agent 接到分配就提 PR,工程師 review 完合進去。下次再問同一個問題,資料就在那裡。

## 現在的資料節奏

db-boy 上線之後,團隊看資料的節奏變了。

**即時性。** 想到問題就 @ 他,幾分鐘回。半夜兩點要看一組留存曲線也行,他都在。"先記著、等分析師下週有空"這種等待消失了。

**自動化。** 週一 9 點週報、月初投資人月報、每天早 8 點 token 用量 top 10,全是 Autopilot 定時跑,跑完直接貼到對應任務評論裡,訂閱者自動收到通知。例行報告不再佔任何人時間。

**視覺化。** 交付物預設是帶圖表的 HTML dashboard,不是一段文字結論。幾分鐘出圖,不為一張趨勢圖等下個 sprint,團隊討論也不再圍著"我感覺是 X"打轉。

**主動性。** 分析鏈路上的堵點他自己接:缺埋點就開任務派給前端 agent,口徑模糊就把相關人拉進同一條執行緒,查詢寫不出來就自己換寫法再來一次。沒有一件事卡在"等誰去做"上。
