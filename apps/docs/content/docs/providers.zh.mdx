Multica 不會替代你使用的 AI 編程工具。執行環境會調用電腦上已經安裝並登入的工具，再把執行進度和結果寫回任務。

如果你已經在使用其中一款，通常可以直接沿用。選擇工具時的四個判斷維度：

- 電腦上是否已經安裝；
- 帳戶可以使用哪些模型；
- 是否需要由 Multica 設定 MCP；
- 團隊要複用哪些 skill。

安裝方法見 [安裝 AI 編程工具](/install-agent-runtime)。

"Multica 管理 MCP" 表示你可以在 Agent 設定中填寫 MCP server，由 Multica 在執行前傳給對應工具。它不代表該工具本身沒有其他 MCP 設定方式。

## 模型來源

建立 Agent 時，模型列表來自對應的執行環境。有些工具提供固定的模型名稱，有些會根據本機設定、登入帳戶和訂閱權益返回可用模型。

不選擇模型時，Multica 使用該工具的預設設定。列表為空時，先確認執行環境在線並且工具已經登入，再刷新模型列表。

QwenPaw 和 MiniMax Code 是例外：它們不接受在 Multica 側選擇的模型，因此選擇框不可用，顯示為"由執行環境管理"。請改在工具自身的設定裡選擇模型。模型列表為空屬於正常情況，並不表示執行環境離線。

DeepSeek Harness 的模型目錄由執行環境自身提供（`dsh --profile multica --list-models`）。它的模型 id 採用 `provider/model` 形式（例如 `deepseek-official/deepseek-chat`），請從列表中選擇完整 id。

<Callout type="info">
不同工具可能使用不同的模型名稱。更換 AI 編程工具後，原有的模型值在新工具中無效，需要重新選擇。
</Callout>

## 會話恢復

表格中標記 ✓ 的工具支援在後續執行中繼續已有會話。前提是原來的會話仍然存在，並且執行由能夠訪問它的執行環境執行。MiniMax Code 0.1.2 尚未通過 ACP 聲明會話載入能力，因此後續執行會新建 MCode 會話。

Multica 會儲存工具返回的會話標識。下一次在同一任務中繼續工作時，執行環境會嘗試恢復這段會話；無法恢復時，會建立一個新會話繼續執行。Pi 儲存的是本地會話檔案路徑，因此更依賴原來的電腦和檔案。

有關重試和會話恢復的規則，見 [執行](/tasks#手動重試)。

## MCP 設定

Antigravity、GitHub Copilot CLI、DevEco Code 和 Pi 暫不讀取 Agent 中的 MCP 設定，因此建立 Agent 時不會顯示這一項。

<Callout type="warning">
MCP server 的命令、參數和環境變數會隨 Agent 設定儲存在伺服器端。不要把不需要共享的本地憑據直接寫入設定。
</Callout>

## Skill 注入方式

執行開始前，Multica 會把 Agent 綁定的 skill 寫入上表對應的位置，讓工具通過自己的原生機制發現它們。

倉庫裡原本存在的 skill 不會被覆蓋。如果名稱衝突，Multica 會為注入的副本使用另一個目錄名；執行結束後，只清理自己建立的檔案。

Codex、Hermes 和 OpenClaw 的處理稍有不同：

- Codex 使用單次執行的 `CODEX_HOME`，不會把 skill 寫進系統級 Codex 目錄。
- Hermes 使用單次執行的 `HERMES_HOME`。已有的本地設定仍然可以被讀取，但綁定的 skill 與會話資料按執行隔離。這套隔離只在 Agent 綁定了 skill 時啟用，沒有綁定 skill 的執行使用本機原有的 Hermes 主目錄。
- OpenClaw 使用當前執行工作目錄下的 `skills/`，並由單次執行設定把該目錄設為工作區。

如何建立和綁定 skill，見 [Skills](/skills)。
