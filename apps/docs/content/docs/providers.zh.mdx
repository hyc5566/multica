Multica 不會取代你使用的 AI 程式開發工具。執行環境會呼叫電腦上已安裝並登入的工具，再將進度和結果寫回任務。

如果你已在使用其中一款，通常可以繼續沿用。選擇工具時可考量四件事：

- 電腦上是否已安裝；
- 帳號能使用哪些模型；
- 是否需要由 Multica 設定 MCP；
- 團隊想共用哪些 skill。

安裝步驟請見[安裝 AI 程式開發工具](/install-agent-runtime)。

## 模型來源

建立 Agent 時，模型清單來自對應的執行環境。有些工具提供固定的模型名稱，有些則會依本機設定、登入帳號和訂閱權益回報可用模型。

未選擇模型時，Multica 會使用該工具的預設模型。清單為空時，請先確認執行環境在線且工具已登入，再重新整理模型清單。

QwenPaw 和 MiniMax Code 是例外：它們不接受在 Multica 中選擇模型，因此模型選擇器無法使用，會顯示"由執行環境管理"。請改在工具自己的設定中選擇模型。這兩款工具的模型清單為空是正常情況，不代表執行環境離線。

DeepSeek Harness 的模型目錄由執行環境本身提供（`dsh --profile multica --list-models`）。模型 ID 格式為 `provider/model`（例如 `deepseek-official/deepseek-chat`），請從清單選取完整 ID。

<Callout type="info">
不同工具使用的模型名稱可能不同。更換 AI 程式開發工具後，原本的模型值在新工具中會無效，必須重新選擇。
</Callout>

## 工作階段恢復

表格中標示 ✓ 的工具支援在後續執行中延續既有工作階段，前提是原工作階段仍存在，且執行環境能存取該工作階段。MiniMax Code 0.1.2 尚未透過 ACP 宣告載入工作階段的能力，因此後續執行會建立新的 MCode 工作階段。

Multica 會儲存工具回傳的工作階段 ID。下次在同一任務中繼續工作時，執行環境會嘗試恢復該工作階段；若無法恢復，就會建立新的工作階段並繼續執行。Pi 儲存的是本機工作階段檔案路徑，因此更依賴原本的電腦和檔案。

重試和工作階段恢復規則請見[執行](/tasks#手動重試)。

## MCP 設定

Antigravity、GitHub Copilot CLI 和 DevEco Code 目前不會讀取 Agent 中的 MCP 設定，因此建立 Agent 時不會顯示這個欄位。

Pi 需使用 0.99.0 或更新版本，才能接收受管理的 MCP 設定。舊版 Pi 仍可執行未設定 MCP 的 Agent。

<Callout type="warning">
MCP server 的命令、參數和環境變數會隨 Agent 設定儲存在伺服器端。請勿將不需共用的本機憑證直接寫入設定。
</Callout>

## skill 注入方式

執行開始前，Multica 會將 Agent 綁定的 skill 寫入上表對應的位置，讓工具透過原生機制找到它們。

儲存庫中原有的 skill 不會被覆寫。如果名稱衝突，Multica 會為注入副本改用另一個目錄名稱；執行結束後，只會清除自己建立的檔案。

Codex、Hermes 和 OpenClaw 的處理稍有不同：

- Codex 使用單次執行專屬的 `CODEX_HOME`，不會將 skill 寫入系統層級的 Codex 目錄。
- Hermes 使用單次執行專屬的 `HERMES_HOME`。工具仍可讀取既有本機設定，但綁定的 skill 和工作階段資料會依執行隔離。只有 Agent 綁定 skill 時才會啟用隔離；未綁定 skill 的執行會使用電腦原有的 Hermes 主目錄。
- OpenClaw 使用目前執行工作目錄下的 `skills/`，並由單次執行的設定將該目錄設為工作區。

如何建立並綁定 skill，請參閱 [skill](/skills)。
