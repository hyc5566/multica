加入[工作區](/workspaces)的人都是成員，每位成員有一種角色：`owner`、`admin` 或 `member`。角色只管理工作區設定和團隊成員；建立任務、發表留言等日常協作則開放給所有成員。

## 三種角色

| 操作 | owner | admin | member |
|---|:---:|:---:|:---:|
| 查看工作區並參與日常協作 | ✓ | ✓ | ✓ |
| 修改工作區設定 | ✓ | ✓ | — |
| 邀請 `admin` 或 `member` | ✓ | ✓ | — |
| 調整或移除 `admin`、`member` | ✓ | ✓ | — |
| 授予、收回或移除 `owner` | ✓ | — | — |
| 刪除工作區 | ✓ | — | — |

工作區至少必須保留一位 `owner`：最後一位 `owner` 不能被降級、移除或離開工作區。

<Callout type="info">
角色不決定誰能執行 Agent。每個 Agent 都有自己的 Access 範圍；`owner` 和 `admin` 也不能繞過 Access 執行未授權的 Agent。詳情請參閱[Agent](/agents#權限與-access)。
</Callout>

## 邀請成員

`owner` 和 `admin` 可前往"設定"→"成員"，輸入電子郵件並選擇角色來發送邀請。邀請只能授予 `admin` 或 `member`；要成為 `owner`，必須先加入工作區，再由現有 `owner` 升任。

![成員管理：邀請表單與帶角色的成員名冊](/images/docs/members-roster.webp)

受邀者使用該電子郵件登入即可接受邀請，不必先註冊。邀請有效期限為 7 天，過期後可以重新寄送。在限制註冊的自行託管環境中，只要邀請仍待接受且尚未過期，受邀者就能使用該電子郵件建立帳號，不必另外加入允許清單。詳情請參閱[驗證設定](/auth-setup#邀請與註冊限制)。

邀請連結只會出現在電子郵件中，產品介面沒有查看或複製連結的功能。若郵件寄送失敗，邀請紀錄仍會保留；請撤銷邀請後重新寄送。

## 調整角色

`admin` 可以在 `admin` 和 `member` 之間調整角色，也可以移除這兩種角色的成員。任何涉及 `owner` 的變更，包括升任、變更或移除，都只能由 `owner` 執行。

角色變更會立即生效。

## 移除成員

成員遭移除後會立即失去工作區存取權限。該成員建立的任務、留言和其他協作紀錄仍會保留在工作區中。

<Callout type="warning">
移除成員也會停用該成員擁有的執行環境、封存綁定於這些環境的 Agent，並取消尚未完成的執行。該成員透過 Agent Access 範圍取得的授權也會清除；即使重新加入工作區，授權也不會自動恢復。
</Callout>
