在[工作區](/workspaces)中，`owner`、`admin` 和 `member` 都能建立任務和發表評論，但管理設置和成員的權限不同。[訪客](#訪客)只能在分享給自己的項目中查看任務和發表評論。

## 成員管理權限 [#三種角色]

| 操作 | owner | admin | member |
|---|:---:|:---:|:---:|
| 查看工作區並參與日常協作 | ✓ | ✓ | ✓ |
| 修改工作區設定 | ✓ | ✓ | — |
| 邀請 `admin` 或 `member` | ✓ | ✓ | — |
| 調整或移除 `admin`、`member` | ✓ | ✓ | — |
| 授予、收回或移除 `owner` | ✓ | — | — |
| 刪除工作區 | ✓ | — | — |

工作區至少必須保留一位 `owner`：最後一位 `owner` 不能被降級、移除或離開工作區。

<RolesDemo />

<Callout type="info">
訪客無法運行Agent。每個Agent有獨立的訪問範圍（Access），`owner` 和 `admin` 也不能繞過它運行未授權的Agent。詳見[Agent](/agents#權限與-access)。
</Callout>

<Callout type="info">
角色同樣不會打開私有項目。`owner` 或 `admin` 只有在成員名單里時才能看到私有項目。詳見[私有項目](/projects#private-projects)。
</Callout>

## 邀請成員

`owner` 和 `admin` 在**設置 → 成員**中點選**邀請成員**，填寫郵箱、選擇角色後發送。邀請可以授予 `admin`、`member` 或[訪客](#訪客)身份；`owner` 需要先加入工作區，再由現有 `owner` 提升。

![成員管理：邀請表單與帶角色的成員名冊](/images/docs/members-roster.webp)

受邀者使用該電子郵件登入即可接受邀請，不必先註冊。邀請有效期限為 7 天，過期後可以重新寄送。在限制註冊的自行託管環境中，只要邀請仍待接受且尚未過期，受邀者就能使用該電子郵件建立帳號，不必另外加入允許清單。詳情請參閱[驗證設定](/auth-setup#邀請與註冊限制)。

邀請連結只會出現在電子郵件中，產品介面沒有查看或複製連結的功能。若郵件寄送失敗，邀請紀錄仍會保留；請撤銷邀請後重新寄送。

需要一條能直接轉發的連結時，在**設定 → 成員**的**分享連結**中選擇角色和有效期後生成。拿到連結的人都可以以所選角色加入，直到連結過期或被撤銷。

## 訪客

訪客只能看到分享給自己的項目。在這些項目里，訪客可以查看任務、評論、添加表情回應和關注任務；不能建立或修改任務，不能運行或 @ agent，也不能打開工作區設置，看不到其他項目、agent、autopilot 和 runtime。

`owner` 和 `admin` 在邀請彈窗里選擇**訪客**並勾選可訪問的項目，即可邀請訪客。在成員的操作菜單里，可以把成員設為訪客（收回其 agent、autopilot 和 runtime 權限），把訪客設為成員，或通過**管理可訪問的項目**調整訪客能看到的項目。和私有項目的其他資訊一樣，訪客在某個私有項目上的權限，只有該項目成員列表裡的人能看到和修改；調整訪客的項目時，你不在其中的私有項目上的權限保持不變。

## 調整角色

在成員列表中開啟某位成員右側的操作選單，選擇**更改角色**，角色立即生效。

`admin` 可以在 `admin` 和 `member` 之間調整角色，也可以移除這兩類成員。涉及 `owner` 的變更——提升、更改或移除——只有 `owner` 能執行。

## 移除成員

成員遭移除後會立即失去工作區存取權限。該成員建立的任務、留言和其他協作紀錄仍會保留在工作區中。

<Callout type="warning">
移除成員也會停用該成員擁有的執行環境、封存綁定於這些環境的 Agent，並取消尚未完成的執行。該成員透過 Agent Access 範圍取得的授權也會清除；即使重新加入工作區，授權也不會自動恢復。
</Callout>
