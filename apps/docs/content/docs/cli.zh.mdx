Multica CLI 可連線至本機執行環境，也能在終端機管理工作區、任務、Agent 和自動化。本頁介紹常見操作；你安裝的版本支援哪些旗標，請一律以各命令自己的 `--help` 為準。

## 安裝

**macOS / Linux**

```bash
curl -fsSL https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.sh | bash
```

如果已安裝 Homebrew，也可以執行：

```bash
brew install multica-ai/tap/multica
```

**Windows PowerShell**

```powershell
irm https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.ps1 | iex
```

確認是否安裝成功：

```bash
multica version
```

## 第一次連接

連線至 Multica Cloud：

```bash
multica setup
```

連線至自架執行個體：

```bash
multica setup self-host \
 --server-url https://api.example.com \
 --app-url https://app.example.com
```

`setup` 會儲存伺服器位址、開啟瀏覽器完成登入，並啟動常駐程式。完成後請檢查：

```bash
multica auth status
multica daemon status
```

如果只需要重新登入，且不想覆寫其他設定，請執行 `multica login`。若環境沒有瀏覽器，請先在 Web 設定中建立個人存取權杖，再輸入：

```bash
multica login --token
```

命令會提示你在終端機貼上權杖，避免完整權杖留在 shell 歷程記錄中。

## 選擇工作區

列出工作區並切換預設工作區：

```bash
multica workspace list
multica workspace switch <slug>
```

之後的命令都會使用這個工作區。若只想讓單一命令使用其他工作區，可用 `--workspace-id` 暫時覆寫，或設定 `MULTICA_WORKSPACE_ID`。

邀請工作區成員：

```bash
multica workspace member invite teammate@example.com
multica workspace member invite admin@example.com --role admin
```

## 常用任務操作

```bash
# 檢視與搜尋
multica issue list
multica issue get MUL-123
multica issue search "login failure"

# 建立與更新
multica issue create --title "Fix login failure"
multica issue status MUL-123 in_progress
multica issue assign MUL-123 --to "Backend Agent"

# 留言與執行記錄
multica issue comment list MUL-123
multica issue comment add MUL-123 --content "Check the regression tests first"
multica issue comment update <comment-id> --expected-revision 2 --content "Check the regression tests and release notes"
multica issue runs MUL-123
```

長篇描述或留言可從 stdin 讀取，避免處理換行和引號：

```bash
multica issue create --title "Upgrade notes" --description-stdin < notes.md
multica issue comment add MUL-123 --content-stdin < review.md
multica issue comment update <comment-id> --expected-revision 2 --content-file revised-review.md
```

查看單次執行中的訊息，或停止執行：

```bash
multica issue run-messages <task-id> --issue MUL-123
multica issue cancel-task <task-id> --issue MUL-123
```

## Agent 和 skill

```bash
multica agent list
multica agent get <agent-id>
multica agent create --help
multica agent update <agent-id> --help

multica skill list
multica skill get <skill-id>
multica skill import --url <skill-url>
multica agent skills add <agent-id> --skill-ids <skill-id>
```

匯入時若遇到同名 skill，預設會停止操作，不修改現有內容。請依需求選擇：

```bash
multica skill import --url <skill-url> --on-conflict overwrite
multica skill import --url <skill-url> --on-conflict rename
multica skill import --url <skill-url> --on-conflict skip
```

`overwrite` 只允許 skill 的建立者使用，並保留原有 ID 和 Agent 綁定關係。

### Agent 執行記錄

`multica agent tasks <agent-id> --limit 200` 會回傳最新一頁執行記錄。每頁預設和上限都是 200 筆。若還有更多記錄，stderr 會印出游標；將游標原樣傳入 `--before '<cursor>'` 即可讀取下一頁。`--output json` 會維持陣列格式，且只包含該頁的用量資料。

對應的 `GET /api/agents/{id}/tasks` 端點接受 `limit` 和 `before` 參數，並維持 JSON 陣列回應。`X-Agent-Tasks-Next-Cursor` 回應標頭會提供下一頁游標；若沒有這個標頭，就表示已到最後一頁。游標會保留 `(created_at, id)` 的排序，包括時間戳記精度。無效的 limit 或游標會回傳 HTTP 400；超過 200 的 limit 會以 200 計算。未使用游標的用戶端只會收到最新 200 筆執行記錄。

## 常駐程式和執行環境

```bash
multica daemon start
multica daemon stop
multica daemon restart
multica daemon status --output json
multica daemon logs --follow

multica runtime list
multica runtime rename <runtime-id> "Office Mac"
multica runtime usage <runtime-id>
multica runtime activity <runtime-id>
```

刪除仍綁定活躍 Agent 的執行環境時，命令預設拒絕。`multica runtime delete <id> --cascade` 會解綁這些 Agent、保留其設定與歷史記錄，並取消它們的活動執行。

執行方式和自訂 profile 請參閱[常駐程式與執行環境](/daemon-runtimes)。

## 命令概覽

| 命令 | 用途 |
| --- | --- |
| `issue` | 建立、更新、指派和搜尋任務；管理留言、訂閱者、標籤、屬性與執行記錄 |
| `project` | 管理專案及其資源 |
| `label`、`property` | 管理工作區標籤和自訂屬性 |
| `agent`、`skill`、`squad` | 管理 Agent、skill 和小隊 |
| `autopilot` | 管理自動化、觸發器和執行記錄 |
| `workspace` | 建立、檢視、切換工作區並邀請成員 |
| `repo` | 管理工作區儲存庫，並將儲存庫檢出至本機 |
| `daemon`、`runtime` | 啟動或停止本機常駐程式，檢視和管理執行環境 |
| `attachment` | 上傳或下載附件 |
| `user profile` | 檢視或更新目前使用者的個人資料 |
| `auth`、`login`、`setup` | 登入、檢查驗證狀態和初始化連線 |
| `config` | 檢視或修改目前 CLI profile 的本機設定 |
| `update`、`version` | 更新 CLI 或檢視版本 |

`multica chat` 讀取的是**Agent 目前正在處理的外部聊天工作階段**，主要供聊天整合中的 Agent 使用；它不是瀏覽任意工作區對話的通用命令。

## ID 和輸出格式

任務使用 `MUL-123` 這類 key 或完整 UUID，不接受 UUID 短前綴。

其他資源的 `list` 命令通常會顯示可複製的短 ID，並支援用 `--full-id` 輸出完整 UUID。若短 ID 不唯一，CLI 會要求提供更多字元或改用完整 UUID。執行記錄的短 ID 也需要透過 `--issue` 指明所屬任務。

許多命令支援結構化輸出：

```bash
multica issue list --output json
multica agent list --output json
```

指令碼應使用 JSON 輸出，不要解析面向終端機的表格。各命令支援的輸出格式和分頁旗標請以 `multica <command> --help` 為準。

## Profile 與設定

預設設定保存在 `~/.multica/config.json`。使用 `--profile <name>` 可以隔離另一套服務地址、令牌、預設工作區和常駐程式狀態：

```bash
multica setup self-host --profile staging \
 --server-url https://api.staging.example.com \
 --app-url https://app.staging.example.com

multica issue list --profile staging
```

命名 profile 保存在 `~/.multica/profiles/<name>/config.json`。查看目前值：

```bash
multica config show
multica config show --profile staging
```

請勿在主機 shell、Compose 服務或啟動常駐程式的容器進入點中設定 `MULTICA_DAEMON_PORT`。主機常駐程式通常會依 `--profile` 推導健康檢查連接埠；若無法繫結該連接埠，便會改用可用的 loopback 連接埠，並自行將實際連接埠注入 Agent 任務。舊版啟動環境應徹底移除此變數：否則 0.4.22 和 0.4.23 會把該 shell 誤判為受管理的任務，並拒絕登入。較新版允許受保護的人工作業登入和 `daemon status` 在連接埠是唯一任務訊號時復原，但一般 API 命令和解析 profile 的命令仍會採取安全拒絕，直到移除此變數。

CLI 在常駐程式管理的 Agent 任務中執行時，不會載入或修改這些由人員管理的 profile 檔案。Multica API 命令會使用常駐程式注入、僅限該任務的憑證進行驗證。`config show` 和 `config set` 會使用任務專用的私人狀態；`login`、`logout`、`setup`、`workspace switch`、本機執行環境 profile 路徑變更、`daemon start` / `stop` / `restart`、`daemon logs` 和 `daemon probe-runtimes` 等人員／本機命令則無法使用。在此情境下，`auth status` 不會輸出權杖內容。

`daemon status` 和 `daemon disk-usage` 仍可供 Agent 檢查承載它的執行環境，且範圍僅限該執行環境：`status` 會探測常駐程式注入的健康檢查連接埠，`disk-usage` 會掃描常駐程式注入的工作區根目錄。兩者都不接受 `--profile`；`disk-usage` 也會拒絕 `--all-profiles` 和 `--workspaces-root`。由於解析狀態需要使用人員儲存的權杖，其 STATUS 欄位會留白。若要檢查此範圍以外的內容，請使用 `du` 和 `df`。

這樣可保護 Multica CLI 隱含解析 profile 的行為，同時保留其他供應商工具所需的一般 `HOME` 和 XDG 變數。這並非作業系統層級的檔案系統隔離：以相同系統使用者身分執行的程序仍可開啟已知的明確路徑。若需要更強的隔離，請使用專用使用者、容器、虛擬機器或同等方案。

<Callout type="warning">
CLI 設定檔包含可代表你存取 Multica 的權杖。請勿將其提交至儲存庫、上傳到日誌或與他人分享。
</Callout>

## 命令參考

下表列出目前所有頂層命令，並依 CLI 本身的分組排列。所有命令都接受全域旗標 `--server-url`、`--workspace-id`、`--profile` 和 `--debug`。`--output` 依命令個別註冊，預設格式也因命令而異：`list` 類命令預設輸出表格；`get`、`create` 類命令大多預設輸出 JSON。完整旗標請以 `multica <command> --help` 為準。

| 命令 | 子命令 | 用途 | 關鍵 flag |

| `issue` | `list` | 列出任務 | `--status`、`--priority`、`--assignee`、`--project`、`--metadata`（可重複）、`--property`（可重複，`"Name=Value"`；`__none__` 符合未設定的項目）、`--limit`、`--offset`、`--sort`（含 `property:<名稱或 ID>`）、`--full-id`、`--resolve-properties`（僅限 JSON；在儲存的 ID 旁附上屬性、選項和成員名稱） |
| | `get <id>` | 檢視單一任務 | `--resolve-properties`（僅限 JSON；在儲存的 ID 旁附上屬性、選項和成員名稱） |

| `attachment` | `download <attachment-id>`、`upload <path>` | 下載或上傳附件 | `download`：`--output-dir`；`upload`：`--task` |

| `update` | — | 更新 CLI 到最新版本 | |
| `version` | — | 查看版本資訊 | `--output`（`text` 或 `json`） |

## 從其他程式開發 Agent 操作 Multica

如果你大多在 Codex、Claude Code 或 Cursor 中工作，可以直接從這些工具操作 Multica，
不必切回終端機。[Multica CLI skill](https://github.com/multica-ai/multica-cli)
會教這些 Agent 安全地使用本頁命令：讀取任務和留言討論串而不耗費過多 token、透過檔案撰寫留言，
並妥善處理 mention、狀態變更和指派所帶來的副作用。

它完全透過你已登入的 CLI 執行，本身不會授予額外權限；實際權限仍取決於你的登入帳號、
所選 profile 和工作區。需要 CLI v0.4.26 或更新版本。該儲存庫的 README 說明如何安裝至
Claude Code 外掛市集、Codex skill 安裝器、Cursor，以及其他會載入 Markdown 指令的工具。
