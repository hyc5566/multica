Multica CLI 既負責連接本機執行環境，也可以在終端中管理工作區、任務、Agent 和自動化。這裡介紹常用路徑；當前版本支援的參數始終以命令自身的 `--help` 為準。

## 安裝

**macOS / Linux**

```bash
curl -fsSL https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.sh | bash
```

安裝了 Homebrew 時也可以執行：

```bash
brew install multica-ai/tap/multica
```

**Windows PowerShell**

```powershell
irm https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.ps1 | iex
```

確認安裝成功：

```bash
multica version
```

## 第一次連接

連接 Multica Cloud：

```bash
multica setup
```

連接自託管實例：

```bash
multica setup self-host \
 --server-url https://api.example.com \
 --app-url https://app.example.com
```

`setup` 會儲存服務地址、開啟瀏覽器完成登入，並啟動守護程序。完成後檢查：

```bash
multica auth status
multica daemon status
```

如果只需要重新登入，不想覆蓋其他設定，執行 `multica login`。沒有瀏覽器的環境可以先在 Web 設定中建立個人訪問令牌，再輸入：

```bash
multica login --token
```

命令會在終端中提示粘貼令牌，避免把完整值留在 shell history 中。

## 選擇工作區

列出並切換預設工作區：

```bash
multica workspace list
multica workspace switch <slug>
```

之後的命令會使用這個工作區。單次命令可以通過 `--workspace-id` 臨時覆蓋，也可以設定 `MULTICA_WORKSPACE_ID`。

邀請成員：

```bash
multica workspace member invite teammate@example.com
multica workspace member invite admin@example.com --role admin
```

## 常用任務操作

```bash
# View and search
multica issue list
multica issue get MUL-123
multica issue search "登入失敗"

# Create and update
multica issue create --title "修復登入失敗"
multica issue status MUL-123 in_progress
multica issue assign MUL-123 --to "Backend Agent"

# Comments and run history
multica issue comment list MUL-123
multica issue comment add MUL-123 --content "請先檢查迴歸測試"
multica issue comment update <comment-id> --expected-revision 2 --content "請檢查迴歸測試和發佈說明"
multica issue runs MUL-123
```

長描述或留言從 stdin 讀取，避免處理換行和引號：

```bash
multica issue create --title "升級說明" --description-stdin < notes.md
multica issue comment add MUL-123 --content-stdin < review.md
multica issue comment update <comment-id> --expected-revision 2 --content-file revised-review.md
```

查看某次執行的消息，或停止執行：

```bash
multica issue run-messages <task-id> --issue MUL-123
multica issue cancel-task <task-id> --issue MUL-123
```

## Agent 和 skill

```bash
multica agent list
multica agent get <agent-id>
multica agent create --help
multica agent update <agent-id> --help

multica skill list
multica skill get <skill-id>
multica skill import --url <skill-url>
multica agent skills add <agent-id> --skill-ids <skill-id>
```

匯入時遇到同名 skill，預設會停止且不修改現有內容。按意圖選擇：

```bash
multica skill import --url <skill-url> --on-conflict overwrite
multica skill import --url <skill-url> --on-conflict rename
multica skill import --url <skill-url> --on-conflict skip
```

`overwrite` 只允許 skill 的建立者使用，並保留原來的 ID 與 Agent 綁定關係。

## 守護程序和執行環境

```bash
multica daemon start
multica daemon stop
multica daemon restart
multica daemon status --output json
multica daemon logs --follow

multica runtime list
multica runtime rename <runtime-id> "Office Mac"
multica runtime usage <runtime-id>
multica runtime activity <runtime-id>
```

刪除仍綁定活躍 Agent 的執行環境時，命令預設拒絕。`multica runtime delete <id> --cascade` 會解綁這些 Agent、保留其設定與歷史記錄，並取消它們的活動執行。

執行機制和自定義 profile 見[守護程序與執行環境](/daemon-runtimes)。

## 命令概覽

| 命令 | 用途 |
| --- | --- |
| `issue` | 建立、更新、分配和搜尋任務；管理留言、訂閱、標籤、屬性與執行記錄 |
| `project` | 管理專案及其資源 |
| `label`、`property` | 管理工作區標籤和自定義屬性 |
| `agent`、`skill`、`squad` | 管理 Agent、skill 和小隊 |
| `autopilot` | 管理自動化、觸發器和執行歷史 |
| `workspace` | 建立、查看、切換工作區和邀請成員 |
| `repo` | 管理工作區倉庫，並把倉庫檢出到本機 |
| `daemon`、`runtime` | 啟停本機守護程序，查看和管理執行環境 |
| `attachment` | 上傳或下載附件 |
| `user profile` | 查看或更新當前使用者資料 |
| `auth`、`login`、`setup` | 登入、查看認證狀態和初始化連接 |
| `config` | 查看或修改當前 CLI profile 的本地設定 |
| `update`、`version` | 更新 CLI 或查看版本 |

`multica chat` 讀取的是**Agent 當前正在處理的外部聊天會話**，主要供聊天整合中的 Agent 使用；它不是用於瀏覽任意工作區對話的通用命令。

## ID 和輸出格式

任務使用 `MUL-123` 這樣的 key 或完整 UUID，不接受 UUID 短前綴。

其他資源的 `list` 命令通常顯示可複製的短 ID，並支援 `--full-id` 輸出完整 UUID。短 ID 不唯一時，CLI 會要求增加字符或改用完整 UUID。執行的短 ID 還需要通過 `--issue` 指明所屬任務。

許多命令支援結構化輸出：

```bash
multica issue list --output json
multica agent list --output json
```

腳本使用 JSON 輸出，不解析面向終端的表格。各命令支援的輸出格式和分頁參數以 `multica <command> --help` 為準。

## Profile 與設定

預設設定儲存在 `~/.multica/config.json`。使用 `--profile <name>` 可以隔離另一套服務地址、令牌、預設工作區和守護程序狀態：

```bash
multica setup self-host --profile staging \
 --server-url https://api.staging.example.com \
 --app-url https://app.staging.example.com

multica issue list --profile staging
```

命名 profile 儲存在 `~/.multica/profiles/<name>/config.json`。查看當前值：

```bash
multica config show
multica config show --profile staging
```

<Callout type="warning">
CLI 設定檔包含可代表你訪問 Multica 的令牌。不要提交到倉庫、上傳到日誌或與他人共享。
</Callout>

## 命令參考

下表覆蓋當前全部頂層命令，按 CLI 自身的分組排列。所有命令都接受全局 flag `--server-url`、`--workspace-id`、`--profile` 和 `--debug`。`--output` 是逐命令註冊的 flag，預設格式因命令而異：`list` 類預設表格，`get`、`create` 類多預設 JSON。完整參數以 `multica <command> --help` 為準。

### Core

| 命令 | 子命令 | 用途 | 關鍵 flag |
| --- | --- | --- | --- |
| `issue` | `list` | 列出任務 | `--status`、`--priority`、`--assignee`、`--project`、`--metadata`（可重複）、`--property`（可重複，`"名稱=值"`；`__none__` 匹配未設定）、`--limit`、`--offset`、`--sort`（支援 `property:<名稱或 id>`）、`--full-id`、`--resolve-properties`（僅 JSON；在儲存的 id 旁附上屬性、選項和成員名稱） |
| | `get <id>` | 查看單個任務 | `--resolve-properties`（僅 JSON；在儲存的 id 旁附上屬性、選項和成員名稱） |
| | `create` | 建立任務 | `--title`（必填）、`--description` / `--description-stdin` / `--description-file`、`--status`、`--priority`、`--assignee`、`--parent`、`--stage`、`--project`、`--start-date`、`--due-date`、`--attachment`（可重複） |
| | `update <id>` | 更新任務欄位 | 與 `create` 同類欄位，另有 `--position`、`--no-start`、`--duplicate-of` |
| | `assign <id>` | 指派或取消指派 | `--to`（名稱模糊匹配成員、Agent 或小隊）、`--to-id`、`--unassign`、`--no-start` |
| | `status <id> <status>` | 修改狀態 | `--no-start`、`--duplicate-of` |
| | `reorder <id>` | 在列內移動 | |
| | `search <query>` | 搜尋任務 | `--limit`、`--include-closed` |
| | `children <id>` | 按階段分組列出子任務 | |
| | `pull-requests <id>` | 列出關聯的 PR | |
| | `comment list/add/delete/resolve/unresolve` | 管理留言 | `add`：`--content` / `--content-stdin` / `--content-file`、`--parent`、`--attachment`；`list`：`--since`、`--thread`、`--tail` |
| | `subscriber list/add/remove <issue-id>` | 管理訂閱者 | `--user`、`--user-id`（缺省為當前使用者） |
| | `label list/add/remove <issue-id>` | 管理任務上的標籤 | |
| | `metadata list/get/set/delete <issue-id>` | 管理任務級鍵值元資料 | |
| | `property list/set/unset <issue-id>` | 設定自定義屬性值 | `set`：`--name`、`--value`（`actor` / `multi_actor` 接受成員的名稱、電子郵件或 id） |
| | `runs <issue-id>` | 查看執行歷史 | `--full-id` |
| | `run-messages <task-id>` | 查看單次執行的消息 | `--since`、`--issue` |
| | `usage <issue-id>` | 查看聚合 token 用量 | |
| | `rerun <id>` | 按當前指派重新入隊執行 | |
| | `cancel-task <task-id>` | 取消進行中或排隊中的執行 | `--issue` |
| `project` | `list/get/create/update/delete` | 管理專案 | |
| | `status <id> <status>` | 修改專案狀態 | |
| | `resource list/add/update/remove` | 管理專案附加資源 | `--type`、`--url`、`--local-path`、`--daemon-id`、`--execution-mode`（本地目錄的 `in_place` / `worktree`） |
| `label` | `list/get/create/update/delete` | 管理工作區標籤 | `list`：`--resource-type`（`issue` 或 `skill`）、`--full-id`；`create`：`--name`、`--color`、`--resource-type`（`issue` 或 `skill`）、`--description` |
| `property` | `list/get/create/update/archive/unarchive` | 管理工作區自定義屬性 | `create`：`--name`、`--type`（`text`、`number`、`select`、`multi_select`、`date`、`checkbox`、`url`、`actor`、`multi_actor`、`multi_text`、`multi_url`）、`--option`（可重複，僅 select 類型）；`list`：`--include-archived`；類型建立後不可修改 |
| `agent` | `list/get/create/update/archive/restore` | 管理 Agent | `--name`、`--runtime-id`（`create` 必填）、`--instructions`、`--conversation-starters`、`--model`、`--thinking-level`、`--mcp-config`、`--permission-mode`、`--max-concurrent-tasks` |

| | `tasks <id>` | 查看 Agent 的執行 | |
| | `avatar <id>` | 上傳頭像 | |
| | `env get/set <agent-id>` | 讀寫自定義環境變數（僅 owner 和 admin） | |
| | `skills list/set/add <agent-id>` | 管理綁定的 skill | `--skill-ids`（`set` 全量替換，`add` 增量新增） |
| | `mcp list/add/enable/disable/remove <agent-id>` | 給該 agent 分配工作區 MCP 服務 | server id 從 `workspace mcp list` 獲取。庫裡的條目在這裡新增之前不會生效；`disable` 只停止下發，保留分配 |
| `autopilot` | `list/get/create/update/delete` | 管理自動化 | `create`：`--title`、`--agent`、`--mode`（均必填）、`--project`、`--subscriber`（可重複） |
| | `trigger <id>` | 手動觸發一次 | |
| | `runs <id>` | 查看執行歷史 | |
| | `trigger-add/trigger-update/trigger-delete/trigger-rotate-url` | 管理定時和 webhook 觸發器 | |
| `workspace` | `list/get/create/update/switch` | 管理工作區；`switch` 設定當前 profile 的預設工作區 | |
| | `mcp list/add/update/remove` | 管理工作區的 MCP 服務庫 | 寫操作需要 owner/admin。這裡新增的服務不會分配給任何 agent——用 `multica agent mcp add` 分配給某個 agent。`list` 只列出名稱與 transport；儲存的條目是隻寫的，任何角色都讀不回。`--server-config-file` / `--server-config-stdin` 避免 token 進入 shell 歷史 |
| | `member list/invite <email>` | 查看成員、發出邀請 | `invite`：`--role`（member 或 admin，預設 member） |
| `repo` | `list/add/remove/checkout` | 管理工作區倉庫並檢出到本機 | `--url`（可重複）；`checkout`：`--ref` |
| `skill` | `list/get/create/update/delete` | 管理 skill | |
| | `import` | 從 URL 或本機檔案匯入 skill | `--url` / `--file`、`--on-conflict`（`fail`、`overwrite`、`rename`、`skip`，預設 `fail`） |
| | `search <query>` | 搜尋 skill | |
| | `files list/upsert/delete <skill-id>` | 管理 skill 內的檔案 | |
| | `label list/add/remove <skill-id>` | 管理 skill 上的標籤 | `add` / `remove`：`<label-id>` 可使用完整 UUID 或短前綴 |
| `squad` | `list/get/create/update/delete` | 管理小隊（`delete` 為歸檔） | |
| | `member list/add/set-role/remove` | 管理小隊成員 | |
| | `activity <issue-id> <outcome>` | 記錄隊長評價 | |
| `chat` | `history`、`thread [id]` | 讀取 Agent 當前正在處理的外部聊天會話 | `--limit`、`--before` |

### Runtime

| 命令 | 子命令 | 用途 | 關鍵 flag |
| --- | --- | --- | --- |
| `daemon` | `start` | 啟動本機守護程序 | `--foreground`、`--device-name`、`--runtime-name`、`--workspaces-root`、`--poll-interval`、`--heartbeat-interval`、`--agent-timeout`（`0` 表示不設上限）、`--max-concurrent-tasks`、`--no-auto-update`；均有對應的 `MULTICA_*` 環境變數 |

## 在其他編碼 Agent 裡操作 Multica

如果你的工作大多發生在 Codex、Claude Code 或 Cursor 裡，可以直接在那裡操作 Multica，
不必切回終端。[Multica CLI skill](https://github.com/multica-ai/multica-cli)
會教這些 Agent 安全地使用本頁的命令：低成本地讀任務和留言線程、通過檔案寫留言，
以及正確處理 mention、狀態變更和指派帶來的副作用。

它完全通過你已認證的 CLI 執行，本身不授予任何權限 —— 權限仍然只來自你的登入、
所選 profile 和 workspace。要求 CLI 版本不低於 v0.4.26。該倉庫的 README 說明了
Claude Code 插件市場、Codex skill 安裝器、Cursor 以及其他任何載入 Markdown 指令的
工具的安裝方式。
