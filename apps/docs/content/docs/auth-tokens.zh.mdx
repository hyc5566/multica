日常使用 Multica 時，主要會接觸兩種憑證：瀏覽器登入工作階段和個人存取權杖。瀏覽器工作階段用於 Web 和 Desktop；個人存取權杖用於 CLI、常駐程式、指令碼和 API。

## 瀏覽器登入工作階段

使用電子郵件驗證碼或 Google 登入後，Multica 會將 JWT 儲存在名為 `multica_auth` 的 HttpOnly cookie 中。瀏覽器會自動傳送這個 cookie；JavaScript 無法直接讀取。

工作階段預設有效 30 天，但不會從登入時起固定倒數：持續使用的工作階段會在到期前重新簽發，因此不必定期重新登入。只有剩餘有效期限不到一半時才會重新簽發，所以閒置的工作階段可能在最後使用後不到 30 天就失效。自架管理員可透過 `AUTH_TOKEN_TTL` 調整期限，請參閱[登入與註冊](/auth-setup#登入有效期)。登出會清除目前瀏覽器中的驗證和 CSRF cookie。

瀏覽器 cookie 不適合複製到指令碼或 CLI；若要從終端機存取 Multica，請使用個人存取權杖。

## 個人存取權杖

個人存取權杖（PAT）以 `mul_` 開頭，代表你的帳號。它能存取你有權使用的所有工作區和 API，請像密碼一樣妥善保管。

在 **設定 → API 權杖** 中建立權杖時，需要輸入名稱，並選擇 30 天、90 天、1 年或永不過期；預設選取 90 天。完整權杖只會顯示一次；關閉對話框後，Multica 只會保留：

- 權杖的雜湊值；
- 用於辨識權杖的前幾個字元；
- 名稱、建立時間、到期時間和最近使用時間。

完整權杖無法復原。若遺失，請撤銷舊權杖並建立新的。

<Callout type="warning">
請勿將 PAT 放進儲存庫、任務、留言、螢幕截圖或日誌，也不要直接寫在會被儲存的 shell 命令中。
</Callout>

## CLI 與 PAT

執行 `multica login` 時，CLI 會透過瀏覽器完成登入，再建立有效期限為 90 天的 PAT，並儲存到目前 profile 的設定檔：

```text
~/.multica/config.json
~/.multica/profiles/<name>/config.json
```

常駐程式會使用同一個 PAT 連線至 Multica。設有期限的 `mul_` PAT 在剩餘期限不到 7 天時會自動續期，並從續期當日起延長 90 天。續期失敗不會變更權杖；若權杖已到期或遭撤銷，請重新執行 `multica login`。

在沒有瀏覽器的電腦上，可以先在 Web 建立 PAT，再讓 CLI 安全地提示你輸入：

```bash
multica login --token
```

## 在 API 請求中使用 PAT

將 PAT 放入 `Authorization` 標頭：

```bash
export MULTICA_TOKEN='mul_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx'

curl https://api.multica.ai/api/me \
 -H "Authorization: Bearer $MULTICA_TOKEN"
```

呼叫工作區層級的 API 時，還需要依端點要求提供工作區：

```bash
curl https://api.multica.ai/api/issues \
 -H "Authorization: Bearer $MULTICA_TOKEN" \
 -H "X-Workspace-ID: $MULTICA_WORKSPACE_ID"
```

指令碼應從 secret manager 或受保護的環境變數讀取權杖，不要將它寫死。自架執行個體請將網域替換為自己的公開 API 位址。

## 登出與撤銷

`multica auth logout` 只會刪除目前 CLI profile 中儲存的 PAT；在 Web 登出只會刪除目前瀏覽器的 cookie。兩者都不會撤銷伺服器上的個人存取權杖。

如果權杖可能已外洩，請立即前往 **設定 → API 權杖** 撤銷。撤銷後，這個 PAT 將無法再使用；其他儲存了它的電腦和指令碼也會失去存取權。

## Agent 執行時使用的暫時權杖

常駐程式領取一次執行後，伺服器會建立以 `mat_` 開頭的暫時權杖。權杖會綁定目前的使用者、工作區、Agent 和這次執行，最長有效 24 小時，並在執行結束時清除。

常駐程式會將這個暫時權杖注入 AI 程式開發工具，而不會把使用者的 PAT 交給 Agent。因此，Agent 發出的請求會記錄為 Agent 的操作，而且不能用這個權杖呼叫僅限使用者或 owner 執行的敏感操作。

這類權杖由伺服器自動建立，使用者不必儲存或管理。

## 其他機器憑證

伺服器還會識別兩種用於內部或受管理情境的憑證：

| 前綴 | 用途 | 誰管理 |
| --- | --- | --- |
| `mcn_` | Multica Cloud Node 連接 | Multica Cloud Fleet |
| `mdt_` | 工作區範圍的常駐程式認證協議 | 服務端內部流程 |

一般的 Cloud、自架和 Desktop 安裝都不需要手動建立這些憑證。用戶端的 CLI 與常駐程式一律使用 `mul_` PAT；請勿自行建立其他前綴的權杖。
