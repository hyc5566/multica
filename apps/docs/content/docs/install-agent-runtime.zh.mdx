本地執行環境由兩部分組成：Multica 守護程序，以及它能夠調用的一款 AI 編程工具。只需要安裝你準備使用的工具，不必安裝全部工具。

## 1. 選擇一款工具

已經安裝並登入的工具不需要額外設定。工具之間的模型、MCP、會話恢復和 skill 支援有所不同，詳細差異見 [AI 編程工具對照](/providers)。

## 2. 在本機完成登入

安裝後，先在終端中單獨啟動一次工具，並按照它自己的流程登入或設定模型服務。工具在終端中無法完成請求時，守護程序調用它同樣會失敗。

使用 CodeArts 時，請用 `codearts run --model provider/model "只回覆 OK"` 驗證非交互模式，而不只是驗證 TUI。當前 CodeArts CLI 可能允許自定義 provider 在 TUI 中工作，但 `run`、`models` 和 `serve` 仍要求設定 [`CODEARTS_CLI_AK` / `CODEARTS_CLI_SK`](https://support.huaweicloud.com/usermanual-cli/codeartsagent_cli_0026.html)。Multica 可以從 `~/.codeartsdoer/codearts_cli.json` 或 `.jsonc` 發現自定義模型，但每次執行都會使用 `codearts run`，因此仍遵循該命令的授權要求。

使用 Reasonix 時，請先執行 `reasonix setup`，設定預設的模型服務和模型，再啟動守護程序。

使用 QwenPaw 時，請在 QwenPaw 自身的設定裡選擇模型服務和模型。Multica 無法在執行時覆蓋 QwenPaw 的模型。

使用 MiniMax Code 時，請安裝受支援的 Node.js 版本（`>=22.19 <23` 或 `>=24 <27`），並執行 `npm install --global @minimax-ai/code@latest`。全局 npm 安裝會把 `mcode` 放入 npm 的全局可執行目錄；如果 `command -v mcode` 或 `Get-Command mcode` 找不到它，請將該目錄加入 `PATH`。然後執行 `mcode login`。模型由 MiniMax Code 管理，Multica 無法通過 ACP 覆蓋它。

使用 DeepSeek Harness 時，請先安裝 Node.js 20+ 並執行 `npm install -g @deepseek-ai/dsh`，然後為它安裝 Multica 執行環境 profile —— 這個 bundle 實現了 Multica 驅動的 `--stdio` 協議，也是單獨的 `dsh` 無法直接使用的原因。把 `MULTICA_DSH_PROFILE_BUNDLE` 設為要安裝的 bundle，守護程序會替你安裝；也可以自己執行 `dsh plugin --profile multica add <bundle>`。`<bundle>` 可以是 `dsh plugin` 接受的任意形式——npm 包名、目錄，或打包好的 tarball——Multica 自己的橋接實現在 [multica-ai/dsh-multica-runtime](https://github.com/multica-ai/dsh-multica-runtime)。它目前還沒有發佈到公共 npm registry（[multica#6936](https://github.com/multica-ai/multica/issues/6936)），所以現階段自託管團隊的做法是：從該倉庫自行構建，然後把變數指向構建產物目錄；如果執行守護程序的機器和構建機器不是同一臺，就指向 `npm pack` 產出的 tarball。等橋接發佈之後，直接填包名是最省事的選擇。無論選哪種，都優先用你們自己發佈或構建的產物：這個值會在沒有二次確認的情況下被裝進每一臺守護程序宿主的 DSH 家目錄，填一個未經審查的第三方包是供應鏈決策，不是圖方便。如果你裝的是 DeepSeek Harness Desktop 而不是 npm 包，守護程序也會去找這個應用生成的 CLI shim，位置在它自己的使用者級資料目錄下：macOS 是 `~/Library/Application Support/DSH Desktop`，Windows 是 `%APPDATA%\DSH Desktop`。Windows 上這是漫遊應用資料目錄，不是安裝目錄：應用本身裝在 Program Files 或 `%LOCALAPPDATA%\Programs`，但它驅動的 CLI 和其他使用者級狀態放在一起。這些路徑裡的版本層是生成出來的 id，所以守護程序會枚舉並優先取最新的一份。不需要 PATH 上有別的東西——生成的 shim 會用絕對路徑調用應用自帶的執行環境。如果 DSH Desktop 裝在非預設位置，請用 `MULTICA_DSH_PATH` 指向那個 shim。守護程序只有在 `dsh --profile multica --probe` 成功後才註冊 DeepSeek Harness；失敗時會在 `/health` 報告缺少 profile。啟動守護程序前請設定 `DEEPSEEK_API_KEY`（或在 dsh 自身設定中儲存）。

這些登入憑據由工具儲存在本機。Multica 不會接收 Claude、Codex、Cursor 或其他 CLI 的登入 token。

<Callout type="info">
Antigravity 需要 1.1.10 或更高版本，Claude Code 需要 2.0.0 或更高版本，Codex 需要 0.100.0 或更高版本，Copilot 需要 1.0.0 或更高版本，Grok 需要 0.2.89 或更高版本，Qwen Code 需要 0.20.0 或更高版本，MiniMax Code 需要 0.1.2 或更高版本，OpenCode 需要 1.1.54 或更高版本。低於最低版本時，守護程序不會註冊對應執行環境。
</Callout>

## 3. 確認守護程序能夠找到命令

在 macOS、Linux 或 WSL 中執行：

```bash
command -v <command>
<command> --version
```

在 Windows PowerShell 中執行：

```powershell
Get-Command <command>
<command> --version
```

把 `<command>` 換成表格中的命令，例如 `claude`、`codex` 或 `cursor-agent`。第一條命令返回執行檔路徑。

如果終端能夠找到工具，但 Desktop 或後臺守護程序找不到，通常是兩者使用的 `PATH` 不同。可以重啟應用，或通過對應的 `MULTICA_<PROVIDER>_PATH` 環境變數指定絕對路徑；完整設定見[環境變數](/environment-variables#守護程序設定)。

## 4. 重新檢測並確認上線

使用 CLI 啟動守護程序：

```bash
multica daemon start
```

如果守護程序已經執行，安裝新工具後重新啟動：

```bash
multica daemon restart
```

使用 Multica Desktop 時，退出並重新開啟應用即可。

然後開啟 Multica 的**執行環境**頁面。目標電腦下面會出現對應工具，並顯示為在線。現在可以在建立或編輯 Agent 時選擇這條執行環境。

<Callout type="warning">
守護程序啟動時必須先檢測到至少一款內置支援的 CLI。自定義執行環境設定會在守護程序啟動後同步，因此不能作為一臺空白機器上的唯一啟動條件。只有一個例外：當守護程序剛開始自行安裝 DSH 執行環境 profile（`MULTICA_DSH_PROFILE_BUNDLE`）時，它會在沒有任何執行環境的情況下啟動，並在安裝完成後註冊 DeepSeek Harness。否則，一臺只裝了需要該 profile 的 DSH 的機器永遠裝不完——守護程序會在安裝結束前退出，並把安裝程序一起帶走。
</Callout>

## 未檢測到工具

依次檢查：

1. 在終端執行工具本身，確認安裝和登入都已完成。
2. 用 `command -v` 或 `Get-Command` 檢查實際命令名和路徑。
3. 執行 `multica daemon logs -f`，查看版本、路徑或認證錯誤。
4. 重啟守護程序，讓它重新讀取當前環境。
5. 回到**執行環境**頁面，確認電腦和工具都已上線。

工具已經顯示在線，但執行仍然失敗時，開啟任務的執行記錄查看 CLI 返回的具體錯誤，或繼續閱讀[故障排查](/troubleshooting)。
