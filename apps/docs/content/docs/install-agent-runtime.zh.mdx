本機執行環境由兩部分組成：Multica 常駐程式，以及常駐程式會呼叫的一款 AI 程式開發工具。只要安裝你要使用的工具即可，不必全部安裝。

## 1. 選擇一款工具

已安裝並登入的工具不需要額外設定。各工具支援的模型、MCP、工作階段恢復和 skill 各不相同，詳情請參閱[AI 程式開發工具比較](/providers)。

## 2. 在本機完成登入

安裝後，請先在終端機單獨啟動工具一次，並依照工具流程登入或設定模型供應商。如果工具無法在終端機完成請求，常駐程式呼叫它時也會失敗。

使用 CodeArts 時，請執行 `codearts run --model provider/model "Reply OK"`，確認非互動模式可正常使用；只測試 TUI 並不足夠。目前的 CodeArts CLI 可能允許在 TUI 使用自訂 provider，但 `run`、`models` 和 `serve` 仍要求設定 [`CODEARTS_CLI_AK` / `CODEARTS_CLI_SK`](https://support.huaweicloud.com/usermanual-cli/codeartsagent_cli_0026.html)。Multica 可從 `~/.codeartsdoer/codearts_cli.json` 或 `.jsonc` 偵測自訂模型，但每次執行都會使用 `codearts run`，因此仍須符合該命令的授權要求。

使用 Reasonix 時，請先執行 `reasonix setup`，設定預設的模型供應商和模型，再啟動常駐程式。

使用 QwenPaw 時，請在 QwenPaw 自己的設定中選擇模型供應商和模型。Multica 無法在執行時覆寫 QwenPaw 的模型。

使用 MiniMax Code 時，請安裝受支援的 Node.js 版本（`>=22.19 <23` 或 `>=24 <27`），並執行 `npm install --global @minimax-ai/code@latest`。全域 npm 安裝會將 `mcode` 放在 npm 的全域可執行檔目錄；如果 `command -v mcode` 或 `Get-Command mcode` 找不到它，請將該目錄加入 `PATH`。接著執行 `mcode login`。模型由 MiniMax Code 管理，Multica 無法透過 ACP 覆寫。

使用 DeepSeek Harness 時，請先安裝 Node.js 20+，並執行 `npm install -g @deepseek-ai/dsh`，接著安裝 Multica 執行環境 profile。這個 bundle 實作 Multica 所需的 `--stdio` 協定；單獨安裝 `dsh` 無法直接供 Multica 使用。你可以將 `MULTICA_DSH_PROFILE_BUNDLE` 設為要安裝的 bundle，讓常駐程式代為安裝；也可以自行執行 `dsh plugin --profile multica add <bundle>`。`<bundle>` 可以是 `dsh plugin` 接受的任一格式：npm 套件名稱、目錄或封裝好的 tarball。Multica 自己的橋接程式位於 [multica-ai/dsh-multica-runtime](https://github.com/multica-ai/dsh-multica-runtime)。目前尚未發佈至公開 npm registry（[multica#6936](https://github.com/multica-ai/multica/issues/6936)），因此自架團隊目前須從該儲存庫自行建置，並將變數指向建置產物目錄；若常駐程式所在的機器與建置機器不同，則指向 `npm pack` 產生的 tarball。橋接程式正式發佈後，直接填入套件名稱會是最簡單的選擇。無論選用哪種方式，都建議使用團隊自行發佈或建置的產物：此值會在沒有額外確認的情況下安裝至每台常駐程式主機的 DSH 家目錄，因此採用未經審查的第三方套件屬於供應鏈決策，不能只為了方便而選擇。

如果安裝的是 DeepSeek Harness Desktop，而非 npm 套件，常駐程式也會尋找該 App 產生的 CLI shim。它位於 App 的使用者資料目錄：macOS 為 `~/Library/Application Support/DSH Desktop`，Windows 為 `%APPDATA%\DSH Desktop`。Windows 的這個路徑是漫遊應用程式資料目錄，不是安裝目錄：App 本身安裝在 Program Files 或 `%LOCALAPPDATA%\Programs`，而它使用的 CLI 與其他使用者狀態則放在同一處。路徑中的版本目錄名稱是自動產生的 ID，因此常駐程式會列舉目錄並優先使用最新的一份。不必另外將路徑加入 `PATH`，因為產生的 shim 會使用絕對路徑呼叫 App 隨附的執行環境。如果 DSH Desktop 安裝在非預設位置，請用 `MULTICA_DSH_PATH` 指向 shim。常駐程式只有在 `dsh --profile multica --probe` 成功後，才會註冊 DeepSeek Harness；若失敗，則會在 `/health` 回報缺少 profile。啟動常駐程式前，請設定 `DEEPSEEK_API_KEY`（或在 dsh 自身的設定中儲存）。

各工具會在本機儲存登入憑證。Multica 不會取得 Claude、Codex、Cursor 或其他 CLI 的登入權杖。

<Callout type="info">
Antigravity 需要 1.1.10 或更新版本，Claude Code 需要 2.0.0 或更新版本，Codex 需要 0.100.0 或更新版本，Copilot 需要 1.0.0 或更新版本，Grok 需要 0.2.89 或更新版本，Qwen Code 需要 0.20.0 或更新版本，MiniMax Code 需要 0.1.2 或更新版本，OpenCode 需要 1.1.54 或更新版本。低於最低版本時，常駐程式不會註冊對應的執行環境。
</Callout>

## 3. 確認常駐程式找得到命令

在 macOS、Linux 或 WSL 中執行：

```bash
command -v <command>
<command> --version
```

在 Windows PowerShell 中執行：

```powershell
Get-Command <command>
<command> --version
```

將 `<command>` 換成表格中的命令，例如 `claude`、`codex` 或 `cursor-agent`。第一個命令會顯示執行檔的路徑。

如果終端機找得到工具，但 Desktop 或背景中的常駐程式找不到，通常是因為兩者使用不同的 `PATH`。你可以重新啟動 App，或透過相應的 `MULTICA_<PROVIDER>_PATH` 環境變數指定絕對路徑；完整設定請參閱[環境變數](/environment-variables#常駐程式設定)。

## 4. 重新偵測並確認執行環境在線

使用 CLI 啟動常駐程式：

```bash
multica daemon start
```

如果常駐程式已經執行，安裝新工具後重新啟動：

```bash
multica daemon restart
```

使用 Multica Desktop 時，請結束並重新開啟應用程式。

接著開啟 Multica 的**執行環境**頁面。目標電腦下方會列出對應工具，並顯示在線。之後建立或編輯 Agent 時，就能選擇這個執行環境。

<Callout type="warning">
常駐程式啟動前，必須先偵測到至少一款內建支援的 CLI。自訂執行環境設定會在常駐程式啟動後才同步，因此無法作為全新機器上唯一的啟動條件。唯一例外是常駐程式剛開始自行安裝 DSH 執行環境 profile（`MULTICA_DSH_PROFILE_BUNDLE`）時：此時即使尚未偵測到任何執行環境，常駐程式仍會啟動，並在安裝完成後註冊 DeepSeek Harness。否則，如果機器只安裝了需要該 profile 的 DSH，就永遠無法完成安裝，因為常駐程式會在安裝結束前退出，連帶終止安裝程序。
</Callout>

## 找不到工具

請依序檢查：

1. 在終端機中直接執行工具，確認已完成安裝和登入。
2. 用 `command -v` 或 `Get-Command` 檢查實際命令名和路徑。
3. 執行 `multica daemon logs -f`，查看版本、路徑或驗證錯誤。
4. 重新啟動常駐程式，讓它重新讀取目前環境。
5. 回到**執行環境**頁面，確認電腦和工具都在線。

若工具顯示在線但執行仍失敗，請開啟任務的執行記錄查看 CLI 回報的錯誤，或參閱[疑難排解](/troubleshooting)。
