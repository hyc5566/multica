當一項工作需要由 Agent 持續負責時，把任務分配給它。Agent 會讀取任務的說明和討論，使用自己的設定與 skill 完成工作，並把進展和結果寫回原來的任務。

只需要 Agent 處理一條具體請求、不改變負責人時，改用[留言中的 @提及](/mentioning-agents)。

## 分配並開始執行

1. 開啟一條任務，點擊**負責人**。
2. 選擇一個 Agent 或小隊。
3. 在確認窗口中檢查即將啟動的 Agent，然後選擇**開始**。

![分配確認窗：確認分配，或選擇暫不開始](/images/docs/assign-confirm-dialog.webp)

這次執行需要 Agent 知道的資訊，都寫在任務本身——它的說明、討論，或者專案說明與 Agent 指令中。

分配給小隊時，任務的負責人是小隊，首先開始執行的是小隊 leader。它會按照小隊的工作方式判斷是否需要交給其他成員。

## 分配後的執行流程

Multica 會為 Agent 建立一條[執行](/tasks)。在線執行環境領取執行後，會調用本機的 AI 編程工具；進度、留言和結果隨後顯示在任務中。

執行環境暫時離線時，執行留在隊列中等待；執行綁定該執行環境，不會轉移到其他電腦執行。

Agent 在執行時可以：

- 讀取任務的描述、屬性和留言；
- 使用綁定的 skill、MCP 和專案上下文；
- 在本地工作目錄中讀取檔案、執行命令和修改內容；
- 發表留言並更新任務狀態。

具體能力仍受 Agent 設定、執行環境和你的調用權限限制。

執行過程中，Agent 根據工作對任務的實際影響管理狀態：開始做任務本身要求的工作時立刻推到 `in_progress`，交付即推到 `in_review`，工作跨輪繼續則保持 `in_progress`，僅答疑或討論則不動狀態——這些動作以 Agent 的身份出現在時間線中。執行的生命週期和任務狀態是分開的：執行完成本身不會改變任務狀態。

負責人是[小隊](/squads)時，同樣的規則適用：Multica 入隊的是隊長，派活不等於交付——派活輪結束時父任務處於 `in_progress`，整體目標達成後隊長才推到 `in_review`。

## 只分配，暫時不啟動

確認窗口中的**暫不開始**會儲存負責人，但不建立這一次執行。適合先明確歸屬，等背景或依賴準備好以後再開始。

`backlog` 也不會因為分配 Agent 而啟動執行。把任務移出 `backlog`，或者在留言中繼續向負責人提出要求後，才會產生後續執行。

如果任務已指派給 Agent 或小隊負責人，將它移出 `backlog` 會彈出相同的確認視窗：這次狀態變更會啟動執行，因此同樣可以選擇**暫不開始**，只變更狀態而不喚醒 Agent。目標狀態只要不屬於 `backlog`、`done` 或 `cancelled` 分類，就會顯示確認視窗。

只有 `backlog` 分類會暫停執行；該分類下的[自訂狀態](/issues#custom-statuses)行為相同。已處於 `done` 或 `cancelled` 的任務，在指派或重新指派給 Agent 時也會立即開始執行。

## 分配權限

能否分配由 Agent 的 Access 決定：

- **僅自己**：只有 Agent owner 可以調用；
- **指定成員**：owner 和名單中的成員可以調用；
- **整個工作區**：所有工作區成員都可以調用。

工作區 owner 和 admin 可以管理 Agent，但"看得到"不代表"可以執行"。負責人選擇器會禁用你無權調用的 Agent。完整規則見[Agent](/agents#權限與-access)。

## 更換或移除負責人

把負責人換成另一個 Agent，會為新負責人啟動一次新的執行；選擇成員只會改變負責人，不會調用 AI 編程工具。移除負責人也不會建立執行。

<Callout type="warning">
更換負責人、取消分配或修改任務狀態，都不會停止已經開始的執行。需要中斷時，在執行日誌中停止對應的執行。
</Callout>

## 使用 CLI

```bash
multica issue assign MUL-42 --to "Agent name"
multica issue assign MUL-42 --to-id <agent-uuid> --no-start
multica issue status MUL-42 in_progress --no-start
multica issue assign MUL-42 --unassign
```

腳本中用 `--to-id <uuid>` 可避免同名對象匹配錯誤。UUID 通過 `multica agent list --output json` 或 `multica workspace member list --output json` 查看。

如果指派只用於記錄負責人、不應建立新執行（例如同一 Agent 已在另一次執行中處理該任務），請使用 `--no-start`。`issue update` 和 `issue status` 同樣支援這個 flag。如果只記錄歸屬的流程同時修改負責人和狀態，兩條命令都要傳入該 flag；抑制指派不會自動抑制後續狀態變更觸發的執行。
