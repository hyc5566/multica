需要 Agent 持續負責一項工作時，請將任務指派給它。Agent 會閱讀任務說明和討論，使用自己的設定與 skill 完成工作，並把進度和結果寫回原任務。

只需要 Agent 處理一項具體要求，而不變更負責人時，請改用[在留言中 @提及](/mentioning-agents)。

Agent這次需要知道的資訊，要寫在任務的說明和討論裡，或者寫進專案說明和Agent指令。

指派給小隊時，小隊會成為任務負責人，並由小隊 leader 先開始執行。leader 會依小隊的運作方式判斷是否交由其他成員處理。

## 指派後的執行流程

Multica 會為 Agent 建立一次[執行](/tasks)。在線的執行環境領取後，會呼叫該電腦上的 AI 程式開發工具；進度、留言和結果接著會顯示在任務中。

執行環境暫時離線時，執行會留在佇列中等待。每次執行都綁定原本的執行環境，不會轉到其他電腦。

Agent 在執行時可以：

- 閱讀任務說明、欄位和留言；
- 使用綁定的 skill、MCP 和專案上下文；
- 在本機工作目錄中讀取檔案、執行命令和修改內容；
- 發表留言並更新任務狀態。

Agent 的實際能力仍受其設定、執行環境和你的執行權限限制。

Agent會隨工作進展更新任務狀態。預設情況下，開始工作時改為進行中，交付後改為稽核中；專案使用工作流時，則按其中的步驟和交接說明推進。一次執行結束不等於任務完成，僅回答一個問題也不表示任務本身的工作已經交付。

專案經常需要在成員或Agent之間交接時，可以用[工作流](/workflows)安排每一步。只是經常傳送同一類請求、希望保留原負責人時，可以儲存成[快捷操作](/quick-actions)。

## 只指派，暫不開始

在確認對話框中選擇**暫不開始**，會儲存負責人，但不會建立這次執行。適合先確認工作歸屬，等背景資訊或相依項目備妥後再開始。

將 Agent 指派給 `backlog` 任務時也不會開始執行。將任務移出 `backlog`，或在後續留言中再向負責人提出要求，才會觸發執行。

如果任務已經有Agent或小隊負責人，把它移出 `backlog` 也會彈出同一個確認窗，因為啟動執行的是這次狀態變更。窗裡同樣有**暫不開始**：只改狀態，不叫醒Agent。只要目標不是 `backlog` 本身，也不屬於 `done` 或 `closed` 分類，都會彈這個確認窗。

只有固定的 `backlog` 狀態有這個效果。`unstarted` 分類下的[自定義狀態](/issues#自定義狀態)**不會**停住工作，把Agent分配到那裡會立刻啟動執行。已經處於 `done` 或 `cancelled` 的任務，分配或重新分配給Agent時同樣會立即開始執行。

## 指派權限

你能否指派 Agent 由其 Access 設定決定：

- **Only me**：只有 Agent owner 可以執行；
- **Specific people**：Agent owner 和清單中的成員可以執行；
- **Entire workspace**：所有工作區成員都可以執行。

工作區 `owner` 和 `admin` 可以管理 Agent，但能看到 Agent 不代表有權執行。負責人選擇器會停用你無權執行的 Agent。完整規則請參閱[Agent](/agents#權限與-access)。

## 更換或移除負責人

將負責人改為另一個 Agent，會為新負責人開始一次執行；改為成員只會變更負責人，不會呼叫 AI 程式開發工具。移除負責人也不會建立執行。

<Callout type="warning">
通常，更換或移除負責人不會停止已經開始的執行，需要時請在執行日誌中停止。[工作流交接](/workflows)的確認視窗還可以在移動任務的同時，停止或取消上一位Agent的執行。
</Callout>

## 使用 CLI

```bash
multica issue assign MUL-42 --to "Agent name"
multica issue assign MUL-42 --to-id <agent-uuid> --no-start
multica issue status MUL-42 in_progress --no-start
multica issue assign MUL-42 --unassign
```

在指令稿中使用 `--to-id <uuid>`，可避免誤選同名對象。請用 `multica agent list --output json` 或 `multica workspace member list --output json` 查詢 UUID。

如果指派只是要記錄負責人，不應建立新的執行（例如同一 Agent 已在另一個執行中處理該任務），請使用 `--no-start`。`issue update` 和 `issue status` 也支援這個 flag。如果流程同時變更負責人和狀態，兩個命令都要帶上此 flag；抑制指派觸發不會一併抑制後續由狀態變更觸發的執行。
