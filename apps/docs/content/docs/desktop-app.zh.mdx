Multica Desktop 支援 macOS、Windows 和 Linux。它與 Web 版共用帳號和工作區資料，但會自動管理本機常駐程式，並為每個工作區分別保留分頁。

## Desktop 與 Web

| | Web | Desktop |
| --- | --- | --- |
| 開啟方式 | 使用瀏覽器 | 安裝桌面版 App |
| 工作區分頁 | 使用瀏覽器分頁 | 每個工作區各自保留分頁 |
| 常駐程式 | 需要另外安裝並啟動 CLI | 登入後由 App 自動啟動 |
| 更新 | 重新整理頁面 | 透過桌面版 App 更新 |

要快速查看，或使用公用電腦時，Web 版較方便。

你可以同時登入 Web 和 Desktop。只要兩者連線至同一個 Multica 服務，顯示的資料就會共用。

## 安裝

請從 [Multica 下載頁](https://multica.ai/download)選擇符合作業系統和處理器架構的安裝程式：

| 平台 | 安裝程式 |
| --- | --- |
| macOS | `.dmg` |
| Windows | `.exe` |
| Linux | `.AppImage`、`.deb` 或 `.rpm` |

安裝後，使用 Web 版的同一個電子郵件帳號登入。登入後，Desktop 會啟動隨附的 Multica CLI，並偵測本機已安裝的 AI 程式開發工具。

<Callout type="info">
Desktop 隨附的 CLI 僅供 App 管理執行環境使用。如果你也想在終端機執行 `multica issue` 等命令，請依照[快速入門第 2 步](/cloud-quickstart#2-連接一台電腦)另外安裝 CLI。
</Callout>

## 桌面標籤頁

Desktop 會分別儲存每個工作區的分頁。例如，你在工作區 A 開啟三個任務，切換至工作區 B 時會看到 B 的分頁；切回 A 時，原本的三個分頁仍會保留。

同一項資源在目前工作區只會開啟一個分頁。分頁可以重新排序、釘選或關閉，並各自保留前進／返回瀏覽紀錄和捲動位置。點選或貼上這個部署環境的 App 連結時，頁面會直接在分頁中開啟，不會跳至瀏覽器。

登出會清除本機儲存的所有分頁，避免下一位使用者看到前一個帳號留下的頁面。

## 內置常駐程式

登入後，Desktop 會為目前的 Multica 服務建立專用 CLI profile，並以此啟動常駐程式。profile 位於：

```text
~/.multica/profiles/desktop-<host>/
```

它不會讀取或覆寫你在終端機使用的預設 profile。如果你也手動啟動另一個常駐程式，Multica 會將兩者顯示為不同的執行環境。

你可以在 Desktop 設定中查看執行狀態和日誌。如果未偵測到工具，請先確認它能在一般終端機中執行且已登入，再重新啟動 Desktop 的常駐程式。

## 更新 Desktop

自動更新預設為開啟。App 會在背景檢查並下載新版本；下載完成後，你可以立即重新啟動以安裝，也可以等到下次結束 App 時再安裝。你也可以在 **設定 → 更新**中關閉自動檢查，或手動檢查新版本。

更新會依作業系統和處理器架構分發：

- Windows arm64 和 macOS x64（Intel）各自使用獨立的更新來源；
- 其他架構使用預設更新來源；
- App 會自動選擇更新來源，不必手動設定；
- Linux 僅 `.AppImage` 支援自動更新；`.deb` 和 `.rpm` 請下載新版套件並覆蓋安裝；
- 若自動更新失敗，也請從下載頁取得相應的安裝套件並覆蓋安裝。

## 連接自架實例

Desktop 預設連線至 Multica Cloud。若要連線至自架執行個體，請在使用者家目錄的 `.multica` 資料夾中建立 `desktop.json`：

| 平台 | 路徑 |
| --- | --- |
| macOS | `/Users/<你>/.multica/desktop.json` |
| Linux | `/home/<你>/.multica/desktop.json` |
| Windows | `C:\Users\<你>\.multica\desktop.json` |

以上為預設路徑。如果使用者家目錄已遷移或重新導向，請改用實際路徑。

```json
{
 "schemaVersion": 1,
 "apiUrl": "https://api.example.com"
}
```

<Callout type="warning">
這個文件**不是** CLI 的 `~/.multica/config.json`，字段名也不同：CLI 用 `server_url`，Desktop 用 `apiUrl`。Desktop 不會讀取 CLI 的設定，它在 `~/.multica/profiles/desktop-<host>/` 下管理獨立的 daemon profile。改 `config.json` 不會影響 Desktop 連接哪個服務。
</Callout>

`apiUrl` 是 backend 的公開位址，為必填欄位，且必須使用 `http` 或 `https`。另外兩個位址可省略，Desktop 會自動推導：

- `wsUrl`：把 `apiUrl` 的協議換成 `ws` 或 `wss`，並在路徑後追加 `/ws`；
- `appUrl`：域名以 `api.` 開頭且至少三段時去掉 `api.` 前綴（`api.example.com` → `example.com`），否則保持與 `apiUrl` 相同。

通常只需設定 `apiUrl`。若推導結果不符合預期，再明確指定其他位址；常見情況有三種：

- Web 和 API 使用不同網域；
- WebSocket 獨立部署；
- 網域不符合移除前綴的規則（`api.local` 這類只有兩段的網域不會移除前綴）。

```json
{
 "schemaVersion": 1,
 "apiUrl": "https://api.example.com",
 "appUrl": "https://app.example.com",
 "wsUrl": "wss://ws.example.com/socket"
}
```

儲存後請重新啟動 Desktop，因為設定只會在啟動時讀取一次。兩種失敗情況的表現不同，可據此快速判斷：

- **找不到檔案**（目錄錯誤，或檔名不是 `desktop.json`）：Desktop 會使用預設的 Cloud 設定，不會顯示錯誤。因此，如果 Desktop 仍顯示 Cloud 位址且沒有設定錯誤，代表檔案不在 Desktop 尋找的位置。
- **找到檔案但內容無效**（JSON、版本或 URL 有問題）：Desktop 會顯示設定錯誤，不會自動退回 Cloud。

刪除該檔案並重新啟動，即可恢復預設的 Cloud 設定。

<Callout type="warning">
Desktop 只能連線至瀏覽器和執行電腦都能存取的位址。遠端自架執行個體若未使用 HTTPS 或未代理 WebSocket，Desktop 就無法建立連線；完整設定請參閱[自架快速入門](/self-host-quickstart#3-選擇存取方式)。
</Callout>

### Windows：檢查檔名和編碼

Windows 上有兩種編輯器預設行為，可能會不知不覺產生 Desktop 無法使用的檔案：

- **記事本會自動加上 `.txt` 副檔名**。儲存為 `desktop.json` 時，實際檔名可能是 `desktop.json.txt`，Desktop 便會判定找不到檔案。請在檔案總管中開啟顯示副檔名，或在儲存對話框選擇*所有檔案*。若要確認實際檔名，請在 PowerShell 執行 `Get-ChildItem "$env:USERPROFILE\.multica" -Filter "desktop.json*"`；`Name` 欄必須正好是 `desktop.json`。
- **PowerShell 重新導向可能寫入 UTF-16 或 BOM**。`> desktop.json` 和 `Out-File` 可能產生無法解析的編碼，導致設定錯誤。

使用 PowerShell 一次建立檔案，即可避開這兩個問題：

```powershell
$dir = "$env:USERPROFILE\.multica"
New-Item -ItemType Directory -Force $dir | Out-Null
$json = @'
{
 "schemaVersion": 1,
 "apiUrl": "https://api.example.com"
}
'@
[System.IO.File]::WriteAllText("$dir\desktop.json", $json)
```

## Windows Defender 把 Multica 報成病毒

**現象**：Windows 安全性報告 `Trojan:Script/Wacatac.B!ml` 等威脅，並隔離 Desktop 安裝目錄中的檔案。通常遭隔離的是隨附的 CLI，而非 App 主程式：

```text
C:\Users\<你>\AppData\Local\Programs\@multicadesktop\resources\app.asar.unpacked\resources\bin\multica.exe
```

**這是誤判。** `!ml` 後綴表示 Defender 是透過機器學習啟發式判斷，而非比對病毒特徵碼。Multica 的 Windows 版本目前尚未使用 Authenticode 進行程式碼簽署；剛發佈、未簽署，且會啟動背景程序並建立網路連線的二進位檔，正是這類啟發式容易判定為可疑的對象。所有 Windows 成品都由 GitHub Actions 從本儲存庫的公開原始碼建置。

**你可以自行驗證**：每個 GitHub release 都會發佈 `checksums.txt`，列出所有 CLI 壓縮檔的校驗碼：

```powershell
Get-FileHash .\multica-cli-<version>-windows-amd64.zip -Algorithm SHA256
```

請將輸出的雜湊值與[最新 release](https://github.com/multica-ai/multica/releases/latest) 中 `checksums.txt` 的對應項目比對。

**處理方式**：

1. **還原遭隔離的檔案**：Windows 安全性 → *病毒與威脅防護* → *保護歷程記錄* → 選取 Multica 項目 → *動作* → *還原*。
2. **新增排除項目**，避免檔案再次遭隔離：*病毒與威脅防護* → *管理設定* → *排除項目* → *新增或移除排除項目* → *資料夾*，並加入以下兩個路徑：
 - `%LOCALAPPDATA%\Programs\@multicadesktop`
 - `%APPDATA%\Multica`

   兩個路徑都必須加入：隨附 CLI 遺失時，Desktop 會將替代版本下載到 `%APPDATA%\Multica\bin`。若只排除安裝目錄，下載的副本還是會遭隔離，形成循環。
3. **向 Microsoft 回報誤判**：前往 [Microsoft Security Intelligence 檔案提交頁](https://www.microsoft.com/en-us/wdsi/filesubmission)，選擇 *Software developer* 和 *Incorrectly detected as malware*。這樣才能讓 Microsoft 撤銷對所有使用者的偵測結果，通常幾天內生效。

<Callout type="warning">
只有在你從[下載頁](https://multica.ai/download)或 [GitHub releases](https://github.com/multica-ai/multica/releases) 安裝，且校驗碼相符時，才新增這些排除項目。排除項目會關閉該資料夾內所有檔案的即時防護。
</Callout>
