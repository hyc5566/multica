專案用來整理需要多項[任務](/issues)共同完成的工作，例如產品上市、系統移轉，或分階段交付的功能。

一項任務就能說明完整的工作不需要建立專案。若多項工作有共同目標、需要一起追蹤進度，或需要共用儲存庫和工作目錄，就適合放在同一個專案中。

## 專案的組成

| 內容 | 用途 |
|---|---|
| **名稱、圖示和描述** | 目標、範圍和長期要求；描述會加入專案內 Agent 的執行脈絡。 |
| **狀態** | `planned`、`in_progress`、`paused`、`completed` 或 `cancelled`。 |
| **優先順序** | `urgent`、`high`、`medium`、`low` 或 `none`。 |
| **負責人（lead）** | 負責協調專案的成員或 Agent。 |
| **開始和目標日期** | 專案規劃的時間範圍。 |
| **任務和進度** | 專案中的工作及完成比例。 |
| **資源** | 連結的 GitHub 儲存庫或特定電腦上的本機目錄。 |

## 專案和任務的關係

一個專案可以包含任意數量的任務；一項任務最多只能屬於一個專案。你可以直接在專案中建立任務，也可以在任務屬性中選擇或變更所屬專案。

專案進度會依關聯任務自動計算：

```text
進度 = 狀態為 done 或 cancelled 的任務數 ÷ 專案中的全部任務數
```

`cancelled` 表示這項工作已從專案範圍中結案，因此會計入進度。專案狀態和任務狀態彼此獨立：所有任務完成後，專案不會自動變為 `completed`；變更專案狀態也不會批次變更其中的任務。

## 專案描述與執行脈絡

Agent 執行專案內的任務時，專案名稱和描述會加入這次執行的脈絡。描述適合記錄所有相關任務都會用到的資訊，例如目標、技術界線和交付慣例。只適用於單一任務的要求請寫在該任務中。

## 加入資源

專案資源會指出 Agent 應使用哪些程式碼和工作目錄：

- **GitHub 儲存庫**：提供執行環境可 checkout 的儲存庫，也可以指定 ref。
- **本機目錄**：讓特定電腦上的執行環境使用既有目錄，Agent 會直接修改其中的內容。

如何選擇及其安全界線，請參閱[專案資源](/project-resources)。

## 專案負責人

Lead 可以是成員或 Agent，表示由誰協調專案。這不是權限設定，也不會自動指派專案中的任務；將 Agent 設為 lead 也不會自動啟動它。要開始執行，仍需指派任務、@提及 Agent，或透過自動化觸發。

## 釘選到側邊欄

釘選專案後，它會出現在你的側邊欄。釘選是個人偏好，不會影響其他成員。

## 建立、編輯和刪除

所有工作區成員都可以建立和編輯專案；只有 `owner` 和 `admin` 可以刪除。

<Callout type="warning">
刪除專案不會刪除其中的任務：任務會解除關聯並繼續留在工作區。專案描述、狀態和資源則會永久刪除。
</Callout>
