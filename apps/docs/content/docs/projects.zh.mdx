專案用來整理需要多項[任務](/issues)共同完成的工作，例如產品上市、系統移轉，或分階段交付的功能。

一項任務就能說明完整的工作不需要建立專案。若多項工作有共同目標、需要一起追蹤進度，或需要共用儲存庫和工作目錄，就適合放在同一個專案中。

## 專案的組成

| 內容 | 用途 |
|---|---|
| **名稱、圖標和描述** | 目標、範圍和長期有效的要求；描述會進入專案內Agent的執行上下文。 |
| **狀態** | `planned`、`in_progress`、`paused`、`completed` 或 `cancelled`。 |
| **優先級** | `urgent`、`high`、`medium`、`low` 或 `none`。 |
| **負責人（lead）** | 成員或Agent，表示誰負責協調專案。 |
| **訪問權限** | 整個工作區，或僅專案成員。見[私有專案](#private-projects)。 |
| **開始和截止日期** | 專案計劃的時間範圍。 |
| **任務和進度** | 專案中的工作及其完成比例。 |
| **資源** | 關聯的 GitHub 儲存庫或指定電腦上的本地目錄。 |
| **工作流程** | 任務經過哪些步驟，以及每一步由誰接手。 |

## 瀏覽項目

打開**全部項目**，在顯示菜單中選擇**表格**或**看板**。兩種佈局都支援搜索，以及按狀態、優先級和負責人篩選。可按狀態、優先級、負責人或[文件夾](#folders)分組，表格也可不分組。在看板中把項目拖到另一列，會修改對應欄位。

表格可顯示開始日期、截止日期、進度和最近活動，也可按這些欄位、名稱、狀態、優先級或建立時間排序。佈局、分組、排序、顯示列和篩選條件按使用者與工作區保存，並在設備間同步；搜索文字不保存。

## 項目和任務的關係

一個專案可以包含任意數量的任務；一項任務最多隻能屬於一個專案。你可以直接在專案中建立任務，也可以在任務屬性中選擇或變更所屬專案。

專案進度會依關聯任務自動計算：

```text
进度 = 状态属于 done 或 closed 分类的任务数 ÷ 项目中的全部任务数
```

內建狀態裡就是 `done` 和 `cancelled`，歸入這兩個分類的自訂狀態也一樣計入。`cancelled` 表示這項工作已從專案範圍中結束，所以算進進度。

專案狀態和任務狀態各管各的：所有任務完成後，專案不會自動變為 `completed`；修改專案狀態，也不會批次修改其中的任務。

## 專案描述與執行脈絡

Agent 執行專案內的任務時，專案名稱和描述會加入本次執行的上下文。所有相關執行都需要知道的資訊寫在描述裡，比如目標、技術邊界、交付約定；只與單條任務相關的要求寫在那條任務中。

## 加入資源

專案資源會指出 Agent 應使用哪些程式碼和工作目錄：

- **GitHub 儲存庫**：提供可 checkout 的儲存庫和可選 ref。
- **本機目錄**：讓指定電腦上的執行時使用已有目錄：Agent 直接修改該目錄，或在它的獨立 worktree 中工作。

如何選擇及其安全界線，請參閱[專案資源](/project-resources)。

## 選擇工作流程

專案的**工作流程**決定看板有哪些列，以及任務進入每一步時交給誰。例如開發交給一個 Agent，審查交給另一個，最後交給成員驗收。沒有選用其他工作流程時，使用 **Default**：所有狀態都可用，也不會自動交接。建立流程和切換已有專案的方法見[工作流程](/workflows)。

## 專案負責人

專案負責人可以是成員或 Agent，擔任負責人的成員還可以為專案切換工作流程。設定負責人不會把任務分配給它，也不會啟動任何工作；想讓某一步交給專案負責人，在工作流程裡把這一步的處理人設為**專案負責人**。

## 私有項目 [#private-projects]

項目的**訪問權限**分為**整個工作區**和**僅項目成員**兩種。私有項目及其中的任務、評論和附件，只有成員名單里的人能看到。對其他人來說，它不會出現在列表和搜索中，打開連結也會顯示不存在。

### 誰能看到私有項目

- **只有成員名單里的人**。工作區角色不帶來任何訪問權限：不在名單里的 `owner` 或 `admin` 也看不到這個項目。他們和其他人一樣被加入名單，也可以被移出。
- **Agent**跟隨它所代表的人。只有觸發運行的人和Agent的所有者都在名單里，這次運行才能看到私有項目。私有項目中的任務只能分配給所有者在名單里的Agent。
- 成員離開工作區時，會同時離開其中所有私有項目。

<Callout type="info">
如果你是 `owner` 或 `admin`，某個私有項目不再出現，說明你不在它的成員名單里。請管理該項目訪問權限的成員把你加進去；工作區所有者也可以在設置中加入（見[工作區所有者恢復訪問](#workspace-owner-recovery)）。
</Callout>

### 誰能管理成員名單

管理訪問權限包括添加和移除成員、更換項目負責人，以及把項目改回整個工作區可見。以下人可以操作：

- 在名單里的 `owner` 和 `admin`。
- 項目認定的一位訪問管理者，在**訪問權限**對話框中標為**管理訪問權限**：負責人是名單里的人時就是負責人；否則是建立者（如果在名單里）；再否則是在名單里時間最長的成員。

私有項目的負責人和其他項目一樣，可以是成員、Agent，也可以留空。訪問管理者不單獨保存，每次都根據負責人、建立者和名單計算，所以負責人變化或有人離開時會隨之改變。把某個人設為負責人會把他加入名單；要把當前負責人移出名單，先更換負責人。其他成員可以查看名單，但不能修改。Agent不能修改任何項目的訪問權限。

### 建立私有項目，或把項目改為私有

- **新建項目**：在建立對話框中打開**訪問權限**，選擇**僅項目成員**並添加成員。你始終在名單里，被設為負責人的人也是。
- **已有項目**：在項目屬性中點選**訪問權限**，選擇**僅項目成員**。把整個工作區可見的項目改為私有需要 `owner` 或 `admin`；操作者會被加入名單，負責人是人時也一起加入。
- **CLI**：給 `project create` 或 `project update` 加上 `--visibility private`，用 `--member`（名稱、郵箱或使用者 ID，可重復）指定初始名單。之後用 `project member list|add|remove` 管理名單。

```bash
multica project create --title "Pricing revamp" --visibility private --member alice@example.com --member Bob
multica project update <project-id> --visibility private --member alice@example.com
multica project member add <project-id> carol@example.com
```

把私有項目改回**整個工作區**後，`owner`、`admin` 和 `member`都能看到這個項目及其中的任務、評論和附件。訪客仍需獲邀訪問該項目。在界面中保存前會要求確認；`multica project update --visibility workspace` 則直接生效。

### 工作區所有者恢復訪問 [#workspace-owner-recovery]

私有項目的名單里可能沒有 `owner` 或 `admin`，甚至一個成員都不剩。工作區 `owner` 可以在**設置 → 常規 → 私有項目**中介入，這一部分只有所有者能看到（`admin` 看不到）。這裡列出每個私有項目的名稱和成員，不顯示其他內容：加入之前，任務、評論和附件都看不到。

點選**加入**並確認，即可把自己加入成員名單。你會像其他成員一樣出現在名單中，現有成員會收到收件匣通知；作為在名單里的所有者，你可以管理項目的訪問權限。加入不會改變負責人。成員全部離開的項目也這樣恢復：先加入，再在項目頁面管理或刪除它。

## 文件夾 [#folders]

文件夾把相關的項目放在一起，比如同一次發佈或同一個團隊的項目，讓側邊欄的項目分區保持簡潔。`owner`、`admin` 和 `member` 共享同一組文件夾，都可以新建、重命名、刪除文件夾，以及把項目移進移出。一個項目最多屬於一個文件夾，文件夾不能嵌套。文件夾只用於整理，不改變誰能看到項目。

- **新建文件夾**：點選側邊欄項目分區的 **+**，選擇**新建文件夾**；或在項目菜單中選擇**移動到文件夾 → 新建文件夾…**，新建的同時把該項目放進去。
- **移動項目**：在項目菜單中選擇**移動到文件夾**，或在側邊欄把項目拖到文件夾上、拖出文件夾。新建項目時可以在建立對話框中選擇文件夾；文件夾行上的 **+** 會直接在該文件夾中新建項目。
- **重命名或刪除文件夾**：在側邊欄右鍵點選文件夾。刪除文件夾後，其中的項目回到頂層，其他內容不受影響。

側邊欄中哪些文件夾展開、文件夾和項目的排列順序，都是個人設置，不影響其他成員。項目分區的篩選同樣作用於文件夾內部：項目全部被篩掉的文件夾會隱藏，而空文件夾會保留，方便往里放項目。在**全部項目**中按**文件夾**分組，可以按文件夾查看項目；在看板中把項目拖到另一列，會把它移到對應的文件夾。

## 固定到側邊欄

釘選專案後，它會出現在你的側邊欄。釘選是個人偏好，不會影響其他成員。

項目分區的設置中，**僅顯示預設圖標**會把該分區的自定義項目圖標顯示為預設項目圖標。預設關閉，不會修改項目本身的圖標。

## 歸檔和恢復

在項目菜單中選擇**歸檔項目**，或在項目列表中選擇**歸檔**。能編輯項目的人也能歸檔或恢復它。歸檔後，項目會從常規項目列表和選擇器中隱藏，不能再向其中新建或移入任務。已有任務、歷史記錄和設置都保留，已有任務仍可查看和編輯，項目狀態也不會改變。

向該項目建立任務的已啓用自動化會被暫停。恢復時，在項目列表的標題菜單中切換到**已歸檔的項目**，選擇**恢復**，也可在項目頁面選擇**恢復項目**。恢復項目不會重新啓用這些自動化，需要時再單獨啓用。

## 建立、編輯和刪除

`owner`、`admin` 和 `member` 都可以建立和編輯專案。成員可以刪除自己或自己目前擁有的Agent建立的專案；Agent只能刪除自己建立的專案。人類 `owner` 和 `admin` 可以刪除任何專案，包括建立者未知的舊專案。私有專案只有成員名單里的人能編輯或刪除，所以 `owner` 或 `admin` 需要先在名單里。

<Callout type="warning">
刪除專案不會刪除其中的任務：任務會解除關聯並繼續留在工作區。專案描述、狀態和資源則會永久刪除。
</Callout>
