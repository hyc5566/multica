Multica 使用你透過 Telegram 官方 [@BotFather](https://t.me/BotFather) 建立的 Bot。一個 Bot 對應一個 Multica Agent；需要多個獨立 Bot 身分時，為每個 Agent 分別建立。

Telegram 整合[由社群維護](/community-maintained)：每個版本都會隨包發布，但不附帶官方支援 SLA。遇到問題請提到 [GitHub 問題回報](https://github.com/multica-ai/multica/issues)。

## 開始前

- 連線操作需要工作區 owner 或 admin 權限。
- API 伺服器必須能夠存取 `https://api.telegram.org`。
- 你需要 @BotFather 簽發的 Bot token；它等同於密碼。

## 1. 建立 Bot

1. 開啟 [@BotFather](https://t.me/BotFather)，傳送 `/newbot`。
2. 設定顯示名稱和一個以 `bot` 結尾的使用者名稱。
3. 複製 HTTP API token。
4. 預設保持 **Group Privacy** 開啟，這是可見範圍最小的設定：Telegram 只會把命令、明確的 @ 和對 Bot 訊息的回覆投遞給 Bot。關閉它是可選項，能讓 Bot 把群組裡周圍的討論作為上下文，代價是 Bot 會收到群裡的每一則訊息，詳見[群組聊天與 forum topic](#群組聊天與-forum-topic)。

<Callout type="warning">
不要把 token 發到任務、聊天、日誌或程式碼儲存庫。若已洩露，請在 @BotFather 中撤銷，再用替換後的 token 重新連線。
</Callout>

## 2. 連線到 Agent

1. 在 Multica 開啟 **Agent**，選擇目標 Agent 並進入 **整合**。
2. 點選 **連線 Telegram**。
3. 貼上 Bot token，然後點選 **連線**。

Multica 會即時請求 Telegram 驗證 Bot，檢查是否存在與長輪詢衝突的 webhook，加密儲存 token，並啟動一條受監督的 `getUpdates` 連線。一個 Bot 若已連線到其他 Agent 或工作區，必須先在原處中斷連線。

## 首次使用與帳號綁定

成員第一次向 Bot 發訊息時，會收到一次性 Multica 帳號綁定連結。開啟連結，登入同一工作區的 Multica 帳號，再回到 Telegram 重新傳送訊息。連結 15 分鐘後過期；再私訊 Bot 即可取得新連結。

在群組裡，Bot 不會公開傳送帶憑證性質的綁定連結，只會讓傳送者先私訊 Bot。

只有目前工作區成員能使用 Bot；每則訊息都會重新驗證成員身分。

## 使用 Bot

### 私訊

直接開啟 Bot 傳送文字，不需要 @。

### 群組聊天與 forum topic

把 Bot 加入群後，@它，或直接回覆它發過的訊息。被接受的訊息會保留在持續的 Multica 對話中。未明確發給 Bot 的群訊息本身不會開啟對話，也不會單獨形成一輪，但會被暫存在一個很小的記憶體緩衝區裡：每個群（或每個 forum topic）保留 Bot 收到的最近 10 則訊息，伺服器重新啟動即清空。之後當成員透過 @ 或回覆 Bot 的訊息下達指令時，這些暫存訊息會作為唯讀上下文附在該輪指令之前，並隨這一輪一起儲存進對話記錄。緩衝裡的圖片或檔案在上下文中只顯示為 `[Image]` 之類的標記和 caption，檔案本身不會被取得。`/new` 開啟的新對話不帶這段上下文。緩衝裡有什麼取決於 Telegram 投遞了什麼：Group Privacy 開啟時只有命令、明確的 @ 和對 Bot 的回覆，所以上下文裡只有之前明確發給它的訊息。想讓它看到普通群組聊天，請在 @BotFather 裡關閉 Group Privacy，再把 Bot 移出群重新加入，此後 Bot 會收到群裡的每一則訊息。被設為群管理員的 Bot 無論隱私設定如何都會收到全部訊息，因此不改 @BotFather 也會把普通群組聊天納入上下文。回覆其他成員的訊息時必須同時 @ Bot，只有這種情況下，被引用訊息的傳送者及文字（或 caption）才會隨新指令進入上下文；發給 Bot 的回覆所引用的訊息若帶圖片或檔案，該檔案也會一並附上，無論傳送者是誰；只回覆成員而不 @ Bot 不會觸發。普通群組聊天各自延續一段 Multica 對話；forum 的每個 topic 分別隔離。

### 命令

- `/new` 建立一個新的空 Multica Chat，並把該 Telegram 對話的後續訊息路由到新 Chat；`/new <訊息>` 會把訊息作為新 Chat 的第一輪。回覆其他成員並明確 @ Bot 時，選取的引用內容仍會附在第一輪中。
- `/clear` 保留目前 Multica Chat，把新的 Agent 可見上下文應用到下一條非空訊息；`/clear <訊息>` 會把訊息作為上下文邊界後的第一輪，明確選擇的回覆引用仍會保留。
- `/issue <標題>` 建立 Multica 任務，後續行作為可選描述；不帶標題時返回用法提示。
- 群組聊天支援 `/issue@your_bot` 這種 Telegram 命令後綴。

### 回覆與內容範圍

Bot 透過傳送並編輯 Telegram 訊息，以串流方式顯示文字回覆，引用觸發訊息、保留 forum topic，並按 Telegram 長度限制自動分段。最終回覆在程序內非同步投遞。正常情況下，某個聊天的退避等待不會佔用 worker；快取達到容量上限並壓縮退避狀態時，同一 Bot installation 下的其他聊天可能被保守延遲。最終狀態佇列有固定容量，超出容量的最終回覆會遭拒並記錄錯誤；佇列不會跨服務重新啟動恢復。

圖片、檔案、影片、語音和音訊訊息會作為同一對話的附件交給 Agent，caption 作為訊息內文。回覆一則帶有這類內容的訊息（私訊，或在群組裡向 Bot 發出指令時，無論傳送者是誰）會把該訊息作為引用附在你的指令前，並把它的檔案一並交給 Agent，這樣你可以指定之前的某張圖片或某段影片。Telegram 只允許 Bot 下載 20 MB 以內的檔案；檔案無法取得時（太大或下載失敗），Bot 會告訴你，Agent 只會看到一個預留標記。Agent 產生的檔案會在回覆之後作為單獨的訊息發回聊天：10 MB 以內的圖片直接顯示在對話中，其餘 50 MB 以內的檔案以檔案形式到達；無法確認送達時 Bot 會說明，檔案仍保留在 Multica 的回覆附件裡。這兩個方向都需要伺服器端設定物件儲存（見下文自行託管部分）；未設定時，Bot 對媒體訊息回覆不支援提示，Agent 也會被告知無法傳送檔案。貼紙、位置、投票等非檔案訊息在私訊中以及群組裡明確 @ Bot 時會收到同樣的提示，群組裡未 @ 的此類訊息保持靜默。

## 管理與中斷連線

在 **設定 → 訊息頻道 → Telegram** 查看所有已連線 Bot。owner 和 admin 可以中斷連線。中斷連線會停止長輪詢和後續回覆，但保留 Multica 對話與稽核記錄。

## 自行託管設定

啟動 API 伺服器前設定一個長期穩定的 32 位元組加密金鑰：

```dotenv
MULTICA_TELEGRAM_SECRET_KEY=<base64 編碼的 32 位元組金鑰>
```

可用 `openssl rand -base64 32` 產生。丟失或輪換此金鑰後，已有 Bot token 無法解密，需要逐個重新連線。

綁定連結使用 `MULTICA_APP_URL`，未設定時回退到 `FRONTEND_ORIGIN`；產生的位址必須能被成員存取。伺服器網路或代理還必須允許 HTTPS 存取 `api.telegram.org`；Go 會讀取標準的 `HTTPS_PROXY` 和 `NO_PROXY` 環境變數。

## 故障排查

- **無法驗證 Bot**：先檢查伺服器網路和代理。只有 Telegram 明確拒絕 token 時才需要重新產生。
- **webhook 衝突**：連線前移除這個 Bot 已有的 webhook；Telegram 不允許 webhook 與 `getUpdates` 同時使用。
- **409 輪詢衝突**：另一個 Multica 實例或程序正在輪詢同一個 Bot。停止另一個消費者，或為不同環境使用不同 Bot。
- **群組裡不回覆**：確認 Bot 已入群，並且訊息 @ 了它或回覆了它的訊息。
- **綁定連結過期**：重新私訊 Bot，並使用最新連結。
- **Bot 不執行**：檢查 Agent 是否已封存，以及它使用的[執行環境](/daemon-runtimes)是否在線。
