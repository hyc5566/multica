Multica 使用你通過 Telegram 官方 [@BotFather](https://t.me/BotFather) 建立的 Bot。一個 Bot 對應一個 Multica Agent；需要多個獨立 Bot 身份時，為每個 Agent 分別建立。

Telegram 整合[由社區維護](/community-maintained)：每個版本都會隨包發佈，但不附帶官方支援 SLA。遇到問題請提到 [GitHub 任務](https://github.com/multica-ai/multica/issues)。

## 開始前

- 連接操作需要工作區 owner 或 admin 權限。
- API 伺服器必須能夠訪問 `https://api.telegram.org`。
- 你需要 @BotFather 簽發的 Bot token；它等同於密碼。

## 1. 建立 Bot

1. 開啟 [@BotFather](https://t.me/BotFather)，傳送 `/newbot`。
2. 設定顯示名稱和一個以 `bot` 結尾的使用者名。
3. 複製 HTTP API token。
4. 預設保持 **Group Privacy** 開啟，這是可見範圍最小的設定：Telegram 只會把命令、明確的 @ 和對 Bot 消息的回覆投遞給 Bot。關閉它是可選項，能讓 Bot 把群裡周圍的討論作為上下文，代價是 Bot 會收到群裡的每一條消息，詳見[群聊與 forum topic](#群聊與-forum-topic)。

<Callout type="warning">
不要把 token 發到任務、聊天、日誌或程式碼倉庫。若已洩露，請在 @BotFather 中撤銷，再用替換後的 token 重新連接。
</Callout>

## 2. 連接到 Agent

1. 在 Multica 開啟 **Agent**，選擇目標 Agent 並進入 **整合**。
2. 點擊 **連接 Telegram**。
3. 粘貼 Bot token，然後點擊 **連接**。

Multica 會實時請求 Telegram 驗證 Bot，檢查是否存在與長輪詢衝突的 webhook，加密儲存 token，並啟動一條受監督的 `getUpdates` 連接。一個 Bot 若已連接到其他 Agent 或工作區，必須先在原處斷開。

## 首次使用與帳戶綁定

成員第一次向 Bot 發消息時，會收到一次性 Multica 帳戶綁定連結。開啟連結，登入同一工作區的 Multica 帳戶，再回到 Telegram 重新傳送消息。連結 15 分鐘後過期；再私聊 Bot 即可獲取新連結。

在群裡，Bot 不會公開傳送帶憑據性質的綁定連結，只會讓傳送者先私聊 Bot。

只有當前工作區成員能使用 Bot；每條消息都會重新校驗成員身份。

## 使用 Bot

### 私聊

直接開啟 Bot 傳送文字，不需要 @。

### 群聊與 forum topic

把 Bot 加入群后，@它，或直接回覆它發過的消息。被接受的消息會保留在持續的 Multica 對話中。未明確發給 Bot 的群消息本身不會開啟對話，也不會單獨形成一輪，但會被暫存在一個很小的內存緩衝裡：每個群（或每個 forum topic）保留 Bot 收到的最近 10 條，伺服器重啟即清空。之後當有成員通過 @ 或回覆 Bot 的消息向它發出指令時，這些暫存消息會作為只讀上下文附在該輪指令之前，並隨這一輪一起儲存進對話記錄。緩衝裡的圖片或檔案在上下文中只顯示為 `[Image]` 之類的標記和 caption，檔案本身不會被獲取。`/new` 開啟的新對話不帶這段上下文。緩衝裡有什麼取決於 Telegram 投遞了什麼：Group Privacy 開啟時只有命令、明確的 @ 和對 Bot 的回覆，所以上下文裡只有之前明確發給它的消息。想讓它看到普通群聊，請在 @BotFather 裡關閉 Group Privacy，再把 Bot 移出群重新加入，此後 Bot 會收到群裡的每一條消息。被設為群管理員的 Bot 無論隱私設定如何都會收到全部消息，因此不改 @BotFather 也會把普通群聊納入上下文。回覆其他成員的消息時必須同時 @ Bot，只有這種情況下，被引用消息的傳送者及文字（或 caption）才會隨新指令進入上下文；發給 Bot 的回覆所引用的消息若帶圖片或檔案，該檔案也會一併附上，無論傳送者是誰；只回覆成員而不 @ Bot 不會觸發。普通群聊各自延續一段 Multica 對話；forum 的每個 topic 分別隔離。

### 命令

- `/new` 建立一個新的空 Multica Chat，並把該 Telegram 對話的後續消息路由到新 Chat；`/new <消息>` 會把消息作為新 Chat 的第一輪。回覆其他成員並明確 @ Bot 時，被選中的引用內容仍會附在第一輪中。
- `/clear` 保留當前 Multica Chat，把新的 Agent 可見上下文應用到下一條非空消息；`/clear <消息>` 會把消息作為上下文邊界後的第一輪，明確選擇的回覆引用仍會保留。
- `/issue <標題>` 建立 Multica 任務，後續行作為可選描述；不帶標題時返回用法提示。
- 群聊支援 `/issue@your_bot` 這種 Telegram 命令後綴。

### 回覆與內容範圍

Bot 通過傳送並編輯 Telegram 消息來流式展示文字回覆，引用觸發消息、保留 forum topic，並按 Telegram 長度限制自動分段。最終回覆在程序內異步投遞。正常情況下，某個聊天的退避等待不會佔用 worker；緩存達到容量上限並壓縮退避狀態時，同一 Bot installation 下的其他聊天可能被保守延遲。終態隊列有固定容量，超限執行會被明確拒絕並記錄錯誤；隊列不會跨服務重啟恢復。

圖片、檔案、視頻、語音和音頻消息會作為同一對話的附件交給 Agent，caption 作為消息正文。回覆一條帶有這類內容的消息（私聊，或在群裡向 Bot 發出指令時，無論傳送者是誰）會把該消息作為引用附在你的指令前，並把它的檔案一併交給 Agent，這樣你可以指定之前的某張圖片或某段視頻。Telegram 只允許 Bot 下載 20 MB 以內的檔案；檔案無法取得時（太大或下載失敗），Bot 會告訴你，Agent 只會看到一個佔位符。Agent 產生的檔案會在回覆之後作為單獨的消息發回聊天：10 MB 以內的圖片內聯顯示，其餘 50 MB 以內的檔案以檔案形式到達；無法確認送達時 Bot 會說明，檔案仍保留在 Multica 的回覆附件裡。這兩個方向都需要服務端設定對象儲存（見下文自託管部分）；未設定時，Bot 對媒體消息回覆不支援提示，Agent 也會被告知無法傳送檔案。貼紙、位置、投票等非檔案消息在私聊中以及群裡明確 @ Bot 時會收到同樣的提示，群裡未 @ 的此類消息保持靜默。

## 管理與斷開

在 **設定 → 消息渠道 → Telegram** 查看所有已連接 Bot。owner 和 admin 可以斷開。斷開會停止長輪詢和後續回覆，但保留 Multica 對話與審計記錄。

## 自託管設定

啟動 API 伺服器前設定一個長期穩定的 32 字節加密密鑰：

```dotenv
MULTICA_TELEGRAM_SECRET_KEY=<base64 編碼的 32 字節密鑰>
```

可用 `openssl rand -base64 32` 生成。丟失或輪換此密鑰後，已有 Bot token 無法解密，需要逐個重新連接。

綁定連結使用 `MULTICA_APP_URL`，未設定時回退到 `FRONTEND_ORIGIN`；生成的地址必須能被成員訪問。伺服器網路或代理還必須允許 HTTPS 訪問 `api.telegram.org`；Go 會讀取標準的 `HTTPS_PROXY` 和 `NO_PROXY` 環境變數。

## 故障排查

- **無法驗證 Bot**：先檢查伺服器網路和代理。只有 Telegram 明確拒絕 token 時才需要重新生成。
- **webhook 衝突**：連接前移除這個 Bot 已有的 webhook；Telegram 不允許 webhook 與 `getUpdates` 同時使用。
- **409 輪詢衝突**：另一個 Multica 實例或程序正在輪詢同一個 Bot。停止另一個消費者，或為不同環境使用不同 Bot。
- **群裡不回覆**：確認 Bot 已入群，並且消息 @ 了它或回覆了它的消息。
- **綁定連結過期**：重新私聊 Bot，並使用最新連結。
- **Bot 不執行**：檢查 Agent 是否已歸檔，以及它使用的[執行環境](/daemon-runtimes)是否在線。
