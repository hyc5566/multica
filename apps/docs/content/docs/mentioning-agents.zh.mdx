在留言中 @提及 Agent，適合請它查看新資訊、回答問題或協助目前的負責人。這則留言會成為本次執行的起點，任務負責人和狀態都不會改變。

## 分配與 @提及的選擇

| | 指派給 Agent | 在留言中 @提及 Agent |
|---|---|---|
| 適合 | 讓 Agent 負責整項任務 | 請 Agent 處理目前這則留言 |
| 改變負責人 | 是 | 否 |
| 改變狀態 | 否 | 否 |
| 每次可指定 | 一個 Agent 或小隊 | 多個 Agent 或小隊 |
| 執行範圍 | 整項任務 | 觸發留言，以及同批合併的留言 |

需要明確的負責人時，請使用[指派](/assigning-issues)；只需讓 Agent 暫時加入討論時，請使用 @提及。

## 觸發預覽

在留言編輯器中選擇 Agent 或小隊後，輸入框下方會顯示觸發預覽：

- 送出後會開始工作的 Agent；
- 目標是由直接 @提及、任務負責人或小隊 leader 指定；
- 目標是否無法使用，或你是否沒有執行權限。

取消勾選某個 Agent 只會略過這次觸發，不必刪除留言中的名稱，也不會變更 Agent 的 Access。

留言送出後，線上的執行環境通常會立即領取執行；若執行環境離線，執行會留在佇列中等待。

## 回覆的自動分派

一般留言（完全不含 @）會依討論脈絡分派：

1. 回覆 Agent 的留言時，交由該 Agent 處理。
2. 在已有 Agent 參與的討論串中回覆時，沿用該討論串的 Agent。
3. 若以上情況都不符合，最上層留言會交給任務目前的 Agent 負責人；若負責人是小隊，則由 leader 處理。直接回覆成員的一般留言不會改派給任務負責人；要讓 Agent 或小隊加入，請明確 @提及。

留言明確 @提及其他對象（包括成員）時，就不會再分派給任務負責人。

回覆會持續交由目標 Agent 處理，即使它的執行環境離線或忙碌，也不會在逾時後自動喚醒任務負責人。若要請其他 Agent 參與，請明確 @提及。

## 給正在執行的Agent插話

Agent做到一半、方向不對時，不必停下來重來。在留言框裡寫下修正併傳送，這條訊息會插進它當前的執行：它在當前步驟結束後讀到，按新方向繼續完成原任務。

<SteerDemo />

收件人正在runtime，留言框下方的標籤會說明這條訊息怎麼送達，點開可以改：

| 選項 | 效果 |
|---|---|
| 插話到當前執行 | 在當前步驟結束後讀到，並繼續完成原任務。 |
| 本輪結束後開始 | 不打斷當前執行，結束後作為新一輪處理。 |
| 停止並重新開始 | 立即停止當前執行，按這條訊息從頭開始。 |
| 本次不會開始 | 只發布留言，不觸發這個Agent。 |

傳送後，留言下方會先顯示"等待 ... 讀取"，讀到後變為"... 已讀取"；執行日誌的步驟列表裡也會標出它是在哪一步讀到的。送達失敗時，可以重試，或者改為作為新一輪傳送。

- 插話只支援文字。帶附件的訊息會在本輪結束後處理。
- 插話需要Agent使用的 AI 開發工具支援；不支援時，選項裡不會出現"插話到當前執行"。
- 預設選項在設定的**回覆正在執行的Agent時**中調整，每條訊息傳送前仍可單獨修改。
- 聊天裡排隊訊息的**引導**不一樣：它會先停掉當前回覆，見[聊天](/chat#回覆還沒結束時繼續發訊息)。

## 連續留言的合併

同一個Agent在同一條任務上已有排隊中的執行，此時新留言會合並進這次執行，開始時一併處理；它已經在runtime，按你在留言框中選擇的方式處理，見上一節。可以連續補充資訊，不必等Agent回覆。

一則留言 @提及多個不同 Agent 時，每個 Agent 都會各自執行一次；多次提及同一個 Agent 時，只會建立一次執行。

## 不觸發 Agent 的留言

有兩種方式：

- 以 `/note` 開頭：留言會作為成員間的筆記送出，不會觸發 Agent。
- 使用 `@all`：通知所有工作區成員，並停用這則留言對任務負責人的自動觸發。

如果觸發預覽仍列出 Agent，請在送出前取消勾選。

<Callout type="info">
`@all` 不會包含 Agent。Agent 沒有收件匣；若要交辦工作，請明確 @提及、回覆相關討論，或將任務指派給它。
</Callout>

## Access 限制

@提及無法繞過 Agent 的 Access。若你沒有執行權限、目標已封存，或沒有可用的執行環境，觸發預覽會說明該 Agent 不會開始執行；留言仍會正常送出。Access 的三種範圍請參閱[Agent](/agents#權限與-access)。

## Agent 之間的互相提及

Agent可以在自己的回覆中 @其他Agent。A @ B、B 又 @ A 時，系統會合並同一時刻的重複執行，但不會判斷這段協作該不該結束。什麼時候停，要寫進Agent指令。
