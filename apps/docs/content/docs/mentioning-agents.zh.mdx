title: 在评论中 @Agent
description: 在任务的评论中 @Agent 或继续回复，让它处理新的信息而不改变负责人。
---

import { Callout } from "fumadocs-ui/components/callout";

在评论中 @Agent，适合让它查看一条新信息、回答问题或协助当前负责人。评论会成为这次执行的起点，任务的负责人和状态都不会改变。

## 分配与 @提及的选择

| | 分配给 Agent | 在评论中 @Agent |
|---|---|---|
| 适合 | 让 Agent 负责整条任务 | 请 Agent 处理当前评论 |
| 改变负责人 | 是 | 否 |
| 改变状态 | 否 | 否 |
| 一次选择 | 一个 Agent 或小队 | 可以 @多个 Agent 或小队 |
| 本轮焦点 | 整条任务 | 触发它的评论，以及同批合并的评论 |

需要明确负责人时使用[分配](/assigning-issues)；只需要临时加入讨论时使用 @提及。

## 触发预览

在评论编辑器中选择 Agent 或小队后，输入框下方会显示触发预览：

- 哪些 Agent 会在发送后开始工作；
- 目标来自直接 @提及、任务负责人还是小队 leader；
- 目标是否不可用，或你是否缺少调用权限。

取消选中某个 Agent 只跳过这一次触发，不需要删除评论中的名字，也不会修改 Agent 的 Access。

![发送前的触发预览：列出发送后将开始工作的 Agent](/images/docs/mention-trigger-preview.webp)

评论发布后，在线的运行时通常立即领取；运行时离线时，运行留在队列中等待。

## 回复的自动路由

普通评论（不含任何 @）按讨论上下文路由：

1. 回复 Agent 的评论时，交给该 Agent。
2. 在已有 Agent 参与的讨论中回复时，沿用这条讨论的 Agent。
3. 都不满足的最外层评论，交给当前的 Agent 负责人；负责人是小队时，由 leader 处理。直接回复成员的普通评论不会走负责人兜底；需要 Agent 或小队加入时，请明确 @提及。

评论明确 @了其他对象（包括成员）时，不再使用负责人兜底。

回复始终交给目标Agent，即使它的运行时离线或正在忙碌，也不会超时后自动唤醒任务负责人。需要其他Agent参与时，请明确 @提及。

## 连续评论的合并

同一个 Agent 在同一条任务上已有排队中的运行，此时新评论会合并进这次运行；它已经在执行时，后续评论等当前运行结束后合并为一次跟进执行。可以连续补充信息，不必等 Agent 回复。

一条评论 @多个不同 Agent 时，每个 Agent 各得一次运行；多个提及指向同一个 Agent 时，只保留一次。

## 不触发 Agent 的留言

两种方式：

- 以 `/note` 开头：评论作为成员之间的备注，不触发任何 Agent。
- 使用 `@all`：通知全部工作区成员，同时关闭这条评论对负责人的自动触发。

触发预览中仍有 Agent 时，发送前取消选中即可。

<Callout type="info">
`@all` 不包含 Agent。Agent 没有收件箱；让它工作需要明确 @它、回复相关讨论，或把任务分配给它。
</Callout>

## Access 限制

@提及不能绕过 Agent 的 Access。无权调用、目标已归档或没有可用运行时时，触发预览会说明它不会启动；评论本身仍可正常发布。三档语义见[Agent](/agents#权限与-access)。

## Agent 之间的互相提及

Agent 可以在自己的回复中 @其他 Agent。A @ B、B 又 @ A 时，系统会合并同一时刻的重复执行，但不会判断这段协作是否应该结束——协作的终止条件需要写进 Agent 指令。
