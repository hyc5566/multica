title: 在留言中 @Agent
description: 在任務的留言中 @Agent 或繼續回覆，讓它處理新的資訊而不改變負責人。
---

在留言中 @Agent，適合讓它查看一條新資訊、回答問題或協助當前負責人。留言會成為這次執行的起點，任務的負責人和狀態都不會改變。

## 分配與 @提及的選擇

| | 分配給 Agent | 在留言中 @Agent |
|---|---|---|
| 適合 | 讓 Agent 負責整條任務 | 請 Agent 處理當前留言 |
| 改變負責人 | 是 | 否 |
| 改變狀態 | 否 | 否 |
| 一次選擇 | 一個 Agent 或小隊 | 可以 @多個 Agent 或小隊 |
| 本輪焦點 | 整條任務 | 觸發它的留言，以及同批合併的留言 |

需要明確負責人時使用[分配](/assigning-issues)；只需要臨時加入討論時使用 @提及。

## 觸發預覽

在留言編輯器中選擇 Agent 或小隊後，輸入框下方會顯示觸發預覽：

- 哪些 Agent 會在傳送後開始工作；
- 目標來自直接 @提及、任務負責人還是小隊 leader；
- 目標是否不可用，或你是否缺少調用權限。

取消選中某個 Agent 只跳過這一次觸發，不需要刪除留言中的名字，也不會修改 Agent 的 Access。

![傳送前的觸發預覽：列出傳送後將開始工作的 Agent](/images/docs/mention-trigger-preview.webp)

留言發佈後，在線的執行環境通常立即領取；執行環境離線時，執行留在隊列中等待。

## 回覆的自動路由

普通留言（不含任何 @）按討論上下文路由：

1. 回覆 Agent 的留言時，交給該 Agent。
2. 在已有 Agent 參與的討論中回覆時，沿用這條討論的 Agent。
3. 都不滿足的最外層留言，交給當前的 Agent 負責人；負責人是小隊時，由 leader 處理。直接回覆成員的普通留言不會走負責人兜底；需要 Agent 或小隊加入時，請明確 @提及。

留言明確 @了其他對象（包括成員）時，不再使用負責人兜底。

回覆始終交給目標 Agent，即使它的執行環境離線或正在忙碌，也不會超時後自動喚醒任務負責人。需要其他 Agent 參與時，請明確 @提及。

## 連續留言的合併

同一個 Agent 在同一條任務上已有排隊中的執行，此時新留言會合並進這次執行；它已經在執行時，後續留言等當前執行結束後合併為一次跟進執行。可以連續補充資訊，不必等 Agent 回覆。

一條留言 @多個不同 Agent 時，每個 Agent 各得一次執行；多個提及指向同一個 Agent 時，只保留一次。

## 不觸發 Agent 的留言

兩種方式：

- 以 `/note` 開頭：留言作為成員之間的備註，不觸發任何 Agent。
- 使用 `@all`：通知全部工作區成員，同時關閉這條留言對負責人的自動觸發。

觸發預覽中仍有 Agent 時，傳送前取消選中即可。

<Callout type="info">
`@all` 不包含 Agent。Agent 沒有收件箱；讓它工作需要明確 @它、回複相關討論，或把任務分配給它。
</Callout>

## Access 限制

@提及不能繞過 Agent 的 Access。無權調用、目標已歸檔或沒有可用執行環境時，觸發預覽會說明它不會啟動；留言本身仍可正常發佈。三檔語義見[Agent](/agents#權限與-access)。

## Agent 之間的互相提及

Agent 可以在自己的回覆中 @其他 Agent。A @ B、B 又 @ A 時，系統會合並同一時刻的重複執行，但不會判斷這段協作是否應該結束——協作的終止條件需要寫進 Agent 指令。
