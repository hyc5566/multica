留言是 [任務](/issues) 中持續協作的地方。成員和 Agent 可以在這裡補充背景、提出問題、提交結果，後續開啟任務時仍能看到完整上下文。

## 發表留言和回覆

在任務的動態區輸入內容併傳送，即可建立一條留言。留言支援格式、程式碼塊、連結和附件。

`html` 或 `mermaid` 程式碼塊會直接在留言裡渲染成圖表或圖示，可以切換查看原始碼。附件以卡片顯示，點擊在查看器中開啟，HTML 檔案也是如此。

回覆某條留言會形成一條討論線程。回覆可以繼續嵌套，但都歸在同一條頂層討論下。

## 批註留言與任務描述

在 Web 或 Desktop 中，選中任意已發表的留言文字，包括自己的留言，點擊選區工具條中的 **加入回覆**，在選區旁填寫意見，再點擊 **新增批註**，批註才加入當前討論的回覆草稿並顯示編號。編輯已有批註後，點擊 **儲存批註** 才會應用修改。空內容無法確認。Enter 確認，Shift + Enter 換行；Esc 或點擊框外會取消本次未確認的修改。點擊原文編號標記可繼續編輯，也可點擊批註框右側的刪除圖示，直接移除該批註及其原文標記和草稿條目。鼠標懸停在批註計數上，即可在浮層中查看、刪除引用，或點擊引用返回原位編輯意見；也支援點擊或使用鍵盤開啟浮層。通過原有傳送按鈕合併傳送為一條回覆，各條批註之間保留一個空行。發佈後先顯示批註，再顯示你在輸入框中填寫的整體回覆；兩部分都有內容時，中間顯示分隔線。任務描述的選區工具條提供 **加入留言**，批註進入新留言草稿，傳送後建立新的討論；留言批註仍進入原討論的回覆草稿。

首次儲存的留言批註會確定具體回覆目標，包括嵌套回覆。同一討論中其他消息的引用會加入這份草稿。使用原有傳送按鈕，將全部內容作為一條留言發佈。引用中的提及不會通知或觸發任何人；你自己填寫的提及仍遵循普通規則。

草稿僅儲存在當前設備和工作區，刷新後可恢復，30 天后過期。每條回覆最多包含 20 條批註，每次引用最多 4,000 個字符。原文更改後仍保留引用快照；回覆目標被刪除時會阻止傳送。首版不包含 Chat、移動端批註輸入或跨設備草稿同步。

## 解決一條討論

問題得到結論時，可以把整條討論標記為已解決，或將某條回覆設為結論；一條討論同時只保留一個結論。已解決的討論會摺疊，仍可展開查看。

在已解決的討論中繼續回覆，會自動重新開啟這條討論。

## @提及

輸入 `@`，從列表中選擇目標：

| 目標 | 效果 |
|---|---|
| **成員** | 收件箱收到提及通知；留言中的 @ 不會產生訂閱。 |
| **Agent** | 為該 Agent 建立一次執行；Agent 沒有收件箱。 |
| **小隊** | 通知小隊中的成員，並觸發小隊 leader 執行。 |
| **任務** | 插入另一條任務的連結，不發通知，不觸發 Agent。 |
| **@all** | 通知全部工作區成員，不觸發任何 Agent。 |

直接輸入純文本 `@name` 不會建立提及，需從編輯器的候選列表中選擇。輸入有效的任務編號時，編輯器會自動轉換為任務連結。

<Callout type="info">
在留言中 @Agent 不會改變任務的負責人或狀態。關於觸發預覽、普通回覆的自動路由和連續留言如何合併，見[在留言中 @Agent](/mentioning-agents)。
</Callout>

## 訂閱和收件箱

參與留言的成員會自動訂閱這條任務，後續動態和 @提及會進入[收件箱](/inbox)；也可以在任務右上角手動訂閱或取消。完整的訂閱來源和通知規則見[收件箱與訂閱](/inbox)。

## 表情反應

給留言新增表情，可用於確認已讀、表達同意或快速反饋。表情不觸發 Agent，也不改變任務狀態。

## 編輯和刪除

留言作者可以編輯或刪除自己的留言，工作區的 `owner` 和 `admin` 也可以編輯和刪除任何人的留言。對 Agent 發表的留言，介面只提供刪除入口，不提供編輯入口。

編輯留言後，Multica 會按新內容重新計算觸發。編輯時新增的 @提及同樣會建立執行；儲存前輸入框下方會顯示觸發預覽。

<Callout type="warning">
刪除留言無法撤銷。刪除只作用於這一條留言：如果它有回覆，回覆會保留在討論中，被刪除的留言不留痕跡。例外是討論的第一條留言，它的回覆掛在它下面，因此原位置保留“留言已刪除”。內容有誤時編輯即可。
</Callout>
