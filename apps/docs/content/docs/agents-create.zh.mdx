建立 Agent 前，需要先有一個可用的[執行環境](/daemon-runtimes)。執行環境決定這名 Agent 使用哪臺電腦和哪款 AI 編程工具；Agent 則儲存它長期使用的身份、指令和能力。

在工作區的 **Agent** 頁面點 **新建 Agent**。

## 選擇起點

建立頁面提供兩種方式：

| 方式 | 適合什麼情況 |
|---|---|
| **從空白開始** | 已經知道 Agent 的職責，想自己填寫每項設定。 |
| **通過 AI 建立** | 先描述目標，讓 Agent Builder 追問關鍵資訊並生成草稿。 |

通過 AI 建立需要一個在線執行環境來完成 Builder 對話。無論選擇哪種方式，建立前都可以檢查並修改最終設定。

![建立 Agent 的起點選擇頁：Start blank 與 Build with AI](/images/docs/quickstart-new-agent.webp)

## 必填項

建立 Agent 只要求兩項：

- **名稱**：在當前工作區中必須唯一。
- **執行環境**：選擇實際執行的環境。

其他欄位可以先使用預設值，建立後再調整。新 Agent 預設只有建立者可以執行。

## 描述與指令

**描述**是寫給團隊看的簡短介紹，只顯示在 Agent 列表和詳情中，不會進入 AI 編程工具的提示。

**指令**會在每次執行時提供給 Agent，通常包含：

- 它負責什麼、不負責什麼；
- 收到工作後先檢查什麼；
- 允許修改哪些內容；
- 結果的提交方式；
- 什麼時候需要向成員確認。

例如：

```text
你負責審查前端 Pull Request。

先閱讀改動和相關測試，只檢查：
- React 與 TypeScript 的正確性
- 可訪問性
- 與現有組件模式是否一致

不要直接修改程式碼。把問題按嚴重程度寫在 issue 留言中；
沒有阻塞問題時，明確說明可以合併。
```

## 新增 skill

建立時可以從工作區選擇一個或多個 [skill](/skills)。

Skill 適合儲存可以跨 Agent 複用的方法和資料；只屬於這名 Agent 的長期要求寫在指令中。

## 對話開場建議

最多新增三條**對話開場建議**，讓使用者在傳送第一條消息前瞭解這個 Agent 擅長什麼。它們出現在別人與該 Agent 開始新對話時，位於輸入框上方。每項包含一個簡短標題和一條完整提示詞。選擇後只會填入輸入框，使用者可以先檢查或修改，不會自動開始執行。

編輯器下方會預覽新對話的實際效果；有編輯權限的人還會在那個空狀態裡看到**自定義開場建議**入口，點擊可直接跳回這裡。

留空時，對話頁會顯示本地化的通用預設值。針對 Agent 職責和邊界編寫的示例通常更有幫助。

CLI 可用 `agent create` / `agent update` 的 `--conversation-starters` 設定（`{"label","prompt"}` 對象的 JSON 數組；更新時傳 `'[]'` 清空）。`agent copy` 仍只搬運源值，沒有覆蓋 flag。

## 選擇執行環境、模型和思考強度

執行環境已經對應一款 AI 編程工具。選擇執行環境後，可以繼續選擇該工具支援的模型和思考強度；部分工具（如 Codex）還可選擇速度檔：

- 留空時，使用執行環境或本地 CLI 的預設設定。
- 設定模型後，該 Agent 之後領取執行環境會使用這個覆蓋值。
- 某些執行環境自行管理模型，因此不會顯示模型選擇。

不同工具支援的模型、會話恢復、skill 和 MCP 能力不同，見[AI 編程工具對照](/providers)。

## 設定 Access

Access 決定哪些成員可以執行這名 Agent（分配、@提及或對話）：

| Access | 含義 |
|---|---|
| **僅自己**（Only me） | 只有你可以執行。預設選項。 |
| **整個工作區**（Entire workspace） | 所有工作區成員都可以執行。 |
| **指定成員**（Specific people） | 只有你和選中的成員可以執行。 |

![Access 設定：僅自己、整個工作區、指定成員三檔](/images/docs/agent-access-settings.webp)

只有 Agent owner 可以修改 Access，工作區管理員也不行。工作區 `owner` 和 `admin` 可以管理其他設定，但不能借管理員身份執行未授權的 Agent。

## 建立後的設定項

開啟 Agent 詳情頁，可以繼續調整：

| 設定 | 作用 |
|---|---|
| **併發上限** | 同一名 Agent 最多同時執行多少次執行，預設是 6；達到上限後繼續排隊。 |
| **環境變數** | 在 AI 編程工具啟動時注入變數。 |
| **自定義參數** | 逐項追加到 AI 編程工具的 CLI 參數中。 |
| **MCP** | 為支援的 AI 編程工具提供 MCP server 設定。 |
| **整合** | 連接這名 Agent 可以使用的外部服務。 |

執行環境所在的守護程序還有一個全局併發上限（預設 20），實際併發取兩者中的較小值。

修改設定不會改變已經開始的執行。後續執行被執行環境領取時，會使用當時儲存的 Agent 設定。

## 環境變數與憑據

環境變數適合放這名 Agent 執行時需要的有限權限憑據，例如只讀 API key 或單一 scope 的 token。

<Callout type="warning">
**`custom_env` 的值在 Multica 伺服器的資料庫裡是明文儲存的**，不屬於"只留在本機"的資料。agent list/get 介面不再返回任何 env 值，只返回鍵的數量；只有工作區 `owner`、`admin` 可以解鎖和修改，並且每次讀取或修改都會留下審計記錄。執行中的 Agent 不能調用管理介面讀取其他 Agent 的變數。
</Callout>

不要使用生產資料庫的管理員密碼或其他高價值長期憑據。

`PATH`、`HOME` 和 `MULTICA_*` 等執行環境關鍵變數不能通過這裡覆蓋。

## 自定義參數和 MCP

自定義參數按數組逐項傳給 AI 編程工具，不經過 shell 展開。參數名稱是否有效由對應工具決定；已有獨立欄位的模型設定不需要在這裡重複設定。

<Callout type="warning">
不要把憑據或其他 secret 放進自定義參數。它們會留在子程序的 argv 中，同機其他程序可能通過 `ps` 或 `/proc` 看到；請改用環境變數（`custom_env`）。守護程序日誌會遮蔽參數值，但無法保護操作系統的程序列表。
</Callout>

MCP 設定可能包含 token，儲存與展示規則和環境變數相同。只有支援託管 MCP 設定的執行環境會顯示這一項；不支援的工具不會因為儲存了設定就自動獲得 MCP 能力。

## 複製 Agent

複製會帶上名稱之外的大部分工作設定，包括指令、對話開場建議、skill、自定義參數、頭像、併發上限和 Access 設定。模型、思考強度和速度檔也會一併帶走；如果原執行環境不可用、複製被迫換到其他執行環境，這三項會清空，需要重新選擇。

環境變數的值和 MCP 設定在任何情況下都不會複製，需要在新 Agent 中重新設定。複製會保留原 Agent 的執行環境綁定和 Access 設定。

## 使用 CLI 建立

```bash
multica agent create \
 --name "Frontend Reviewer" \
 --runtime-id <runtime-id> \
 --description "審查前端 Pull Request" \
 --instructions "先閱讀改動和測試，只在 issue 留言中提交審查結論。" \
 --conversation-starters '[{"label":"審查 PR","prompt":"審查當前最相關的未合併 Pull Request。"}]'
```

命令列參數中的明文會進入 shell 歷史；stdin 和權限受限的檔案不會。

已有設定相近的 Agent 時，可以直接複製：

```bash
multica agent copy <agent-id>
```

預設複製到同一執行環境；加 `--runtime-id` 換到其他執行環境，必須同時指定 `--model`。環境變數、MCP 設定和 `runtime_config` 永不復制；執行環境綁定本身會保留。完整參數見[使用 CLI](/cli)。
