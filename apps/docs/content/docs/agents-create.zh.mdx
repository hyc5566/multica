建立 Agent 前，必須先有可用的[執行環境](/daemon-runtimes)。執行環境決定 Agent 使用哪台電腦和哪款 AI 程式開發工具；Agent 則保存長期使用的身分、指令和能力。

在工作區的 **Agent** 頁面點選 **新增 Agent**。

## 選擇起點

建立頁面提供兩種方式：

| 方式 | 適用情況 |
|---|---|
| **從空白開始** | 已經知道 Agent 的職責，想自行填寫各項設定。 |
| **使用 AI 建立** | 先描述目標，再讓 Agent Builder 詢問關鍵資訊並產生草稿。 |

使用 AI 建立時，需要有執行環境在線，才能進行 Builder 對話。不論選擇哪種方式，建立前都可以檢查並修改最終設定。

![Agent 建立頁的起點選擇：Start blank 與 Build with AI](/images/docs/quickstart-new-agent.webp)

## 必要資訊

建立 Agent 只需要兩項資訊：

- **名稱**：在目前工作區中必須唯一。
- **執行環境**：選擇實際執行工作的環境。

其他欄位可以先使用預設值，建立後再調整。新 Agent 預設只有建立者可以執行。

## 描述與指令

**描述**是提供給團隊的簡介，只會顯示在 Agent 清單和詳細資訊頁，不會放入 AI 程式開發工具的提示中。

**指令**會在每次執行時提供給 Agent，通常包含：

- 它負責什麼、不負責什麼；
- 收到工作後先檢查什麼；
- 允許修改哪些內容；
- 結果的提交方式；
- 什麼時候需要先向成員確認。

例如：

```text
你負責審查前端 Pull Request。

先閱讀變更和相關測試，只檢查：
- React 與 TypeScript 的正確性
- 無障礙使用
- 是否符合既有元件模式

不要直接修改程式碼。請依嚴重程度將問題寫在任務留言中；
沒有阻礙合併的問題時，請明確說明可以合併。
```

## 加入 skill

建立 Agent 時，可以從工作區選擇一個或多個 [skill](/skills)。

skill 適合保存可供多個 Agent 重複使用的方法和資料；只適用於這個 Agent 的長期要求則寫在指令中。

## 對話開場建議

最多可新增三則**聊天開場建議**，讓使用者在傳送第一則訊息前了解 Agent 擅長的工作。開場建議會在他人與 Agent 開始新 Chat 時顯示於輸入框上方，每則包含簡短標籤和完整提示。選取後只會填入輸入框，使用者可以先檢查或修改，不會自動開始執行。

編輯器會預覽新 Chat 的實際畫面；有權編輯 Agent 的人也會在空白畫面中看到**自訂開場建議**連結，點選後可直接返回此頁。

如果留白，Chat 會顯示在地化的通用建議。依 Agent 職責和界線撰寫的範例通常更有幫助。

CLI 可透過 `agent create`／`agent update` 的 `--conversation-starters` 設定此項（JSON 物件陣列，每個物件包含 `label` 和 `prompt`；更新時傳入 `'[]'` 可清空）。`agent copy` 仍會複製來源設定，沒有覆寫 flag。

## 選擇執行環境、模型和思考強度

每個執行環境都已對應一款 AI 程式開發工具。選好執行環境後，可以選擇該工具支援的模型和思考強度；部分工具（例如 Codex）還提供服務層級選項：

- 留白時，會使用執行環境或本機 CLI 的預設值。
- 設定模型後，Agent 之後的執行會使用這個覆寫值。
- 某些執行環境會自行管理模型，因此不會顯示模型選擇器。

不同工具支援的模型、工作階段延續、skill 和 MCP 能力各不相同，請參閱[AI 程式開發工具對照](/providers)。

## 設定 Access

Access 決定哪些成員可以執行這個 Agent（指派任務、@提及或聊天）：

| Access | 含義 |
|---|---|
| **Only me（只有我）** | 只有你可以執行。這是預設選項。 |
| **Entire workspace（整個工作區）** | 所有工作區成員都可以執行。 |
| **Specific people（特定成員）** | 只有你和選取的成員可以執行。 |

![Access 設定：Only me、Entire workspace、Specific people](/images/docs/agent-access-settings.webp)

只有 Agent owner 可以修改 Access，工作區管理員也不能例外。工作區 `owner` 和 `admin` 可以管理其他設定，但不能用管理員身分執行未授權的 Agent。

## 建立後的設定

在 Agent 詳細資訊頁可以繼續調整：

| 設定 | 說明 |
|---|---|
| **並行數上限** | 同一 Agent 最多可同時執行的次數，預設為 6；超過上限的執行會繼續排隊。 |
| **環境變數** | 在啟動 AI 程式開發工具時注入變數。 |
| **自訂參數** | 逐項附加到 AI 程式開發工具的 CLI 參數。 |
| **MCP** | 為支援的 AI 程式開發工具提供 MCP server 設定。 |
| **整合** | 連接 Agent 可以使用的外部服務。 |

承載執行環境的常駐程式也有全域並行數上限（預設為 20）；實際上限取 Agent 和常駐程式兩者中較小的值。

修改設定不會影響已開始的執行。之後的執行由執行環境領取時，會使用當時儲存的 Agent 設定。

## 環境變數與憑證

環境變數適合存放這名 Agent 執行時需要的有限權限憑證，例如唯讀 API key 或單一 scope 的 token。

<Callout type="warning">
**`custom_env` 的值會以明文儲存在 Multica 伺服器資料庫中**，並非"只留在本機"的資料。agent list/get 介面不再回傳任何 env 值，只會回傳鍵的數量；只有工作區 `owner` 和 `admin` 可以解鎖和修改，每次讀取或修改都會留下稽核紀錄。執行中的 Agent 無法呼叫管理介面讀取其他 Agent 的變數。
</Callout>

請勿使用正式環境資料庫管理員密碼或其他高價值的長期憑證。

`PATH`、`HOME` 和 `MULTICA_*` 等執行環境關鍵變數無法在此處覆寫。

## 自訂參數和 MCP

自訂參數會以陣列逐項傳給 AI 程式開發工具，不會經過 shell 展開。參數是否有效由該工具決定；已有獨立欄位的模型設定不必在此重複填寫。

<Callout type="warning">
請勿將憑證或其他祕密資訊放入自訂參數。它們會保留在子程序的 argv 中，同一台電腦上的其他程序可能透過 `ps` 或 `/proc` 讀取；請改用環境變數（`custom_env`）。常駐程式日誌會遮蔽參數值，但無法保護作業系統的程序清單。
</Callout>

MCP 設定可能包含 token，其儲存和顯示規則與環境變數相同。只有支援管理 MCP 設定的執行環境會顯示這個區塊；不支援 MCP 的工具不會因為儲存設定就自動取得這項能力。

## 複製 Agent

複製會沿用名稱以外的大部分工作設定，包括指令、聊天開場建議、skill、自訂參數、頭像、並行數上限和 Access。模型、思考強度和服務層級也會一併複製；如果原本的執行環境無法使用，複本必須改用其他環境，這三項設定就會清空，需重新選擇。

環境變數值和 MCP 設定都不會複製，必須在新 Agent 中重新設定。複製會保留原 Agent 的執行環境綁定和 Access。

## 使用 CLI 建立

```bash
multica agent create \
 --name "Frontend Reviewer" \
 --runtime-id <runtime-id> \
 --description "審查前端 Pull Request" \
 --instructions "先閱讀變更和測試，只在任務留言中提交審查結論。" \
 --conversation-starters '[{"label":"審查 PR","prompt":"審查目前最相關、尚未合併的 Pull Request。"}]'
```

命令列參數中的明文會保留在 shell 歷史；stdin 和權限受限的檔案則不會。

已有設定相近的 Agent 時，可以直接複製：

```bash
multica agent copy <agent-id>
```

預設會複製到相同執行環境；加入 `--runtime-id` 可改用其他執行環境，但必須同時指定 `--model`。環境變數、MCP 設定和 `runtime_config` 永遠不會複製；執行環境綁定則會保留。完整參數請參閱[使用 CLI](/cli)。
