建立 Agent 前，必須先有可用的[執行環境](/daemon-runtimes)。執行環境決定 Agent 使用哪臺電腦和哪款 AI 程式開發工具；Agent 則儲存長期使用的身分、指令和能力。

## 建立流程

在工作區的 **Agent** 頁面點 **新建Agent**，按三步完成：

<Steps>
<Step>

**選擇runtime。** 頁面會列出各臺機器上的 AI 開發工具（harness），只有線上的才能進入下一步。後面能選哪些模型、能不能用 skill，都取決於這一步的選擇。

</Step>
<Step>

**設定Agent。** 填寫名稱、描述、指令、skill、模型和存取許可權。不想從頭寫，可以點 **讓 AI 幫我寫**：目前草稿會交給 Agent Builder，它在對話裡追問關鍵資訊並補全設定。這個按鈕只在所選runtime線上、且不是雲端runtime時出現。對話期間，旁邊的設定草稿隨時可以直接修改。

</Step>
<Step>

**點選建立Agent。** 完成頁會顯示它執行在哪個runtime，並給出下一步入口：指派第一個任務、在任務裡 @ 它，或加入小隊。

</Step>
</Steps>

## 必要資訊

建立 Agent 只需要兩項資訊：

- **名稱**：在目前工作區中必須唯一。
- **執行環境**：選擇實際執行工作的環境。

其他欄位可以先使用預設值，建立後再調整。新 Agent 預設只有建立者可以執行。

## 描述與指令

**描述**是提供給團隊的簡介，只會顯示在 Agent 清單和詳細資訊頁，不會放入 AI 程式開發工具的提示中。

**指令**會在每次執行時提供給 Agent，通常包含：

- 它負責什麼、不負責什麼；
- 收到工作後先檢查什麼；
- 允許修改哪些內容；
- 結果的提交方式；
- 什麼時候需要先向成員確認。

例如：

```text
你负责审查前端 Pull Request。

先阅读改动和相关测试，只检查：
- React 与 TypeScript 的正确性
- 可访问性
- 与现有组件模式是否一致

不要直接修改代码。把问题按严重程度写在 issue 评论中；
没有阻塞问题时，明确说明可以合并。
```

## 加入 skill

建立 Agent 時，可以從工作區選擇一個或多個 [skill](/skills)。

skill 適合儲存可供多個 Agent 重複使用的方法和資料；只適用於這個 Agent 的長期要求則寫在指令中。

## 對話開場建議

最多可新增三則**聊天開場建議**，讓使用者在傳送第一則訊息前瞭解 Agent 擅長的工作。開場建議會在他人與 Agent 開始新 Chat 時顯示於輸入框上方，每則包含簡短標籤和完整提示。選取後只會填入輸入框，使用者可以先檢查或修改，不會自動開始執行。

建立時，它是**身份**卡片裡的一個可選項。建立之後，它在**設定 → 通用**裡，和頭像、名稱、描述放在一起，旁邊會預覽新對話的實際效果。

如果留白，Chat 會顯示在地化的通用建議。依 Agent 職責和界線撰寫的範例通常更有幫助。

CLI 可透過 `agent create`／`agent update` 的 `--conversation-starters` 設定此項（JSON 物件陣列，每個物件包含 `label` 和 `prompt`；更新時傳入 `'[]'` 可清空）。`agent copy` 仍會複製來源設定，沒有覆寫 flag。

## 選擇執行環境、模型和思考強度

每個執行環境都已對應一款 AI 程式開發工具。選好執行環境後，可以選擇該工具支援的模型和思考強度；部分工具（例如 Codex）還提供服務層級選項：

- 留白時，會使用執行環境或本機 CLI 的預設值。
- 設定模型後，Agent 之後的執行會使用這個覆寫值。
- 某些執行環境會自行管理模型，因此不會顯示模型選擇器。

不同工具支援的模型、工作階段延續、skill 和 MCP 能力各不相同，請參閱[AI 程式開發工具對照](/providers)。

## 設定 Access

Access 決定哪些成員可以執行這個 Agent（指派任務、@提及或聊天）：

| Access | 含義 |
|---|---|
| **Only me（只有我）** | 只有你可以執行。這是預設選項。 |
| **Entire workspace（整個工作區）** | 所有工作區成員都可以執行。 |
| **Specific people（特定成員）** | 只有你和選取的成員可以執行。 |

![Access 設定：Only me、Entire workspace、Specific people](/images/docs/agent-access-settings.webp)

只有 Agent owner 可以修改 Access，工作區管理員也不能例外。工作區 `owner` 和 `admin` 可以管理其他設定，但不能用管理員身分執行未授權的 Agent。

## 建立後的設定

在 Agent 詳細資訊頁可以繼續調整：

| 設定 | 說明 |
|---|---|
| **併發上限** | 同一名智慧體最多同時執行多少次執行，預設是 6；達到上限後繼續排隊。 |
| **環境變數** | 在 AI 程式設計工具啟動時注入變數。 |
| **自定義引數** | 逐項追加到 AI 程式設計工具的 CLI 引數中。 |
| **MCP** | 為支援的 AI 程式設計工具設定 MCP server：可以單獨新增，也可以從工作區共享的 MCP Server 裡選用。 |
| **訊息渠道** | 將智慧體連線到飛書、Slack、釘釘、企業微信或 Telegram 等聊天平臺。|

承載執行環境的常駐程式也有全域並行數上限（預設為 20）；實際上限取 Agent 和常駐程式兩者中較小的值。

修改設定不會影響已開始的執行。之後的執行由執行環境領取時，會使用當時儲存的 Agent 設定。

## 環境變數與憑證

環境變數適合存放這名 Agent 執行時需要的有限許可權憑證，例如唯讀 API key 或單一 scope 的 token。

<Callout type="warning">
**`custom_env` 的值會以明文儲存在 Multica 伺服器資料庫中**，並非"只留在本機"的資料。agent list/get 介面不再回傳任何 env 值，只會回傳鍵的數量；只有工作區 `owner` 和 `admin` 可以解鎖和修改，每次讀取或修改都會留下稽核紀錄。執行中的 Agent 無法呼叫管理介面讀取其他 Agent 的變數。
</Callout>

請勿使用正式環境資料庫管理員密碼或其他高價值的長期憑證。

`PATH`、`HOME` 和 `MULTICA_*` 等執行環境關鍵變數無法在此處覆寫。

## 自訂引數和 MCP

自訂引數會以陣列逐項傳給 AI 程式開發工具，不會經過 shell 展開。引數是否有效由該工具決定；已有獨立欄位的模型設定不必在此重複填寫。

建立智慧體、修改自定義引數或更換執行時時，執行時介面卡保留的引數會被拒絕，錯誤資訊會指出衝突的引數。例如，Multica 使用 `--permission-mode bypassPermissions` 執行 Claude Code，在自定義引數裡設定 `--permission-mode dontAsk` 會被拒絕。已儲存的引數與目標執行時衝突時，可以同時傳入 `[]` 清空自定義引數，再完成更換。

<Callout type="warning">
請勿將憑證或其他秘密資訊放入自訂引數。它們會保留在子程式的 argv 中，同一臺電腦上的其他程式可能透過 `ps` 或 `/proc` 讀取；請改用環境變數（`custom_env`）。常駐程式日誌會遮蔽引數值，但無法保護作業系統的程式清單。
</Callout>

MCP 設定可能包含 token，儲存與展示規則和環境變數相同。只有支援託管 MCP 設定的runtime會顯示這一項；不支援的工具不會因為儲存了設定就自動獲得 MCP 能力。Agent有 MCP 設定時，daemon還會合並runtime所在電腦上已設定的 MCP server，見[本機 MCP 設定](/daemon-runtimes#local-mcp)。

Agent詳情頁的 **MCP** 分三組列出這名Agent能用的 MCP server：

| 分組 | 來源 |
|---|---|
| **由 Multica 管理** | 只屬於這名Agent的 server。點選**新增 MCP Server**，用視覺化表單或 JSON 填寫 STDIO 啟動命令或 Streamable HTTP 地址。 |
| **工作區 MCP Server** | 從工作區共享庫裡分配給它的 server，見下一節。 |
| **從runtime繼承** | runtime所在電腦上 AI 開發工具自己的使用者設定，只讀。只有本地runtime線上時才能讀取。 |

名稱相同時，Agent自己的設定優先於工作區分配的 server，兩者又都優先於runtime裡的同名 server。被蓋住的一項會標上**已覆蓋**或**已由 Multica 覆蓋**。

### 工作區共享的 MCP Server

同一個 MCP server 要給多名Agent用時，不必在每名Agent裡各填一遍地址和 token。工作區 `owner` 或 `admin` 在**設定 → MCP 伺服器**裡新增一次，再分給需要它的Agent。

<Steps>
<Step>

管理員開啟**設定 → MCP 伺服器**，點選**新增 MCP Server**，填寫名稱和設定。

</Step>
<Step>

新增後，這個 server 不屬於任何Agent。開啟要用它的Agent詳情頁的 **MCP**，在**工作區 MCP Server**一組點選**從工作區新增**，選中它。

</Step>
<Step>

分配後，每名Agent各有一個開關，可以暫時關掉而不取消分配。改動從這名Agent的下一次執行起生效。

</Step>
</Steps>

**設定 → MCP 伺服器**的列表裡，每個 server 下方顯示"已分配給 N 個Agent"或"未分配給任何Agent"。使用時注意：

- **設定只寫不讀**：儲存後，地址、命令、請求頭和環境變數的值不會再顯示給任何人，包括 owner。要改設定只能點**替換設定**，重新填寫一份完整設定；只改名稱不影響設定和已有分配。
- **刪除影響所有Agent**：在設定裡刪除一個 server，會把它從所有分配過的Agent上一併移除，從各自的下一次執行起生效。只想讓某一名Agent不再用，在它的 **MCP** 裡關掉開關或移除即可。
- **許可權**：普通成員能看到列表，但不能新增或修改。給Agent分配或移除 server，需要該Agent的 owner 或工作區 `owner`、`admin`。Agent在執行中透過 CLI 不能新增 server，也不能改分配。

用 CLI 也能完成同樣的操作。設定裡通常有 token，用檔案或 stdin 傳入，不要直接寫在命令列引數裡：

```bash
multica workspace mcp add linear --server-config-file ./linear.json
multica workspace mcp list
multica agent mcp add <agent-id> <server-id>
```

## 複製 Agent

複製會沿用名稱以外的大部分工作設定，包括指令、聊天開場建議、skill、自訂引數、頭像、並行數上限和 Access。模型、思考強度和服務層級也會一併複製；如果原本的執行環境無法使用，複本必須改用其他環境，這三項設定就會清空，需重新選擇。

環境變數的值、MCP 設定和工作區 MCP Server 的分配在任何情況下都不會複製，需要在新Agent中重新設定。

## 使用 CLI 建立

```bash
multica agent create \
 --name "Frontend Reviewer" \
 --runtime-id <runtime-id> \
 --description "审查前端 Pull Request" \
 --instructions "先阅读改动和测试，只在 issue 评论中提交审查结论。" \
 --conversation-starters '[{"label":"审查 PR","prompt":"审查当前最相关的未合并 Pull Request。"}]'
```

命令列引數中的明文會保留在 shell 歷史；stdin 和許可權受限的檔案則不會。

已有設定相近的 Agent 時，可以直接複製：

```bash
multica agent copy <agent-id>
```

預設會複製到相同執行環境；加入 `--runtime-id` 可改用其他執行環境，但必須同時指定 `--model`。環境變數、MCP 設定和 `runtime_config` 永遠不會複製；執行環境繫結則會保留。完整引數請參閱[使用 CLI](/cli)。
