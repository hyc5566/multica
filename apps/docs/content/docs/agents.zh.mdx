Agent 是 [Multica 工作区](/workspaces)中的协作者。你可以把任务分配给它、在评论中 @它，或直接和它对话。它会通过绑定的运行时调用 AI 编程工具，并把进度和结果写回工作区。

Agent 本身不是一个持续运行的进程。它是一套可以反复使用的身份和配置，只有收到工作时才会产生具体的[运行](/tasks)。

## Agent 的配置项

| 配置 | 作用 |
|---|---|
| **名称、头像和描述** | 让团队知道它是谁、适合做什么。描述只用于展示，不会进入执行提示。 |
| **指令** | 规定它的职责、工作方式、边界和交付要求。每次执行都会使用。 |
| **对话开场建议** | 提供最多三条针对该 Agent 的示例，出现在别人与该 Agent 开始新对话时。选择后只会填入输入框，不会发送。 |
| **Skills** | 提供可以复用的方法、参考资料和支持文件。 |
| **运行时、模型和思考强度** | 决定在哪个运行时、用哪款 AI 编程工具和哪个模型执行；部分工具（如 Codex）还可选择速度档。 |
| **Access** | 决定哪些成员可以运行它。 |
| **执行配置** | 包括并发上限、环境变量、CLI 参数、MCP 和外部集成。 |

更换模型或修改指令不会创建新 Agent，过去的任务、评论和执行记录也不会丢失。

## Agent、运行时和运行

| 概念 | 职责 |
|---|---|
| **Agent** | 决定谁来做、按什么方式做 |
| **运行时** | 决定在哪台电脑、用哪款 AI 编程工具执行 |
| **运行** | 记录这一次执行的过程和结果 |

一个运行时可以承载多个 Agent；一个 Agent 也可以先后完成多次运行。运行时离线时，Agent 的身份和历史仍在，但新的运行需要等待运行时恢复。

## 参与工作的方式

- **负责任务**：把 Agent 设为负责人，运行入队后开始处理。
- **处理一条评论**：在评论中 @Agent，不改变任务的负责人。
- **继续讨论**：回复 Agent 的评论，新的信息会进入后续执行。
- **直接对话**：开始一段不依附于任务的对话。
- **参与项目和小队**：Agent 可以成为项目 lead，也可以担任小队 leader 或小队成员。
- **通过自动化运行**：按时间表或外部事件触发预设工作，也可以手动运行。

Agent 可以创建任务、发表评论和修改工作状态，但它没有收件箱，也不会收到 `@all`。对 Agent 的 @提及是一次执行触发，不是通知。

## 权限与 Access

每个 Agent 都有一名 owner 和一个 Access 设置：

| Access | 谁可以运行 |
|---|---|
| **仅自己**（Only me） | 只有 Agent owner。 |
| **整个工作区**（Entire workspace） | 工作区中的所有成员。 |
| **指定成员**（Specific people） | Agent owner 和指定的成员。 |

新建 Agent 默认使用 **仅自己**。

<Callout type="info">
工作区 `owner` 和 `admin` 可以查看并管理所有 Agent，但不能绕过 Access 运行别人的"仅自己"Agent。普通成员只会看到自己拥有或有权运行的 Agent。
</Callout>

**看见**由 owner 身份、工作区管理角色和 Access 共同决定；**修改**开放给 Agent owner 和工作区 owner/admin，其中 Access 只有 Agent owner 能改。

环境变量和 MCP 等可能包含凭据的配置有更严格的读取规则，见[创建和配置 Agent](/agents-create#环境变量与凭据)。

## 在线、离线和工作状态

Agent 列表会同时展示两类状态：

- **可用性**来自运行时，例如在线、离线或不稳定。
- **工作负载**来自运行，例如处理中、排队中或空闲。

"离线"不表示 Agent 被删除。已经入队的运行会等待运行时恢复；"已归档"才表示它不能再接收新工作。

## 归档和恢复

不再使用的 Agent 可以归档。归档后，它不再出现在选择器中，也不能被分配或 @提及；历史记录保留，之后可以恢复。

<Callout type="warning">
归档会取消该 Agent 所有尚未结束的运行，包括排队中和进行中的运行。
</Callout>

Agent owner 和工作区 `owner`、`admin` 都可以归档或恢复 Agent。
