Agent 是 [Multica 工作區](/workspaces)中的協作者。你可以把任務分配給它、在留言中 @它，或直接和它對話。它會通過綁定的執行環境調用 AI 編程工具，並把進度和結果寫回工作區。

Agent 本身不是一個持續執行的程序。它是一套可以反覆使用的身份和設定，只有收到工作時才會產生具體的[執行](/tasks)。

## Agent 的設定項

| 設定 | 作用 |
|---|---|
| **名稱、頭像和描述** | 讓團隊知道它是誰、適合做什麼。描述只用於展示，不會進入執行提示。 |
| **指令** | 規定它的職責、工作方式、邊界和交付要求。每次執行都會使用。 |
| **對話開場建議** | 提供最多三條針對該 Agent 的示例，出現在別人與該 Agent 開始新對話時。選擇後只會填入輸入框，不會傳送。 |
| **Skills** | 提供可以複用的方法、參考資料和支援檔案。 |
| **執行環境、模型和思考強度** | 決定在哪個執行環境、用哪款 AI 編程工具和哪個模型執行；部分工具（如 Codex）還可選擇速度檔。 |
| **Access** | 決定哪些成員可以執行它。 |
| **執行設定** | 包括併發上限、環境變數、CLI 參數、MCP 和外部整合。 |

更換模型或修改指令不會建立新 Agent，過去的任務、留言和執行記錄也不會丟失。

## Agent、執行環境和執行

| 概念 | 職責 |
|---|---|
| **Agent** | 決定誰來做、按什麼方式做 |
| **執行環境** | 決定在哪臺電腦、用哪款 AI 編程工具執行 |
| **執行** | 記錄這一次執行的過程和結果 |

一個執行環境可以承載多個 Agent；一個 Agent 也可以先後完成多次執行。執行環境離線時，Agent 的身份和歷史仍在，但新的執行需要等待執行環境恢復。

## 參與工作的方式

- **負責任務**：把 Agent 設為負責人，執行入隊後開始處理。
- **處理一條留言**：在留言中 @Agent，不改變任務的負責人。
- **繼續討論**：回覆 Agent 的留言，新的資訊會進入後續執行。
- **直接對話**：開始一段不依附於任務的對話。
- **參與專案和小隊**：Agent 可以成為專案 lead，也可以擔任小隊 leader 或小隊成員。
- **通過自動化執行**：按時間表或外部事件觸發預設工作，也可以手動執行。

Agent 可以建立任務、發表留言和修改工作狀態，但它沒有收件箱，也不會收到 `@all`。對 Agent 的 @提及是一次執行觸發，不是通知。

## 權限與 Access

每個 Agent 都有一名 owner 和一個 Access 設定：

| Access | 誰可以執行 |
|---|---|
| **僅自己**（Only me） | 只有 Agent owner。 |
| **整個工作區**（Entire workspace） | 工作區中的所有成員。 |
| **指定成員**（Specific people） | Agent owner 和指定的成員。 |

新建 Agent 預設使用 **僅自己**。

<Callout type="info">
工作區 `owner` 和 `admin` 可以查看並管理所有 Agent，但不能繞過 Access 執行別人的"僅自己"Agent。普通成員只會看到自己擁有或有權執行的 Agent。
</Callout>

**看見**由 owner 身份、工作區管理角色和 Access 共同決定；**修改**開放給 Agent owner 和工作區 owner/admin，其中 Access 只有 Agent owner 能改。

環境變數和 MCP 等可能包含憑據的設定有更嚴格的讀取規則，見[建立和設定 Agent](/agents-create#環境變數與憑據)。

## 在線、離線和工作狀態

Agent 列表會同時展示兩類狀態：

- **可用性**來自執行環境，例如在線、離線或不穩定。
- **工作負載**來自執行，例如處理中、排隊中或空閒。

"離線"不表示 Agent 被刪除。已經入隊的執行會等待執行環境恢復；"已歸檔"才表示它不能再接收新工作。

## 歸檔和恢復

不再使用的 Agent 可以歸檔。歸檔後，它不再出現在選擇器中，也不能被分配或 @提及；歷史記錄保留，之後可以恢復。

<Callout type="warning">
歸檔會取消該 Agent 所有尚未結束的執行，包括排隊中和進行中的執行。
</Callout>

Agent owner 和工作區 `owner`、`admin` 都可以歸檔或恢復 Agent。
