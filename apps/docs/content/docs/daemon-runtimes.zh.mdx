Multica 記錄和協調工作，連線上來的電腦負責執行：電腦上的**daemon**（daemon）領取執行，再呼叫本機安裝的 AI 開發工具。

## 常駐程式與執行環境

- **常駐程式**是在電腦背景執行的 Multica 程式，負責連線至伺服器、偵測本機工具、領取執行工作並回傳結果。
- **執行環境**是工作區可使用的一種執行方式，由一台電腦及其上的 AI 程式開發工具（或自訂執行環境設定檔）組成。

例如，一臺電腦裝了 Claude Code 和 Codex，連線了兩個工作區，daemon就為每個工作區各註冊一條 Claude Code runtime和一條 Codex runtime。重啟daemon會更新原有記錄，不會為同一個組合反覆建立新runtime。

## 執行位置與資料邊界

本地runtime呼叫的 AI 開發工具、這些工具自己的登入憑據和原生代碼目錄，都留在連線的電腦上。Multica 伺服器不替本地工具執行命令，也不會自動上傳整個工作目錄。

為了讓團隊能夠協作，伺服器會儲存任務、留言、Agent 設定、執行上下文、執行記錄和 Agent 回傳的結果。這些內容可能包含 Agent 主動讀取並寫入回覆的程式碼片段或其他專案內容。

<Callout type="warning">
"本地執行"不等於所有 secret 都只存在本機。Agent的自定義環境變數和 MCP 配置儲存在伺服器側，展示時受敏感資訊規則限制；自定義環境變數會在runtime傳送給runtime。
</Callout>

daemon預設在後臺執行。常用命令：

| 命令 | 作用 |
| --- | --- |
| `multica daemon status` | 查看常駐程式和連接狀態 |
| `multica daemon logs -f` | 持續查看日誌 |
| `multica daemon restart` | 重新啟動常駐程式並再次偵測本機工具 |
| `multica daemon stop` | 停止常駐程式 |
| `multica daemon start --foreground` | 在目前的終端機中執行，方便除錯 |

若要將執行工作目錄放在其他磁碟，可用 `multica config set workspaces_root <path>` 為目前的 profile 設定固定根目錄，也可在 `daemon start` 或 `daemon restart` 時傳入 `--workspaces-root <path>`。旗標的優先順序高於 `MULTICA_WORKSPACES_ROOT`，而環境變數又高於 profile 設定。變更根目錄不會搬移既有的執行目錄。

啟動時，daemon檢測 `PATH` 中受支援的 AI 開發工具，為你有權連線的工作區註冊runtime。工具剛安裝或剛登入時，重啟daemon就會重新檢測。

常駐程式至少需要偵測到一款內建支援的 AI 程式開發工具才能啟動。安裝方式和執行檔名稱請參閱[安裝 AI 程式開發工具](/install-agent-runtime)。

### 開機自啟 [#autostart]

用 CLI 啟動的daemon預設不會隨電腦重啟自動恢復。需要的話，為當前 profile 登記開機自啟：

```bash
multica daemon autostart enable
multica daemon autostart status
multica daemon autostart disable
```

登記的命令是這個 profile 的 `multica daemon start --foreground`，由系統在登入時拉起：Windows 寫入當前使用者的 Run 登錄檔項，macOS 寫入 `~/Library/LaunchAgents` 下的 LaunchAgent，Linux 寫入 systemd 使用者單元，沒有 systemd 使用者會話時改用 XDG autostart 條目。使用命名 profile 時加 `--profile <name>`，每個 profile 單獨登記。

- 只有 `enable` 會建立登記。`multica daemon start` 不會自己登記，只在沒有登記時提示一行；已有 Multica 建立的登記時，它會順手更新其中的可執行檔案路徑，升級或挪動 CLI 後不必重新 `enable`。
- 在 macOS 和 Linux 上，登入會話只帶上 `enable` 時 shell 裡的 `PATH`，shell 匯出的其他變數（API key、`HTTPS_PROXY` 等）都不會帶過去。daemon配置用 `multica config set` 持久化，其他變數放進使用者級環境。
- Linux 的 systemd 使用者單元在登入時啟動。要在開機後不登入也啟動，按 `enable` 輸出的提示執行 `loginctl enable-linger <使用者名稱>`。
- `multica daemon stop` 只停止當前程序，不刪除登記。
- 同一位置已有不是 Multica 建立的檔案（例如你自己寫的 systemd 單元）時，`enable` 和 `disable` 都會拒絕修改它。
- Desktop 拉起的daemon由 Desktop 管理，`daemon start` 不會為它提示或更新登記。

## 派發與線上狀態

runtime註冊後保持連線。新執行入隊時，伺服器通知對應的daemon；daemon也會定期輪詢，防止連線中斷時漏掉通知。所以runtime線上、又有空閒容量時，執行通常立即開始。

daemon每 15 秒傳送一次心跳。服務端綜合心跳與連線狀態判斷runtime是否線上；daemon意外退出後，最遲約 3 分鐘會被判為離線。**runtime**頁面在失聯的頭 5 分鐘裡顯示"最近失聯"，之後顯示"離線"。


執行環境離線時：

- 已經排隊的執行等待runtime恢復，不會轉到其他電腦。只有runtime心跳缺席超過重連寬限期，**並且**這條執行自己也已排隊滿這麼久，它才會失敗。runtime只是忙的話，積壓會一直保留；指派給已離線runtime的工作，也有完整的一個寬限期可以等。
- 正在執行的執行不會馬上失敗。runtime心跳缺席超過重連寬限期（`MULTICA_RUNTIME_RECONNECT_GRACE`，預設 3 小時）後，它們才以 `runtime_offline` 失敗；符合條件的任務或對話執行可以自動重試。
- daemon重新啟動後，會重新註冊runtime，並回收上一次沒有正常結束的執行。
- 離線超過 7 天且沒有任何Agent（包括已歸檔的）繫結的runtime，會被自動清理。

## 併發限制

一個常駐程式預設最多同時執行 20 個工作；每個 Agent 預設最多同時執行 6 個。實際並行上限取兩者中的較小值。

達到上限後，新執行繼續排隊。單個Agent的併發數在Agent設定中調整，整臺電腦的上限用 `MULTICA_DAEMON_MAX_CONCURRENT_TASKS` 調整。並行執行會同時佔用機器效能、工具賬號額度和同一工作目錄。

執行消耗的 token、費用和失敗情況在[統計](/analytics)頁按工作區彙總；單條runtime的 token 用量也可以用 `multica runtime usage <runtime-id>` 檢視。

## 本機 MCP 配置 [#local-mcp]

Agent沒有儲存 MCP 配置時，Multica 不向工具傳任何 MCP 設定，工具照常讀取這臺電腦上它自己的配置。

Agent有 MCP 配置後（哪怕是空配置），Multica 會為每次執行生成一份專用配置交給工具，例如 Claude Code 會以嚴格模式只載入這份配置。為了不讓本機已有的伺服器因此失效，daemon會在runtime所在的電腦上讀取該工具的使用者級 MCP 配置，再和Agent的配置合併。同名伺服器按以下順序取第一個：

1. Agent **MCP** 標籤頁中由 Multica 管理或從工作區 MCP 庫分配的伺服器；
2. 工具的使用者級配置檔案；
3. 僅 Claude Code：已啟用的 Claude Code 外掛自帶的 MCP 伺服器。外掛取自 `~/.claude/settings.json` 的 `enabledPlugins`，讀取外掛目錄下的 `.mcp.json` 和外掛清單裡宣告的 MCP 檔案。

| 工具 | 讀取的使用者級配置 |
|---|---|
| Claude Code | `~/.claude.json` 的 `mcpServers`，以及已啟用外掛的 MCP 伺服器 |
| Codex | `$CODEX_HOME/config.toml`（預設 `~/.codex/config.toml`）的 `mcp_servers` |
| Cursor Agent | `~/.cursor/mcp.json` 的 `mcpServers` |
| OpenCode | `$XDG_CONFIG_HOME/opencode/opencode.json`（預設 `~/.config/opencode/opencode.json`）的 `mcp` |
| OpenClaw | `$CLAWDBOT_CONFIG_PATH`，或 `$OPENCLAW_STATE_DIR/openclaw.json`（預設 `~/.openclaw/openclaw.json`）的 `mcp.servers` |
| CodeArts | `~/.codeartsdoer/codearts_cli.json` 或 `codearts_cli.jsonc` 的 `mcp` |

CodeBuddy、Kimi CLI 和 Pi 啟動時會自己載入使用者級配置，並與 Multica 下發的配置合併，daemon不再預先合併，否則同一個伺服器會啟動兩次。CodeBuddy 遇到同名伺服器時以 Multica 下發的為準。表外的其他工具只收到Agent的配置。

合併在runtime所在的電腦上完成，本機伺服器的命令、URL、請求頭和環境變數不會上傳。Agent **MCP** 標籤頁的"從runtime繼承"一欄只顯示伺服器名稱、傳輸方式、來源和是否啟用；被Agent同名伺服器覆蓋的會標為"已由 Multica 覆蓋"。本機配置檔案無法解析時，daemon記一條警告日誌，這次執行只使用Agent的配置。

## 清理與保留 [#cleanup]

daemon啟動約 30 秒後清理一次，之後每 2 小時一次。正在執行的執行用到的目錄不會被清理。`multica daemon disk-usage` 可以按工作區或按執行檢視佔用。下文的時長都是預設值，對應的 `MULTICA_GC_*` 變數見[環境變數](/environment-variables#gc)。

### 執行目錄

每次執行在工作目錄根目錄（預設 `~/multica_workspaces`）下有一個目錄，放檢出的程式碼、輸出和日誌；同一任務的後續執行會續用它。整個目錄在以下時機刪除：

| 執行來源 | 刪除時機 |
|---|---|
| 任務 | 任務進入 `done` 或 `closed` 分類的狀態，並且超過 24 小時沒有更新 |
| 聊天 | 會話歸檔 24 小時後；會話被刪除後的下一輪清理。會話未歸檔時一直保留 |
| 自動化（僅執行）、快速建立 | 執行結束後的下一輪清理 |
| 找不到歸屬（目錄缺少後設資料，或伺服器上已沒有對應記錄） | 目錄 72 小時沒有改動 |

任務仍未關閉時，執行完成 12 小時後只刪除可重新產生的內容：目錄中的 `node_modules`、`.next`、`.turbo`，以及 `codex-home` 下的四個精確路徑：`.sandbox-bin`、`.tmp/plugins`、`.tmp/marketplaces`、`cache/remote_plugin_catalog`。其他檔案（包括 SQLite 資料庫和 WAL 檔案）保留。受管理的任務執行目錄預設還會在執行完成 14 天後整個刪除，不論任務是否關閉。

未歸檔的聊天若使用 Multica 管理的工作目錄，daemon 預設會在最後一次執行結束 12 小時後依相同規則清理可重新產生的內容。清理成功後，daemon 會跳過該次執行的重複掃描；後續執行結束後，經過相同等待時間便可再次清理。聊天直接在專案本機目錄執行時，只清理上述精確路徑中的 Codex 快取。

專案本機目錄上的執行直接修改自己的目錄，daemon 不會動它。執行記錄目錄保留 daemon 日誌和 `output/`。執行完成超過 `MULTICA_GC_COMPLETED_TASK_TTL`（預設 14 天）後，如果工作階段記錄儲存在記錄目錄外，就刪除整個 `codex-home`；仍保存任務本機工作階段記錄的 home 會保留。將該變數設為 `0` 可關閉 home 到期清理。後續執行會重建 home 並重新連接工作階段儲存；工作階段儲存仍遵循下文獨立的保留策略。

### 共享的倉庫快取

daemon為每個工作區的倉庫保留一份裸倉庫快取，位置在工作目錄根目錄下的 `.repos/<工作區 ID>/`。這臺電腦上同一工作區的執行共用這份快取：每次檢出從快取建立 git worktree，只拉取新提交，不重新克隆。Linux 和 Windows 上的 Codex 執行例外，會從快取得到一份 `.git` 在工作目錄內的獨立克隆，因為在 Codex 的 workspace-write 沙箱下，工作目錄外的 Git 後設資料是隻讀的。

快取在三個條件同時滿足時刪除：已經沒有工作區或專案引用這個倉庫，沒有剩餘 worktree，並且 30 天內沒有執行從它檢出。之後需要時會重新克隆。清理刪掉過期的Agent分支後，daemon會在沒有執行runtime對快取執行 `git reflog expire --expire=30.days --all` 和 `git gc --prune=30.days`。

### 會話、記憶與臨時目錄

| 資料 | 位置 | 保留 |
|---|---|---|
| Codex 會話記錄（每個Agent、每個任務一份） | Codex 目錄（預設 `~/.codex`）下的 `multica-sessions/` | 14 天未使用後刪除；之後這個任務的執行無法續接原來的 Codex 會話 |
| Hermes 會話記錄 | Multica 配置目錄（預設 `~/.multica`，命名 profile 為 `~/.multica/profiles/<name>`）下的 `hermes-sessions/` | 14 天未使用後刪除 |
| Hermes 記憶（每個Agent一份） | 同一目錄下的 `hermes-state/` | 90 天未使用後刪除 |
| 每次執行的私有臨時目錄（`TMPDIR`） | 系統臨時目錄下的 `multica-task-*` | 執行結束後刪除，daemon被強制結束時由之後的清理補刪 |

Hermes 在任務和聊天中的執行會將會話持久目錄作為隔離的 `HERMES_HOME`，`state.db` 及其 SQLite 日誌檔案均為目錄內的普通檔案。這個佈局同時支援舊版程序內 ACP 和新版由 Gateway 執行的 ACP。已有會話記錄會直接複用，舊執行目錄中的會話歷史會在下次執行前遷移。

Multica 每次執行都會重新整理其中的 skill 和派生配置。模型服務認證會保留，託管執行的訊息平臺介面卡和 HTTP 入口會關閉。宿主的 Gateway 狀態、日誌、會話和定時任務各自隔離。執行結束時會停止本次執行的 Gateway，確保後續執行使用自己的執行環境。

### Codex 原生記憶與子Agent [#codex-memory]

daemon管理的 Codex 執行預設關閉 Codex 原生記憶，避免本機或前一次執行留下的記憶帶進別的工作區。設定只寫入這次執行專用的 `CODEX_HOME/config.toml`（`features.memories` 和 `memories.generate_memories`、`memories.use_memories` 均為 `false`），不改你的 `~/.codex/config.toml`。需要保留原生記憶時，在daemon的環境中設定 `MULTICA_CODEX_MEMORY=1`。

Codex 原生子Agent同樣預設關閉：父執行緒結束時，Multica 就把這次執行判為結束，仍在執行的子Agent的結果會丟失。接受這個風險的話，設定 `MULTICA_CODEX_MULTI_AGENT=1`。

## runtime共享 [#私有與公開]

本地runtime預設是**私有**的：只有runtime所有者可以在它上面建立Agent，工作區的 owner、admin 也不例外。runtime是別人的電腦，在上面跑Agent，用的是對方的機器和工具憑據。

也只有所有者可以把它改為**公開**。管理員可以重新命名或刪除runtime，但要不要共享由所有者決定。公開後，工作區中的其他成員也可以選擇這條runtime，把Agent的執行路由到這臺電腦；底層 AI 開發工具的登入憑據不會因此共享。

只想開放給部分成員時，在runtime詳情中選擇**指定成員**，勾選一位或多位工作區成員，然後**儲存**。這些成員可以選擇該runtime並在上面建立Agent。只有所有者能修改名單；在名單上不代表可以重新命名、刪除或管理這條runtime。

所有者移除共享成員、把公開runtime改為指定成員，或重新設為**私有**時，Multica 會先展示受影響的Agent和活動執行，包括Agent構建會話。確認後會解綁其他成員的這些Agent，以 `runtime_access_revoked` 取消其排隊中、已排程、執行中、等待本地目錄和延遲中的執行，並暫停分配給這些Agent的已啟用自動化。所有者和仍有許可權的成員，其Agent與執行不受影響。影響範圍變化時需要重新確認；遇到併發聊天寫入時可能需要重試。恢復工作時，請先將Agent繫結到可用的runtime，再手動恢復已暫停的自動化。

取消會保留聊天曆史，並在服務端儲存草稿和附件恢復資料。網頁端和桌面端沿用現有的草稿恢復入口；移動端暫未提供該入口。已開始但尚無輸出的執行，會等待daemon確認取消或服務端收尾寬限期結束，再決定是否恢復輸入。已連線的daemon透過常規檢查接收取消。電腦離線時，服務端仍會立即撤銷訪問，但本地程序可能繼續執行，直到重新連線並收到取消；服務端無法保證立即遠端停止。

## 自訂執行環境設定檔

如果團隊使用內部 wrapper、固定版本的可執行檔，或需要為相容工具加入固定參數，可以建立**自訂執行環境設定檔**。

自定義配置不增加新的通訊協議。建立時要選擇一種 Multica 已支援的協議族（工具的對接協議型別，見 [AI 開發工具對照](/providers)）；命令本身必須與該協議相容。

### 執行環境中的任務變數

常駐程式啟動 Agent 任務時，會將任務上下文注入執行環境程序。這些值由常駐程式管理；Agent 的自訂環境無法覆寫任何 `MULTICA_` 變數或任務暫存目錄變數。

下表列出自訂執行環境目前可使用的變數。這不是完整清單，也不是有版本保證的 API。整合程式只能依賴標示為**整合契約**的 5 個變數；其餘僅供參考，未來可能變更。

| 變數 | 任務中的值 | 穩定性 |
| --- | --- | --- |
| `MULTICA_TOKEN` | task 級 `mat_` API 憑據 | **整合契約** |

<Callout type="warning">
這些值存在於runtime程序的實際環境中。runtime啟動的任何子程序預設都會繼承全部變數，包括 `MULTICA_TOKEN`。子程序不應持有該憑據時，必須顯式移除，程序之間沒有自動隔離。反過來，有些工具會過濾自己的子程序環境，這時可能需要顯式放行變數。例如，Codex 的 shell 工具會丟棄名稱中含有 `TOKEN`、`KEY` 或 `SECRET` 的變數，所以daemon會安裝託管的 shell 策略，放行所需的 task 變數。令牌只能存在於程序環境中，不得寫入 prompt、日誌、倉庫檔案或持久配置。子程序與父 task 共享身份和許可權，不會獲得新的獨立作用域身份。
</Callout>

### 建立設定

只有工作區 owner 和 admin 可以建立、修改或刪除自訂執行環境設定：

1. 開啟 **執行環境**，前往已安裝該命令的電腦。
2. 點選**新增自訂執行環境**。
3. 選擇該命令實際相容的協定類別。
4. 填寫名稱、命令和固定參數，然後儲存。

設定會在工作區內共用。每台已連線的電腦都會自行尋找這個命令；只有能從 `PATH` 找到命令的電腦才會註冊對應執行環境。建立設定不會自動安裝命令，也不會替其他成員登入工具。

這裡填寫的是執行檔和參數，不是 shell 指令碼。可以使用一般參數、引號和反斜線跳脫，但不能使用管線、重新導向、`&&`、`;`、反引號或環境變數展開。若需要這些功能，請將其寫在 wrapper script 中，再把該指令碼填作命令。

版本檢查和 Pi 模型探測會在空臨時目錄中執行，以相容禁止從主目錄啟動的沙箱包裝器。主目錄環境和使用者級配置仍然可用。固定引數中的指令碼或配置檔案請使用絕對路徑；探測不再讀取相對於 daemon 啟動目錄的配置。任務執行仍使用任務的工作目錄。

### 引數的排列順序

命令欄位中填寫的內容會緊接在執行檔之後，排在 Multica 附加的參數之前：

```text
<你的命令> <你的固定參數> <Multica 的協定參數> <Agent 的自訂參數>
```

帶子命令的 wrapper 靠這個順序工作。命令是 `ccms start q36` 時，工具先看到 `start q36`，在 Multica 的 `-p` 等引數到達之前選好子命令；這類 wrapper 只接受這一種順序。

這裡的引數以前追加在最後。多數 flag 形式的命令在兩種位置下解析結果相同，但區分全域性 flag 和子命令 flag 的命令會在意位置。已經配置了帶固定引數的 profile 的，升級後請發起一次執行，確認它仍能正常啟動。

另外：

- **發生衝突時以 Multica 的值為準。** 如果固定參數設定了 Multica 也會設定的旗標，Multica 的值會排在後面並生效。最常見的情況是 Agent 選擇的模型會覆寫 profile 中固定的 `--model`。若要為所有人固定模型，請將 Agent 的模型欄位留空。
- **協定所需的關鍵旗標會被忽略。** `-p`、`--output-format`、`--input-format`、`--permission-mode` 以及其他協定類別的對應旗標都會從固定參數中移除，因為覆寫它們會中斷 daemon 與工具之間的通訊。子命令和其他位置參數一律會原樣傳遞。

如果 Desktop 啟動的常駐程式找不到終端機可執行的命令，可以為目前的電腦設定絕對路徑：

```bash
multica runtime profile set-path <profile-id> --path /absolute/path/to/command
```

移除路徑覆蓋：

```bash
multica runtime profile unset-path <profile-id>
```

修改配置隻影響之後領取的執行。刪除配置前，需要先處理仍繫結在對應runtime上的活動Agent。只刪除某臺電腦上的runtime例項不會刪除配置，執行中的daemon還會重新註冊它。

## Qoder Cloud Agents 遠端runtime

Qoder Cloud Agents 透過遠端會話執行分配的任務。Multica 服務端管理橋接程序，複用現有daemon任務協議，無需使用者啟動本地daemon。

### 準備工作

- 需要工作區管理員許可權。每個工作區只有一個 Qoder 連線。
- 建立 Qoder 個人訪問令牌（PAT）、至少一個執行環境，以及要在 Qoder Cloud Agents 中使用的Agent。模型、工具和 skill 都在 Qoder Cloud Agents 中的遠端Agent上配置，不在 Multica 中配置。
- 自託管部署需在服務端設定 `MULTICA_VCS_SECRET_KEY`：一個 base64 編碼的 32 位元組金鑰，重啟前後必須保持不變。未設定時，**新增**選單中不會出現 Qoder Cloud Agents。

### 連線 Qoder

1. 在**runtime**頁面點選**新增**，在**雲服務**下選擇 **Qoder Cloud Agents**。
2. 在**服務區域**中選擇簽發 PAT 的站點：**國際站**（qoder.com）或**中國站**（qoder.com.cn）。PAT 只在簽發它的站點有效；如果被拒絕，可點選按鈕改用另一站點重試。
3. 將 PAT 貼上到**個人訪問令牌**。驗證透過後會從 Qoder 載入**執行環境**列表；只有一個環境時自動選中，否則手動選擇。
4. 可選：展開 **GitHub 倉庫授權**，為Agent需要克隆的每個倉庫填寫倉庫 URL 和令牌。Agent只能克隆這裡授權過的倉庫。
5. 可選：展開**執行設定**，設定併發執行數（預設 3，最多 10）和執行超時（預設 60 分鐘，可設 5 到 240 分鐘）。
6. 點選**連線**。Qoder Cloud Agents 會出現在runtime頁面的雲服務分組中，幾秒內上線。

### 新增Agent

在runtime頁面開啟 Qoder Cloud Agents，點選**用它建立Agent**；也可以照常建立Agent並選擇 Qoder runtime。在Agent表單的 **遠端Agent**中選擇遠端Agent。已有Agent可在**Qoder Cloud Agents** 標籤頁中修改關聯的 Qoder Cloud Agents Agent或預設倉庫。多個 Multica Agent可以共用同一個連線，各自關聯不同的 Qoder Cloud Agents Agent。

連線憑證加密儲存，在工作區內共享。管理員管理連線，成員可以選擇可訪問的 Qoder Cloud Agents Agent。專案選擇倉庫和起始分支；建立編碼會話時，對應倉庫的令牌會傳給 Qoder Cloud Agents。儲存後的 PAT 不會返回瀏覽器。

管理員可以在 Qoder Cloud Agents 頁面編輯連線和倉庫；點選**暫停**停止下發新任務，憑證和Agent保留；點選**斷開連線**刪除已儲存的令牌、移除該runtime並解綁其Agent。

### 執行方式

超出併發上限的任務會排隊等待。同一任務的後續執行會在上一會話空閒時繼續使用該 Qoder 會話。Agent可以設定預設倉庫，在任務所屬專案未繫結倉庫時使用。Agent會被要求以任務標識命名分支，並在 PR 標題前加上任務標識，以便 PR 自動關聯到任務。

首版支援任務執行、聊天、擔任小隊隊長、透過Agent建立任務、進度同步、取消和基於持久化記錄的恢復。模型、工具和 skill 在 Qoder 中配置。任務和聊天訊息裡的附件和圖片會交給遠端會話，包括 PDF 和 Office 文件，每個檔案不超過 5 MB；更大的檔案不會傳過去，Agent只知道有這些檔案。聊天中Agent用 DeliverArtifacts 交付的檔案（每個不超過 10 MB）會作為附件隨回覆發出。暫不支援本地目錄，也不支援從 Multica 建立遠端 Qoder Cloud Agents Agent。runtime頁面分別展示遠端runtime和電腦。

獨立橋接程序的配置與限制見 [Qoder runtime README](https://github.com/multica-ai/multica/blob/main/server/cmd/qoder-runtime/README.md)。

## 執行環境離線的排查

按以下順序檢查：

1. 執行 `multica daemon status`，確認常駐程式已啟動。
2. 執行 `multica daemon logs -f`，查看登入、網路或工具偵測錯誤。
3. 在相同的執行環境中執行 `command -v <工具命令>`，確認常駐程式找得到該工具。
4. 打開 Multica 的**執行環境**頁面，檢查目標電腦和對應的 AI 程式開發工具是否顯示在線。
5. 安裝工具、修改路徑或更新設定後，執行 `multica daemon restart`。

仍未解決時，參見[疑難排解](/troubleshooting)。
