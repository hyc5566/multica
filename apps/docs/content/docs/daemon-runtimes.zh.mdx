Multica 負責記錄和協調工作，連線的電腦則負責執行。電腦上的**常駐程式**（daemon）會領取執行工作，再呼叫本機安裝的 AI 程式開發工具。

## 常駐程式與執行環境

- **常駐程式**是在電腦背景執行的 Multica 程式，負責連線至伺服器、偵測本機工具、領取執行工作並回傳結果。
- **執行環境**是工作區可使用的一種執行方式，由一台電腦及其上的 AI 程式開發工具（或自訂執行環境設定檔）組成。

例如，一台電腦同時安裝 Claude Code 和 Codex，並連線至兩個工作區。常駐程式會在兩個工作區中分別註冊 Claude Code 和 Codex 執行環境。重新啟動常駐程式只會更新既有記錄，不會為相同組合重複建立執行環境。

## 執行位置與資料邊界

本機執行環境所呼叫的 AI 程式開發工具、工具本身的登入憑證，以及本機程式碼資料夾都留在連線的電腦上。Multica 伺服器不會代替本機工具執行命令，也不會自動上傳整個工作目錄。

為了讓團隊能夠協作，伺服器會儲存任務、留言、Agent 設定、執行上下文、執行記錄和 Agent 回傳的結果。這些內容可能包含 Agent 主動讀取並寫入回覆的程式碼片段或其他專案內容。

<Callout type="warning">
Agent 的自訂環境變數會儲存在伺服器端，並在執行時傳送給執行環境。請勿將"本機執行"理解為所有 secret 都只存在本機：自訂環境變數和 MCP 設定儲存在伺服器端，其顯示方式會依敏感資訊規則限制。
</Callout>

## 啟動常駐程式

使用 Multica Desktop 時，App 會自動啟動常駐程式，不需要額外執行命令。

使用 Web、遠端電腦或無介面環境時，請先[安裝 Multica CLI](/cli)，再執行：

```bash
multica daemon start
```

常駐程式預設在背景執行。常用命令如下：

| 命令 | 作用 |
| --- | --- |
| `multica daemon status` | 查看常駐程式和連接狀態 |
| `multica daemon logs -f` | 持續查看日誌 |
| `multica daemon restart` | 重新啟動常駐程式並再次偵測本機工具 |
| `multica daemon stop` | 停止常駐程式 |
| `multica daemon start --foreground` | 在目前的終端機中執行，方便除錯 |

若要將執行工作目錄放在其他磁碟，可用 `multica config set workspaces_root <path>` 為目前的 profile 設定固定根目錄，也可在 `daemon start` 或 `daemon restart` 時傳入 `--workspaces-root <path>`。旗標的優先順序高於 `MULTICA_WORKSPACES_ROOT`，而環境變數又高於 profile 設定。變更根目錄不會搬移既有的執行目錄。

啟動時，常駐程式會偵測 `PATH` 中受支援的 AI 程式開發工具，並為你有權連接的工作區註冊執行環境。如果剛安裝或登入某款工具，重新啟動常駐程式即可再次偵測。

常駐程式至少需要偵測到一款內建支援的 AI 程式開發工具才能啟動。安裝方式和執行檔名稱請參閱[安裝 AI 程式開發工具](/install-agent-runtime)。

## 派發與在線狀態

執行環境註冊後會維持連線。新的執行工作進入佇列時，伺服器會通知對應的常駐程式；若連線中斷，常駐程式也會定期輪詢作為補充。因此，執行環境上線且有剩餘容量時，工作通常會立即開始。

常駐程式每 15 秒傳送一次心跳。伺服器會綜合心跳和連線狀態判斷執行環境是否上線；常駐程式意外結束後，執行環境通常最晚約 3 分鐘就會顯示離線。

![一台在線電腦的執行環境詳情：同一常駐程式註冊了 7 個執行環境，每款檢測到的 AI 程式開發工具各佔一行，均顯示在線狀態與 CLI 版本](/images/docs/runtime-machine-detail.webp)

執行環境離線時：

- 已排入佇列的執行會等待執行環境恢復。只有在執行環境未傳送心跳超過重新連線寬限期，**且**該執行也已排隊這麼久時，執行才會失敗。因此，若執行環境只是忙碌，待處理工作會繼續排隊；指派給已離線執行環境的工作也仍有完整的寬限期可等待。
- 正在執行的工作會失敗；符合條件的任務或對話執行可以自動重試。
- 常駐程式重新啟動後，會重新註冊執行環境，並回收上次未正常結束的執行。
- 離線超過 7 天且沒有任何 Agent（包括已封存的）綁定的執行環境，會被自動清理。

詳細狀態和重試規則見[執行](/tasks)。

## 併發限制

一個常駐程式預設最多同時執行 20 個工作；每個 Agent 預設最多同時執行 6 個。實際並行上限取兩者中的較小值。

達到上限後，新的執行會繼續排隊。你可以在 Agent 設定中調整單一 Agent 的並行數，也可以透過 `MULTICA_DAEMON_MAX_CONCURRENT_TASKS` 調整整台電腦的上限。平行執行會同時占用電腦資源、工具帳號額度和同一個工作目錄。

## 私有與公開

本機執行環境預設為**私人**：只有執行環境擁有者可以在上面建立 Agent。工作區 owner 和 admin 也不例外——執行環境屬於別人的電腦，在上面執行 Agent 會使用對方的電腦資源和工具憑證。

只有執行環境擁有者可以將它設為**公開**。工作區管理員可以重新命名或刪除執行環境，但是否共享由擁有者決定。公開後，工作區中的其他成員也能選用這個執行環境；這不會分享底層 AI 程式開發工具的登入憑證，只會讓成員將 Agent 的執行工作交由這台電腦處理。

## 自訂執行環境設定檔

如果團隊使用內部 wrapper、固定版本的可執行檔，或需要為相容工具加入固定參數，可以建立**自訂執行環境設定檔**。

自訂設定檔不會增加新的通訊協定。建立時仍須選擇 Multica 已支援的其中一種協定類型（工具的整合協定，請參閱 [AI 程式開發工具比較](/providers)），而命令本身必須與該協定相容。

### 執行環境中的任務變數

常駐程式啟動 Agent 任務時，會將任務上下文注入執行環境程序。這些值由常駐程式管理；Agent 的自訂環境無法覆寫任何 `MULTICA_` 變數或任務暫存目錄變數。

下表列出自訂執行環境目前可使用的變數。這不是完整清單，也不是有版本保證的 API。整合程式只能依賴標示為**整合契約**的 5 個變數；其餘僅供參考，未來可能變更。

| 變數 | 任務中的值 | 穩定性 |
| --- | --- | --- |
| `MULTICA_TOKEN` | 僅供該任務使用的 `mat_` API 憑證 | **整合契約** |
| `MULTICA_TASK_ID` | 目前任務的 ID | **整合契約** |
| `MULTICA_AGENT_ID` | 受指派 Agent 的 ID | **整合契約** |
| `MULTICA_WORKSPACE_ID` | 任務所屬工作區的 ID | **整合契約** |
| `MULTICA_SERVER_URL` | 常駐程式選定的 Multica 伺服器位址 | **整合契約** |
| `MULTICA_TASK_CONFIG_ROOT` | 任務專用的本機 Multica CLI 設定根目錄 | 僅供參考 |
| `MULTICA_TASK_WORKSPACES_ROOT` | 常駐程式管理的任務工作區根目錄 | 僅供參考 |
| `MULTICA_AGENT_NAME` | 被指派 Agent 的顯示名稱 | 僅供參考 |
| `MULTICA_DAEMON_PORT` | 本機常駐程式的健康檢查／API 連接埠，供 `multica repo checkout` 等僅限任務使用的命令使用 | 僅供參考 |
| `MULTICA_TASK_SLOT` | 常駐程式全域並行池中的槽位，可用於依槽位編號的資源，例如 GPU | 僅供參考 |
| `TMPDIR` | 目前任務的專用暫存目錄；也會設為 `TMP` 和 `TEMP`。Windows 的任務則會沿用使用者暫存路徑，以供 Git Bash 共用 `/tmp`；Windows 版 Claude Code 會將 `CLAUDE_CODE_TMPDIR` 預設為任務暫存目錄 | 僅供參考 |

使用 `MULTICA_TOKEN` 發出請求時，作者身分由伺服器決定；任務留言等寫入操作會歸屬於受指派的 Agent 和目前任務。權杖的完整綁定關係、權限、歸屬方式、最長 24 小時的有效期限和清理規則，請參閱[Agent 執行時使用的暫時權杖](/auth-tokens#agent-執行時使用的暫時權杖)。

<Callout type="warning">
這些值會存在於執行環境程序的實際環境中。執行環境啟動的任何子程序預設都會繼承所有變數，包括 `MULTICA_TOKEN`。若子程序不應持有該憑證，必須明確移除；不要假設程序間有實際上不存在的隔離。反過來說，有些工具會篩除子程序環境中的變數，因此可能需要明確允許。例如，Codex 的 shell 工具會丟棄名稱含有 `TOKEN`、`KEY` 或 `SECRET` 的變數，因此常駐程式會安裝受管理的 shell 政策，允許必要的任務變數。權杖只能存留於程序環境中，不得寫入 prompt、日誌、儲存庫檔案或持久設定。子程序會與父任務共用身分和權限，不會取得新的獨立作用域身分。
</Callout>

### 建立設定

只有工作區 owner 和 admin 可以建立、修改或刪除自訂執行環境設定：

1. 開啟 **執行環境**，前往已安裝該命令的電腦。
2. 點選**新增自訂執行環境**。
3. 選擇該命令實際相容的協定類別。
4. 填寫名稱、命令和固定參數，然後儲存。

設定會在工作區內共用。每台已連線的電腦都會自行尋找這個命令；只有能從 `PATH` 找到命令的電腦才會註冊對應執行環境。建立設定不會自動安裝命令，也不會替其他成員登入工具。

這裡填寫的是執行檔和參數，不是 shell 指令碼。可以使用一般參數、引號和反斜線跳脫，但不能使用管線、重新導向、`&&`、`;`、反引號或環境變數展開。若需要這些功能，請將其寫在 wrapper script 中，再把該指令碼填作命令。

### 參數的排列順序

命令欄位中填寫的內容會緊接在執行檔之後，排在 Multica 附加的參數之前：

```text
<你的命令> <你的固定參數> <Multica 的協定參數> <Agent 的自訂參數>
```

帶子命令的 wrapper 正是依靠這個順序才能工作。如果命令是 `ccms start q36`，工具會先看到 `start q36`，在 Multica 的 `-p` 等參數到達之前完成子命令選擇——這類 wrapper 只接受這一種順序。

以前，這裡填寫的參數會附加在最後。多數使用旗標的命令在這兩種位置下解析結果相同，但並非全部如此：如果命令區分全域旗標和子命令旗標，就會受到旗標位置影響。如果你已設定帶固定參數的 profile，升級後請執行一次，確認仍能正常啟動。

另有兩點需要注意：

- **發生衝突時以 Multica 的值為準。** 如果固定參數設定了 Multica 也會設定的旗標，Multica 的值會排在後面並生效。最常見的情況是 Agent 選擇的模型會覆寫 profile 中固定的 `--model`。若要為所有人固定模型，請將 Agent 的模型欄位留空。
- **協定所需的關鍵旗標會被忽略。** `-p`、`--output-format`、`--input-format`、`--permission-mode` 以及其他協定類別的對應旗標都會從固定參數中移除，因為覆寫它們會中斷 daemon 與工具之間的通訊。子命令和其他位置參數一律會原樣傳遞。

如果 Desktop 啟動的常駐程式找不到終端機可執行的命令，可以為目前的電腦設定絕對路徑：

```bash
multica runtime profile set-path <profile-id> --path /absolute/path/to/command
```

移除路徑覆蓋：

```bash
multica runtime profile unset-path <profile-id>
```

修改設定只會影響之後領取的執行。刪除設定前，必須先處理仍綁定至對應執行環境的活動 Agent。只刪除某台電腦上的執行環境實例並不會刪除設定；正在執行的常駐程式仍會重新註冊該設定。

## 執行環境離線的排查

按以下順序檢查：

1. 執行 `multica daemon status`，確認常駐程式已啟動。
2. 執行 `multica daemon logs -f`，查看登入、網路或工具偵測錯誤。
3. 在相同的執行環境中執行 `command -v <工具命令>`，確認常駐程式找得到該工具。
4. 打開 Multica 的**執行環境**頁面，檢查目標電腦和對應的 AI 程式開發工具是否顯示在線。
5. 安裝工具、修改路徑或更新設定後，執行 `multica daemon restart`。

仍未解決時，參見[疑難排解](/troubleshooting)。
