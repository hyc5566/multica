Multica 負責記錄和協調工作，連接的電腦負責執行。電腦上的**守護程序**（daemon）領取執行，再調用本機安裝的 AI 編程工具。

## 概念區分

- **守護程序**是執行在一臺電腦上的 Multica 後臺程序。它負責連接伺服器、發現本機工具、領取執行和回傳結果。
- **執行環境**代表一個工作區可以使用的具體執行環境。它對應一臺電腦，以及這臺電腦上的一款 AI 編程工具或自定義執行環境設定。

例如，一臺電腦同時安裝了 Claude Code 和 Codex，並連接兩個工作區。守護程序會分別為兩個工作區註冊 Claude Code 和 Codex 執行環境。重啟守護程序會更新原有記錄，不會為同一個組合不斷建立新執行環境。

## 執行位置與資料邊界

本地執行環境調用的 AI 編程工具、這些工具自己的登入憑據，以及本地程式碼目錄都留在連接的電腦上。Multica 伺服器不會代替本地工具執行命令，也不會自動上傳整個工作目錄。

為了讓團隊能夠協作，伺服器會儲存任務、留言、Agent 設定、執行上下文、執行記錄和 Agent 寫回的結果。這些內容可能包含 Agent 主動讀取並寫入回覆的程式碼片段或其他專案上下文。

<Callout type="warning">
Agent 的自定義環境變數儲存在伺服器側，並在執行時傳送給執行環境。不要把"本地執行"理解為所有 secret 都只存在本機；自定義環境變數和 MCP 設定儲存在伺服器側，展示受敏感資訊規則限制。
</Callout>

## 啟動守護程序

使用 Multica Desktop 時，應用會自動啟動守護程序，不需要額外執行命令。

使用 Web、遠端電腦或無介面環境時，先[安裝 Multica CLI](/cli)，再執行：

```bash
multica daemon start
```

守護程序預設在後臺執行。常用命令如下：

| 命令 | 作用 |
| --- | --- |
| `multica daemon status` | 查看守護程序和連接狀態 |
| `multica daemon logs -f` | 持續查看日誌 |
| `multica daemon restart` | 重啟守護程序並重新檢測本機工具 |
| `multica daemon stop` | 停止守護程序 |
| `multica daemon start --foreground` | 在當前終端中執行，便於調試 |

如需把執行工作目錄放到其他磁盤，可用 `multica config set workspaces_root <path>` 為當前 profile 持久化根目錄，也可在 `daemon start` 或 `daemon restart` 中傳入 `--workspaces-root <path>`。flag 的優先順序高於 `MULTICA_WORKSPACES_ROOT`，環境變數又高於 profile 設定。修改根目錄不會遷移已有的執行目錄。

啟動時，守護程序會檢測 `PATH` 中受支援的 AI 編程工具，併為你有權連接的工作區註冊執行環境。如果一款工具剛剛安裝或登入，重啟守護程序即可重新檢測。

守護程序至少需要檢測到一款內置支援的 AI 編程工具才能啟動。安裝方法和執行檔名見[安裝 AI 編程工具](/install-agent-runtime)。

## 派發與在線狀態

執行環境註冊後會持續保持連接。新執行入隊時，伺服器會通知對應守護程序；守護程序也會定期輪詢，作為連接中斷後的補充。因此執行環境在線且有空閒容量時，執行通常會立即開始。

守護程序每 15 秒傳送一次心跳。服務端綜合心跳與連接狀態判斷執行環境是否在線；守護程序意外退出後，最遲通常會在約 3 分鐘內顯示為離線。

![一臺在線電腦的執行環境詳情：同一守護程序註冊了 7 個執行環境，每款檢測到的 AI 編程工具各佔一行，均顯示在線狀態與 CLI 版本](/images/docs/runtime-machine-detail.webp)

執行環境離線時：

- 已經排隊的執行會等待執行環境恢復，只有當它心跳缺席超過重連寬限期**且**該執行自己也已排隊滿這麼久時才會失敗；所以執行環境只是忙的話積壓會一直保留，指派給已離線執行環境的工作也仍然有完整一個寬限期可以等待。
- 正在執行的執行會失敗；符合條件的任務或對話執行可以自動重試。
- 守護程序重新啟動後，會重新註冊執行環境，並回收上一次沒有正常結束的執行。
- 離線超過 7 天且沒有任何 Agent（包括已歸檔的）綁定的執行環境，會被自動清理。

詳細狀態和重試規則見[執行](/tasks)。

## 併發限制

一臺守護程序預設最多同時執行 20 次執行；每個 Agent 預設最多同時執行 6 次。實際併發取兩者中的較小值。

達到上限後，新執行會繼續排隊。你可以在 Agent 設定中調整單個 Agent 的併發數，也可以通過 `MULTICA_DAEMON_MAX_CONCURRENT_TASKS` 調整整臺電腦的上限。並行執行會同時佔用機器性能、工具帳戶額度和同一工作目錄。

## 私有與公開

本地執行環境預設是**私有**的：只有執行環境所有者可以在它上面建立 Agent。工作區的 owner、admin 也不例外——執行環境是別人的電腦，在上面跑 Agent 消耗的是對方的機器和工具憑據。

只有執行環境所有者可以把它改為**公開**——管理員可以重命名或刪除執行環境，但要不要共享由所有者決定。公開後，工作區中的其他成員也可以選擇這條執行環境；這不會分享底層 AI 編程工具的登入憑據，只是允許成員把 Agent 的執行路由到這臺電腦。

## 自定義執行環境設定

如果團隊使用內部 wrapper、固定版本的執行檔，或需要為一款兼容工具追加固定參數，可以建立**自定義執行環境設定**。

自定義設定不會增加新的通信協議。建立時仍需選擇一種 Multica 已支援的協議族（工具的對接協議類型，見 [AI 編程工具對照](/providers)）；命令本身必須與該協議兼容。

### Task 執行環境

守護程序啟動 Agent task 時，會把 task 上下文注入執行環境程序。這些值由守護程序管理；Agent 的自定義環境無法覆蓋任何 `MULTICA_` 變數或 task 臨時目錄變數。

下表列出自定義執行環境目前可以使用的變數。它不是完整清單，也不是有版本保證的 API。整合只能依賴標為**整合契約**的 5 個變數；其餘變數僅供參考，後續可能變化。

| 變數 | task 中的值 | 穩定性 |
| --- | --- | --- |
| `MULTICA_TOKEN` | task 級 `mat_` API 憑據 | **整合契約** |
| `MULTICA_TASK_ID` | 當前 task 的 ID | **整合契約** |
| `MULTICA_AGENT_ID` | 被指派 Agent 的 ID | **整合契約** |
| `MULTICA_WORKSPACE_ID` | task 所屬工作區的 ID | **整合契約** |
| `MULTICA_SERVER_URL` | 守護程序選定的 Multica 服務地址 | **整合契約** |
| `MULTICA_TASK_CONFIG_ROOT` | 私有的 task 本地 Multica CLI 設定根目錄 | 僅供參考 |
| `MULTICA_TASK_WORKSPACES_ROOT` | 守護程序管理的 task 工作區根目錄 | 僅供參考 |
| `MULTICA_AGENT_NAME` | 被指派 Agent 的顯示名稱 | 僅供參考 |
| `MULTICA_DAEMON_PORT` | 本地守護程序的健康檢查/API 端口，供 `multica repo checkout` 等僅限 task 的命令使用 | 僅供參考 |
| `MULTICA_TASK_SLOT` | 守護程序全局併發池中的槽位，可用於 GPU 等按槽位編號的資源 | 僅供參考 |
| `TMPDIR` | 當前 task 的私有臨時目錄；也會以 `TMP` 和 `TEMP` 提供給跨平臺工具 | 僅供參考 |

使用 `MULTICA_TOKEN` 發起請求時，作者身份由服務端決定；任務留言等寫入操作會歸屬到被指派的 Agent 和當前 task。令牌的完整綁定關係、權限、歸屬方式、最長 24 小時的有效期和清理規則見[Agent 執行的臨時令牌](/auth-tokens#agent-執行的臨時令牌)。

<Callout type="warning">
這些值存在於執行環境程序的實際環境中。執行環境啟動的任何子程序預設都會繼承全部變數，包括 `MULTICA_TOKEN`。如果子程序不應持有該憑據，必須顯式移除；不要假定程序之間存在並沒有的隔離。反過來，有些工具會過濾自己的子程序環境，因此可能需要顯式放行變數。例如，Codex 的 shell 工具會丟棄名稱中含有 `TOKEN`、`KEY` 或 `SECRET` 的變數，所以守護程序會安裝託管的 shell 策略，放行所需的 task 變數。令牌只能存在於程序環境中，不得寫入 prompt、日誌、倉庫檔案或持久設定。子程序與父 task 共享身份和權限，不會獲得新的獨立作用域身份。
</Callout>

### 建立設定

只有工作區 owner 和 admin 可以建立、修改或刪除自定義執行環境設定：

1. 開啟 **執行環境**，進入已經安裝該命令的電腦。
2. 點擊**新增自定義執行環境**。
3. 選擇命令實際兼容的協議族。
4. 填寫名稱、命令和固定參數，然後儲存。

設定會在工作區內共享。每臺已連接電腦會自行查找這個命令；只有能在 `PATH` 中解析到它的電腦才會註冊對應執行環境。建立設定不會自動安裝命令，也不會替其他成員完成工具登入。

這裡填寫的是執行檔和參數，不是 shell 腳本。可以使用普通參數、引號和反斜槓轉義，但不能使用管道、重定向、`&&`、`;`、反引號或環境變數展開。需要這些行為時，把它們放進 wrapper script，再把該腳本作為命令填寫。

### 參數的排列順序

命令欄位裡填寫的內容會緊跟在執行檔之後，排在 Multica 追加的參數之前：

```text
<你的命令> <你的固定參數> <Multica 的協議參數> <Agent 的自定義參數>
```

帶子命令的 wrapper 正是依靠這個順序才能工作。如果命令是 `ccms start q36`，工具會先看到 `start q36`，在 Multica 的 `-p` 等參數到達之前完成子命令選擇——這類 wrapper 只接受這一種順序。

此前這裡填寫的參數是追加在最後的。多數 flag 形式的命令在兩種位置下解析結果相同，但並非全部——如果某個命令區分全局 flag 和子命令 flag，它就會在意 flag 的位置。如果你已經設定了帶固定參數的 profile，升級後請發起一次執行，確認它仍能正常啟動。

另有兩點需要注意：

- **衝突時以 Multica 的值為準。** 如果固定參數設定了 Multica 也會設定的 flag，Multica 的值排在後面並最終生效。最典型的是：在 Agent 上選擇的模型會覆蓋 profile 裡固定的 `--model`。若要為所有人固定模型，請把 Agent 的模型欄位留空。
- **協議關鍵 flag 會被忽略。** `-p`、`--output-format`、`--input-format`、`--permission-mode` 以及其他協議族的對應 flag 會從固定參數中被剔除，因為覆蓋它們會切斷 daemon 與工具之間的通信。子命令和其他位置參數始終原樣傳遞。

如果 Desktop 啟動的守護程序找不到終端裡能夠執行的命令，可以為當前電腦設定絕對路徑：

```bash
multica runtime profile set-path <profile-id> --path /absolute/path/to/command
```

移除路徑覆蓋：

```bash
multica runtime profile unset-path <profile-id>
```

修改設定隻影響之後領取的執行。刪除設定前，需要先處理仍綁定在對應執行環境上的活動 Agent。只刪除某臺電腦上的執行環境實例並不會刪除設定，執行中的守護程序還會重新註冊它。

## 執行環境離線的排查

按以下順序檢查：

1. 執行 `multica daemon status`，確認守護程序已經啟動。
2. 執行 `multica daemon logs -f`，查看登入、網路或工具檢測錯誤。
3. 在同一執行環境中執行 `command -v <工具命令>`，確認守護程序能夠找到它。
4. 開啟 Multica 的**執行環境**頁面，檢查目標電腦和對應的 AI 編程工具是否顯示在線。
5. 工具剛安裝、路徑剛修改或設定剛更新時，執行 `multica daemon restart`。

仍未解決時，參見[故障排查](/troubleshooting)。
