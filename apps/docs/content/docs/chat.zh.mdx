對話適合還沒有形成明確任務的工作：梳理想法、查詢工作區情況、討論方案、問一個不屬於任何任務的問題，或者先讓 Agent 完成一個小任務。

對話（Chat）是你和[Agent](/agents)的一對一溝通，不在[任務](/issues)看板上。整段對話**完全私人**，[工作區](/workspaces)裡的其他人，包括 admin，都看不到。

對話**不繫結任務**。Agent 不盯著你的看板，不會自動收到任務的描述和留言，也不會自己把對話變成任務。它仍可以在權限範圍內用 Multica CLI 查詢工作區、專案、任務和 skill；你明確要求時，它會以你的工作區權限代你操作，例如建一個任務。

Chat 也可以附帶背景資訊。點選輸入框左下角的 **+**，選擇**專案脈絡**，將[專案](/projects)加入聊天；Agent 執行時會取得該專案的描述、儲存庫和其他資源。

## 開始對話

<Steps>
<Step>

開啟側邊欄中的**聊天**。

</Step>
<Step>

點選新建，選擇一個你有權執行的 Agent。

</Step>
<Step>

輸入訊息，也可以附加圖片或檔案。

</Step>
<Step>

傳送後，Multica 會為這條訊息建立一次執行，回覆回到目前對話。

</Step>

執行環境離線時，訊息會等到環境重新上線。Agent 遭封存，或你失去執行權限後，就無法再傳送新訊息。

第一條訊息傳送前，對話頁會顯示所選 Agent 設定的最多三個建議。選擇一條只會把完整提示詞填進輸入框，不會傳送，你可以先改再發。沒有設定建議的 Agent 顯示通用示例。

Agent 回覆後，下方有時會給出**後續提問**。後續提問點選後直接傳送。

## 在任意頁面開啟懸浮聊天窗

不用離開目前頁面也能聊天。工作區頁面可以在懸浮聊天窗裡開啟對話。窗裡的對話和**聊天**頁是同一份，在哪邊開始的對話，另一邊都能接著聊。

視窗較寬時，快捷聊天在應用底部狀態列的右端：

- 點**問 Multica**開始新對話。
- Agent 正在處理、有未讀回覆，或者你在懸浮窗裡開啟過的對話，會在狀態列裡顯示成一個標籤。標籤上轉圈表示 Agent 正在回覆，彩色圓點表示有未讀回覆；游標停留能看到對話標題和狀態。點標籤開啟對應對話，再點一次收起懸浮窗。放不下的標籤收進 **+N** 選單。
- 游標停留標籤後點 **×** 可以關掉它。這段對話有新訊息，或者你再次開啟它時，標籤會回來。
- 狀態列最右邊的**對話歷史**列出最近的對話，同樣標出執行中和未讀。點一條開啟它，或者點**全部對話**進入**聊天**頁。
- 懸浮窗開啟在你點的按鈕或標籤上方。

視窗較窄時沒有狀態列，改由右下角的圓形聊天按鈕開啟懸浮窗。Agent 正在回覆時，這個按鈕會輕輕跳動；游標停留提示會說明有對話正在執行或有未讀回覆。

- 按 `⌘J`（Windows / Linux 上是 `Ctrl+J`）開啟或收起懸浮窗，開啟後游標直接落在輸入框裡。游標在輸入框裡時也能用這個鍵收起。按鍵可以在**設定 → 快捷鍵**裡改，見[搜尋、快捷鍵與偏好設定](/shortcuts)。
- 按 `⇧⌘J`（Windows / Linux 上是 `Ctrl+Shift+J`）則直接開始新對話，和點**問 Multica**一樣；`⌘J` 開啟的是上次那段對話。停在新對話上再按一次會收起懸浮窗。
- 懸浮窗可以拖動邊緣調整大小，也可以展開或最小化。
- **聊天**頁本身的狀態列裡沒有快捷聊天，也不顯示圓形按鈕，`⌘J` 和 `⇧⌘J` 在這裡也不起作用：整頁顯示的已經是同一段對話。

不需要懸浮窗時，在**設定 → 偏好設定 → 留言與聊天**裡關閉**懸浮聊天窗**。之後狀態列裡不再有快捷聊天，也不再顯示圓形按鈕，只能從側邊欄進入聊天。這個開關只對目前裝置生效。

## 對話與任務的選擇

| 需要 | 更適合 |
|---|---|
| 快速提問、討論做法或處理私人草稿 | **Chat** |
| 需要明確負責人、狀態、優先順序和交付成果 | **任務** |
| 需要團隊成員檢視背景並接續討論 | **任務** |
| 暫時查詢工作區資訊，不需要留下工作紀錄 | **Chat** |

在 Multica 中建立的直接對話只有建立者能讀取，其他成員和管理員都不能。需要團隊一起看的結論，整理到任務、專案說明或 skill 中。

## 多輪上下文

系統會盡量在 AI 程式開發工具中延續同一個工作階段，因此後續訊息不必重複先前內容。Multica 會儲存工作階段 ID，並將後續執行交給能存取該工作階段的執行環境。

如果本機工作階段已不存在、無法延續脈絡，或不應沿用上次的錯誤，執行環境就會開啟新的工作階段。聊天中的歷史訊息仍會保留。

## 檢視和停止執行

Agent 執行時，介面會顯示目前階段和工具活動。展開**檢視詳細資訊**可以檢視完整執行過程。

需要中斷時，點選輸入框旁的停止按鈕（輸入框為空時顯示）。已經返回到對話中的內容會保留。

如果 Agent 還沒輸出任何內容就被停下，你剛發的那條訊息會從對話裡撤回，連同附件放回輸入框，改一改就能重發。停止有時要過一會兒才真正完成；這期間重新整理頁面或關掉視窗也不會丟，下次開啟這段對話時，訊息會回到輸入框。輸入框裡已經有別的草稿時，會等你清空後再放回。

## 回覆還沒結束時繼續發訊息

Agent 還在回覆時，可以接著輸入下一條。輸入框有內容時，傳送按鈕變成**排隊傳送**。排隊的訊息不會打斷目前回覆，而是顯示在輸入框上方的佇列裡，等目前回覆結束後按順序處理。

| 操作 | 結果 |
|---|---|
| **引導** | 把這條訊息提到隊首，並停止目前回覆。已經寫出的內容留在對話裡，Agent 緊接著處理這條訊息。 |
| 刪除（垃圾桶圖示） | 從佇列裡移除這條訊息，它不會發給 Agent。 |
| **⋯ → 編輯排隊訊息** | 把訊息連同附件放回輸入框，改完重新傳送。 |
| **⋯ → 全部清空** | 撤回佇列裡的所有訊息，目前回覆照常進行。 |

目前回覆還沒真正開始（例如還在等runtime領取）時，**引導**按鈕不可用；失去這名 Agent 的執行權限後也不能引導。

<Callout>
這裡的**引導**會先停掉目前回覆。任務留言裡的[插話到目前執行](/mentioning-agents#給正在執行的Agent插話)不一樣：它不中斷執行，Agent 在目前步驟結束後讀到插話，然後繼續原來的任務。

## 整理對話列表

Chat 支援重新命名、釘選、封存和刪除：

- **釘選**會將常用聊天固定在清單前方；
- **封存**會將聊天移至"已封存"並設為唯讀；
- **取消封存**後即可繼續傳送訊息；
- **刪除**會永久移除聊天及其中的訊息。

若 Chat 繫結外部管道（例如 Slack），封存時會解除繫結；取消封存不會重新繫結，必須再次連結。

<Callout type="warning">
刪除 Chat 無法復原，並會停止其中尚未完成的執行。暫時不需要時，請改用封存。
</Callout>
