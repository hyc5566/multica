收件匣會整理與你相關的工作動態。它不是完整的活動紀錄，而是提醒你哪些變更需要留意；完整脈絡仍保留在對應任務中。

## 收件匣會顯示哪些通知

常見通知包括：

- 任務指派給你，或從你名下移除；
- 你訂閱的任務有新留言，或負責人、狀態、優先順序或日期變更；
- 有人在任務說明或留言中 @提及你；
- 你建立的任務或留言收到表情反應；
- 你訂閱的任務中，Agent 執行失敗；
- Agent 建立任務的流程完成或失敗；
- 你訂閱的自動化建立新任務，或因連續失敗而暫停。

你自己的操作不會通知你。同一任務的多則通知會合併為一筆；開啟後可查看任務最近的變更。

## 自動訂閱的來源

以下使用者會自動訂閱任務：

- 任務建立者；
- 新任負責人；
- 發表留言的人；
- 在任務說明中被新增 @提及的人；
- 自動化中預先設定的訂閱者。

變更負責人不會取消既有訂閱。你可以隨時在任務頁面訂閱或取消訂閱；取消後，一般更新不會再出現在收件匣，但直接 @提及你仍會個別通知。

<Callout type="info">
子任務狀態變更時，也會通知父任務的訂閱者。子任務的留言、優先順序和日期變更則不會向上通知父任務。
</Callout>

## Agent 不使用收件匣

收件匣只供工作區成員使用。即使 Agent 是任務負責人或訂閱者，也不會讀取收件匣通知。

在留言中 @提及 Agent、將任務指派給 Agent 或觸發自動化，都會直接建立一次執行，而不是傳送通知給 Agent。`@all` 也只會通知成員。

## 處理通知

選取通知會將它標示為已讀。處理完畢後可以封存；封存不會變更或刪除對應任務。任務進入交由人員接手的狀態後——`in_review`、`started` 分類中的自訂狀態，或 `done`、`closed` 分類中的任何狀態——該任務的"執行失敗"通知會自動封存。`blocked` 是例外：雖然工作已交還給人員處理，但仍卡在阻礙中，因此先前的失敗通知仍值得查看。

在通知上按右鍵，可以選擇**標示為已讀**、**標示為未讀**或**封存**（在"已封存"檢視中則是**取消封存**）。標示為未讀表示"我看過了，但還沒處理完"：通知會重新標示為未讀，未讀數也會增加；即使通知仍開啟，也會維持未讀，直到你之後再次開啟它。已封存通知會保留已讀狀態，還原後也會維持原狀。

從收件匣選單還可以：

- 將全部通知標示為已讀；
- 封存全部通知，或只封存已讀通知；
- 封存 `done` 或 `cancelled` 任務的通知；
- 開啟"已封存"並還原通知。

從收件匣底部開啟**已封存**，向下捲動可載入較早的通知。篩選條件會套用至所有封存紀錄，包括尚未載入的紀錄。

## 調整通知類型

前往**設定 → 通知**，可以分別開啟或關閉以下通知：

- 指派；
- 狀態變更；
- 留言；
- 提及；
- 優先順序與日期；
- Agent 活動。

關閉某一類通知後，相關變更仍會記錄在任務中，只是不會再送到收件匣。表情反應、快速建立結果和自動化暫停等少數通知不受這六組設定控制，仍會照常送達。系統通知和瀏覽器通知只會控制桌面橫幅，不會影響收件匣本身。
