收件匣彙總與你有關的工作動態，提醒你哪裡出現了需要關注的變化。它不是完整的活動日誌，前因後果仍在對應的任務裡。

## 在哪裡找到收件匣

收件匣是**工作**面板裡的一個分割槽，排在固定之後、檢視和專案之前；沒有固定項時，它就是第一個分割槽。分割槽標題欄有三個標籤：**收件匣**、**已延後**和**已歸檔**。只有當前標籤顯示名稱，另外兩個顯示為圖示，懸停可看到名稱。再次點選當前標籤可以摺疊這個分割槽。未讀數顯示在**收件匣**旁，也會以角標顯示在應用側欄的**工作**上；右鍵點選**工作**可以**全部標為已讀**。

**收件匣**標籤每個任務佔一行，最新的在前，已讀和未讀都在。每行顯示任務狀態、標題和時間；未讀的行帶一個圓點。在顯示設定裡關掉**緊湊顯示**，每行會多出第二行，顯示誰做了什麼。滑鼠懸停在某行上會彈出卡片，顯示完整標題和評論內容，並提供**開啟**、**標為已讀**（已讀時提供**標為未讀**）、**延後**和**歸檔**。右鍵點選某行可**在新標籤頁開啟**、**標為已讀 / 未讀**、**歸檔**（已歸檔標籤下為**取消歸檔**）、**取消訂閱並歸檔**，或永久**刪除**通知。

在手機上，工作面板收在抽屜裡。其中的收件匣分割槽末尾有**全部通知**，點開是收件匣頁面，帶自己的列表、同樣的三個標籤和篩選。

## 收件匣的內容

常見通知包括：

- 任務分配給你，或從你名下移走；
- 你訂閱的任務出現新評論，或負責人、優先級和日期發生變化（別人的任務預設只推送關鍵更新，見下文）；
- 你訂閱的任務狀態發生變化，前提是你打開了預設關閉的**狀態變更**；
- 有人在任務描述或評論中 @你；
- 你建立的任務或評論收到表情回應；
- 你訂閱的任務中，Agent運行失敗；
- 你訂閱的項目里新建了任務；
- 分配給你的任務的所有[前置阻塞](/issues#relations)全部結束（**等待的任務已結束**）；
- [透過Agent建立任務](/issues#透過Agent建立)的操作完成或失敗；
- 你訂閱的自動化建立了新任務，或自動化因連續失敗被暫停。

自己的操作不會通知自己。同一任務的多條通知會合併成一行，打開後可查看這條任務最近的變化。

## 自動訂閱的來源

以下使用者會自動訂閱任務：

- 任務建立者；
- 新任負責人；
- 發表留言的人；
- 在任務說明中被新增 @提及的人；
- 自動化中預先設定的訂閱者。

變更負責人不會取消既有訂閱。你可以隨時在任務頁面訂閱或取消訂閱；取消後，一般更新不會再出現在收件匣，但直接 @提及你仍會個別通知。

<Callout type="info">
打開**狀態變更**後，子任務的狀態變化也會通知父任務的訂閱者。子任務的評論、優先級和日期變化不會向父任務冒泡。
</Callout>

## 別人的任務

任務分配給別人或別人的Agent時，你因為建立、評論或被 @ 而自動產生的訂閱，預設只推送關鍵更新：@你、回復你參與的討論，以及（打開**狀態變更**時）`in_review`、`blocked`、`done` 等需要人來看的狀態。日常評論和其他變化留在任務里。你手動訂閱的任務、通過項目訂閱的任務，以及分配給你或你的Agent的任務，仍會收到你打開的所有通知類型。

任務頁面會把這類訂閱標為**僅關鍵更新**。點開後選**接收全部動態**，會把它變為對這個任務的手動訂閱；之後這個任務無法再退回僅關鍵更新，只能取消訂閱。**修改預設設置**會打開**設置 → 通知**，把**你訂閱的任務**分組頂部的**別人的任務**改為**全部動態**，所有這類任務都會推送全部動態。

## Agent與收件匣

收件匣通知屬於工作區成員。只有服務端驗證運行的上游觸發人就是運行環境所有者時，Agent才能讀取和處理該所有者的通知。這個身份會沿Agent調用鏈繼承。這條規則覆蓋收件匣的所有操作：活躍列表、歸檔、稍後提醒列表、未讀數，以及所有修改。由他人觸發、沒有可驗證觸發人的運行，以及沒有任務綁定的雲節點憑證，都會被拒絕。Agent讀取的未讀數只包含運行所在的工作區，不包含所有者的其他工作區。只有人可以刪除通知。Agent做的每次修改都會在服務端留下記錄，寫明是哪個Agent、哪次運行、代哪個人操作。

在留言中 @Agent、把任務分配給Agent或觸發自動化，都會直接建立一次執行，不會給Agent留通知。`@all` 也只通知成員。

## 用 CLI 管理

復用現有 CLI 登錄讀取和處理通知。列出通知不會將其標為已讀：

```sh
multica inbox count
multica inbox list --unread --since 1d --output json
multica inbox list --issue MUL-123
multica inbox list --archived     # 或 --snoozed
```

每行顯示通知 ID、任務編號、類型、來自誰、標題，以及評論或變更的簡短摘要。`--unread`、`--issue`（任務編號或 UUID）、`--since`（RFC 3339 時間，或 `2h`、`1d`、`1w` 這樣的時長）、`--project` 和 `--type` 用於篩選列表。`--archived` 會逐頁讀取整個歸檔，早已歸檔的任務也能找到並恢復。`--project` 接受完整 UUID 或唯一 ID 前綴，包括 `multica project list` 顯示的短 ID；無匹配或前綴有歧義時會報錯。表格還保留任務、評論和項目 ID，摘要會截短；`--output json` 帶完整摘要。

用列表裡的 ID 處理通知：

```sh
multica inbox read <id>...                      # unread <id>... 撤銷
multica inbox read --issue MUL-123              # 一個任務上的全部通知
multica inbox archive <id>...                   # unarchive <id>... 恢復
multica inbox snooze <id>... --until tomorrow   # RFC 3339、30m、3h、1d、1w；unsnooze <id>... 結束
```

與應用里一樣，標為已讀、歸檔或稍後提醒一條任務通知，會作用於整個任務；標為未讀只改變這一條。某個 ID 失敗不會中斷其餘 ID，命令會列出失敗的條目並以非零狀態退出。

批量操作與收件匣菜單一致：`multica inbox read --all`，以及帶 `--all`、`--read`（最新通知已讀的任務）或 `--completed`（處於 `done` 或 `closed` 類狀態的任務）的 `multica inbox archive`。它們需要 `--yes`，手動執行環境也可以輸入確認；除 `--completed` 外，稍後提醒中的任務不受影響：與應用一致，`--completed` 也會歸檔稍後提醒中已完成或已關閉的任務，並結束稍後提醒。每次修改都會輸出實際改動的通知條數，包括整個任務上的通知；本來就是該狀態的記為 0。`--output json` 返回同一計數，以及每個 ID 的結果。CLI 不能刪除通知。

獲授權的Agent運行在這些操作中都使用任務憑證，不會回退到人的登錄憑證。

## 處理通知

點選一行會在收件匣頁面開啟這條通知，並定位到它所指的評論。所有通知都在這裡開啟，包括沒有對應任務的通知，例如自動化暫停和快速建立結果。通知開著時這一行保持高亮，再點一次會重新定位到那裡。開啟通知會把它標為已讀，但這一行仍留在列表裡。任務頁頭裡的**在任務頁開啟**（↗）會在單獨的任務頁開啟這個任務，那裡不顯示收件匣操作；手機上點頁頭左側的按鈕可開啟抽屜切換到別的通知，返回則回到開啟它的列表。

評論框上方居中浮著一組操作，給出通常能處理掉這條通知的操作：先是任務本身的，再是通知的，快捷鍵顯示在各自旁邊：

- **狀態**、**負責人**和**快捷操作**直接修改任務本身，和屬性裡一樣；工作區有快捷操作時才會出現。
- **延後**（`H`）把任務移出收件匣，到你選的時間再回來，並打開下一條。詳見下方的「延後任務」。
- **歸檔**（`E`）是實心按鈕，會歸檔這條通知並開啟下一條。歸檔不會修改或刪除任務。要結束任務，請修改它的狀態；預設情況下這也會歸檔它的通知（見下文「通知何時離開收件匣」）。
- **⋯** 始終在最右邊，裡面是不常用的操作：
  - **標為未讀 / 標為已讀**（`U`）原地切換當前開啟通知的未讀或已讀狀態，不會關閉當前通知。
  - **取消訂閱並歸檔**（`⇧E`）：任務不是你的（負責人不是你，也不是你擁有的Agent）時出現。它取消你對這個任務的訂閱，歸檔這條通知並開啟下一條；之後普通動態不再進入收件匣，@你仍會通知。有子任務時，選單裡列出兩個選項：只退訂這個任務，或連同全部子任務一起退訂；按 `⇧E` 會直接開啟選單停在這兩項上。只退訂這個任務時，提示裡可以**撤銷**，訂閱會按原來的方式恢復；連同子任務一起退訂無法在這裡撤銷，可以在任務頁面重新訂閱。懸停卡片和行的右鍵選單裡也有這個操作。

視窗較窄時，先收起快捷鍵，再收起名稱；懸停按鈕可以看到兩者。

"下一條"是分割槽在當前篩選下列出的下一行，因此不用回到列表，就能把收件匣一條條處理完。按 `J` / `K` 可以在當前標籤的列表中上下切換通知而不歸檔。

在**收件匣**和**已歸檔**標籤下，分割槽 ⋯ 選單裡的**篩選**可以按通知型別、收到時間和來自誰篩選，也可以按任務的狀態和優先順序篩選。設定了篩選條件時，分割槽標題欄會顯示帶條件數的篩選按鈕，點它可以再次開啟篩選；點**清除篩選**即可恢復。

在**收件匣**標籤下，分割槽的 ⋯ 選單裡有以下批次操作：

- **全部標為已讀**；
- **歸檔全部已讀**；
- **歸檔已完成**：歸檔 `done` 或 `closed` 分類下任務的通知；
- **歸檔全部**（執行前會彈窗確認，僅歸檔活躍通知，不影響已延後的任務）。

**已歸檔**標籤列出已歸檔的通知，向下滾動可繼續載入更早的記錄。篩選覆蓋全部歸檔記錄，包括尚未載入的記錄。已歸檔的通知會保留已讀狀態，因此點行上或已開啟通知上方操作組裡的**移回收件匣**（或按 `E`）時會原樣回來。

## 延後任務

延後會把一個任務暫時移出你的收件匣，到你選的時間再回到最上面，並標為未讀。可以點任務上方操作組裡的**延後**（或按 `H`），也可以在懸停收件匣行時點歸檔旁邊的按鈕，或在懸停卡片裡點 **延後**。可選 **1 小時**、**3 小時**、**1 天**、**3 天**、**1 周**，或點 **選擇日期和時間…** 選一年內的任意時間。按天延後時保留當前的鐘點；在 22:00 到 6:00 之間延後的，會在早上 9:00 回來。延後後的提示裡可以撤銷（`Z`）；如果是改了時間，撤銷會恢復原來的時間。

任務延後期間：

- 它的新通知會跟著一起等，不計入未讀角標。回來時，這一行會顯示 **延後到期** 以及期間有多少條動態；
- 有人點名 @ 你、它被指派給你、執行失敗、全部子任務完成，或全部前置阻塞結束時，它會提前回來。`@all` 提及不會喚醒它；
- **全部標為已讀** 和各種全部歸檔操作會跳過它。歸檔它會結束延後；**自動歸檔我處理過的任務**包含完成（預設包含）時，你自己完成這個任務也一樣；
- 直接開啟這個任務的任務頁不會把它標為已讀，也不會結束延後。從**已延後**標籤開啟時，操作組會顯示它何時回來，點這個時間可以讓它現在回來（`H`）或換個時間。

延後隻影響你自己的收件匣。所有延後的任務都在**已延後**標籤裡，點每行的按鈕可以讓它現在回來。

如果**已延後**標籤無法載入，可以點選 **重試**。重新整理失敗時，已載入的任務會繼續顯示。

## 通知何時離開收件匣

通知不會因為已讀而離開收件匣。只有以下幾種情況，一行才會移出：

- 你手動歸檔它：在它所在的行、懸停卡片、任務上方的操作組，或透過批次操作；
- 你延後了它的任務。這是暫時的：到你選的時間，或有需要你處理的通知時，它會回來。見上方的「延後任務」；
- 你親自處理了它的任務，按**設定 → 通知**裡**自動歸檔我處理過的任務**的選擇來算。預設的**完成或觸發Agent時**包括：把任務改為 `done` 或 `closed` 分類下的狀態，以及任何實際觸發了Agent執行的操作——觸發Agent的評論、快捷操作或插話（steer），在非 `backlog` 狀態下指派給Agent或小隊，把已指派給Agent或小隊的任務從 `backlog` 推進到活躍狀態（包括 `todo`），進入帶Agent處理者的工作流列，重新執行任務，或手動觸發喚醒。沒有喚醒Agent的整理動作（比如把未指派的任務從 `backlog` 改到 `todo`、在 `backlog` 中先指派Agent、取消指派、發 `/note` 備註、取消勾選觸發，或因執行環境不可用被攔截）不會歸檔。**完成任務時**只算 `done` 和 `closed`，**從不**會關掉自動歸檔，**自定義**可以逐項勾選，包括預設不算的回覆、推進狀態、轉交以及改優先順序、改專案、改日期和改標籤。只歸檔你自己在該任務上的通知，無論是否已讀。別人或Agent做同樣的操作時，通知會留在你的收件匣裡，你仍能看到這個變化；
- 它是"運行失敗"通知，且任務進入交回給人的狀態：`in_review`、`started` 分類下的自定義狀態，或 `done`、`closed` 分類下的任一狀態。這會歸檔所有人在該任務上的"運行失敗"通知，不論是誰改的狀態，也不受上面的開關影響。`blocked` 例外：它同樣交回給人，但工作還卡著，之前的失敗記錄還要看。
- 你在該工作區的收件匣超過 2,000 條通知。收件匣保留最新的 2,000 條，隨後自動歸檔更早的通知，無論是否已讀。從延後中回來或從歸檔中還原的通知，按回來的時間算作新通知。已延後任務上的通知不計入，也不會被歸檔。

開啟著的視窗會立即移除已歸檔的行，但你正開啟的那一行除外。它的通知自動離開收件匣時（你在狀態裡把任務改為 `done`、觸發了Agent、別的視窗歸檔了它，或修改後不再符合分割槽的篩選），這一行會在原位保持高亮，操作組會顯示**撤銷歸檔**（`Z`），點它讓通知回來；懸停它可以看到歸檔原因和之後會怎樣，比如"已改為進行中 · 有新動態時會回到收件匣"。觸發Agent時，任務頁頭會顯示它正在工作，側邊欄行也會原位更新直到你離開。在操作組裡改**狀態**、**負責人**或執行**快捷操作**後通知被歸檔時，這幾個操作仍留在組裡，可以接著改。**下一條**（`E`）此時是實心按鈕，開啟下一行。任務不是你的時，最右邊的 **⋯** 裡有**取消訂閱此任務**，通知本身保持不動；已延後的任務和從**已歸檔**標籤開啟的任務，操作組裡也有它。你離開之後，這一行才會移出，仍在執行中的任務會繼續顯示在**檢視 → 執行中**裡。如果這是收件匣裡的最後一條通知，就沒有**下一條**；按 `E` 會開啟已清空的收件匣。

如果是你自己把正開啟的這一行處理掉（在操作組、它所在的行、懸停卡片，或包含它的批次操作裡），會直接開啟下一行；沒有剩下的行時，會開啟收件匣頁面，顯示**收件匣已清空**：寫明你剛才的操作，可以**撤銷**（或按 `Z`）把它找回，並顯示延後中的任務數和下一條回來的時間。如果是篩選隱藏了收件匣裡的其餘通知，會改為說明還剩多少條，並提供**清除篩選，繼續處理**。返回上一頁可以回到任務。歸檔和批次操作的提示裡都可以**撤銷**：通知會回來，任務的狀態保持不變。帶**撤銷**的提示（歸檔、延後、取消訂閱都一樣）會停留 10 秒；提示還在時，按 `Z` 撤銷這次操作。

之後該任務再有新通知，會重新進入收件匣。

**設定 → 通知 → 移出收件匣**裡有**自動歸檔我處理過的任務**（**從不**、**完成任務時**、**完成或觸發Agent時**、**自定義**），並提供已歸檔通知的入口。

## 顯示與通知類型

收件匣分區標題欄的設置按鈕會打開它的顯示設置，只保存在當前設備上：

- **顯示條數**：5、10 或 20 條；其餘的收在"再顯示 N 項"里。
- **緊湊顯示**：每行只佔一行高度，預設開啟；關掉後每行多出第二行，顯示誰做了什麼。
- **未讀數量**：分區標題旁的數字。
- **在"工作"上顯示未讀數**：應用側欄里工作上的角標。

下方的**接收以下通知**可以分別開關每一類通知。它們和**設置 → 通知**里的開關是同一組，設置頁按通知到達你的方式分組：

| 分組 | 類型 |
|---|---|
| **與你直接相關** | 分配、提及、表情回應 |
| **你訂閱的任務** | 狀態變更、評論、優先級與截止日期 |
| **你訂閱的項目** | 新任務 |
| **Agent** | Agent活動（執行失敗） |

**狀態變更**預設關閉，其餘類型預設打開。關閉某一類後，不再建立這類通知，重新打開也不會補回錯過的通知；相關變化仍然保存在任務中。快速建立結果和自動化暫停等少數類型不受這些分組控制，始終投遞。系統通知和瀏覽器通知控制的是桌面橫幅，不會改變收件匣本身。

**評論**下的**包含小隊內部交接**針對隊長和Agent之間傳遞工作的評論，無論任務是指派給小隊，還是在評論裡 @ 了小隊：隊長 @ Agent或小隊派活，以及Agent向隊長回報。預設開啟；關閉後只保留寫給人的評論。@ 你或其他成員的評論、Agent對某人評論的回覆和Agent執行失敗照常通知。小隊收尾時的最終回報也會送達：Agent回報後，隊長的執行如果既沒有繼續派活、也沒有發評論就結束了，那條回報會在這時送達。狀態變化按**狀態變更**開關通知。
