把一個 Multica Agent 連接成飛書 Bot 後，團隊成員可以在飛書裡私聊它、在群裡 @ 它，也可以用 `/issue` 建立任務。對話和執行記錄仍會儲存到 Multica 工作區。

每個 Bot 只對應一個 Agent。需要在飛書中使用多個 Agent 時，分別為它們連接 Bot。

## 連接 Bot

Agent 的所有者、工作區 owner 和 admin 可以發起連接：

1. 開啟 **Agent**，選擇要接入飛書的 Agent。
2. 進入 **整合**，點擊 **綁定到飛書**。
3. 用飛書掃描二維碼並確認授權。
4. 回到 Multica。頁面顯示 **已連接到飛書** 後即可使用。


二維碼為一次性憑證，過期後重新生成即可。已經連接的 Agent 不會再次顯示掃碼入口；需要改名或調整權限時，點擊 **在飛書中管理**。

<Callout type="info">
目前只開放中國大陸版飛書的新連接入口。已有的國際版 Lark 連接仍可繼續使用和管理。
</Callout>

## 第一次使用

成員第一次給 Bot 發消息時，會收到一個帳戶綁定連結：

1. 開啟連結並登入 Multica。
2. 確認要關聯的工作區帳戶。
3. 回到飛書，再傳送一次消息。

綁定後，Multica 才能確認消息來自哪位工作區成員。非成員無法使用 Bot。

## 在飛書中交代工作

### 私聊

直接給 Bot 發消息即可。連續消息保留在同一段 Multica 對話中，Agent 的回覆也發回當前對話。

### 群聊

先把 Bot 加入群聊，再 `@Bot` 並寫下要求。Bot 只會響應明確 @ 它的消息；執行時會結合當前會話中可讀取的近期上下文。

### 建立任務

傳送：

```text
/issue 修復登入後的跳轉問題
Safari 登入成功後仍然停留在登入頁。
```

第一行作為標題，其餘內容作為描述。只傳送 `/issue` 不會建立任務；Bot 會回覆用法提示。

## 管理連接

開啟**設定 → 訊息頻道 → 飛書**可查看工作區內已連線的 Bot。工作區 owner 和 admin 可以在此中斷連線；Agent 擁有者也可以回到該 Agent 的**整合**頁面管理自己的 Bot。

斷開後，Bot 不再接收新消息，已有的對話和審計記錄不會隨之刪除。

## 自託管設定

Multica Cloud 無需額外設定。自託管部署需要先設定一個用於加密 Bot 憑據的密鑰：

```dotenv
MULTICA_LARK_SECRET_KEY=<base64 編碼的 32 字節密鑰>
```

可以這樣生成：

```bash
openssl rand -base64 32
```

重啟 API 服務後，再從 Agent 的 **整合** 頁面連接 Bot。該密鑰需要長期儲存：更換或丟失後，已有憑據無法解密，需要重新連接。

`MULTICA_LARK_HTTP_BASE_URL` 和 `MULTICA_LARK_CALLBACK_BASE_URL` 只用於代理、測試等特殊部署，正常情況下不需要設定。

## 常見問題

- **沒有綁定按鈕**：確認當前帳戶是 Agent 所有者、工作區 owner 或 admin，並檢查自託管密鑰是否已設定。
- **二維碼失效**：關閉彈窗後重新發起連接。
- **Bot 要求綁定帳戶**：開啟綁定連結並使用該工作區的 Multica 帳戶登入。
- **Bot 沒有執行**：確認 Agent 尚未封存，且使用的[執行環境](/daemon-runtimes)在線。
- **Bot 完全沒有回覆**：應用必須透過長連線推送事件；Multica 沒有 webhook 接收位址。請在飛書開發者後臺的**事件與回呼 → 事件設定**中，確認使用長連線接收事件而非請求位址、已訂閱 `im.message.receive_v1`，且包含該設定的版本已發布（企業需要審核時也必須通過）。使用請求位址的應用仍可完成綁定並顯示「已連線」，但收不到任何訊息。
