把一個 Multica Agent 連線成飛書 Bot 後，團隊成員可以在飛書裡私聊它、在群裡 @ 它，也可以用 `/issue` 建立任務。對話和執行記錄都儲存在 Multica 工作區。

每個 Bot 只對應一個 Agent。需要在飛書中使用多個 Agent 時，分別為它們連線 Bot。

## 連線 Bot

Agent 擁有者、工作區 owner 和 admin 可以發起連線：

<Steps>
<Step>
開啟 **Agent**，選擇要接入飛書的 Agent。
</Step>
<Step>
進入 **訊息渠道**，點選 **新增訊息渠道**，再選擇 **飛書**。
</Step>
<Step>
用飛書掃描二維碼並確認授權。二維碼只能用一次，過期後重新生成即可。
</Step>
<Step>
回到 Multica。繫結後頁面顯示 **等待第一條訊息**。請在飛書/Lark 中給機器人傳送訊息。**正常** 只表示本次繫結收到過有效訊息，不保證持續線上、Agent 執行成功或回覆成功。升級時，舊繫結可以依據本次繫結之後的有效工作階段歷史保留接收證明；沒有這類證據的繫結仍需等待新訊息。重新繫結會清空記錄。
</Step>
</Steps>

已經連線的 Agent 不會再次顯示掃碼入口；需要改名或調整權限時，開啟 Bot 的管理選單，點選 **在飛書中管理**。

<Callout type="info">
目前只開放中國大陸版飛書的新連線入口。已有的國際版 Lark 連線仍可繼續使用和管理。
</Callout>

## 第一次使用

成員第一次給 Bot 發訊息時，會收到一個帳號繫結連結：

<Steps>
<Step>
開啟連結並登入 Multica。
</Step>
<Step>
確認要關聯的工作區帳號。
</Step>
<Step>
回到飛書，再傳送一次訊息。
</Step>
</Steps>

Multica 靠這次繫結確認訊息來自哪位工作區成員。非成員無法使用 Bot。

## 在飛書中交代工作

### 私訊

直接給 Bot 發訊息即可。連續訊息保留在同一段 Multica 對話中，Agent 的回覆也發回目前對話。

### 群組聊天

先把 Bot 加入群聊，再 `@Bot` 並寫下要求。Bot 只響應明確 @ 它的訊息，runtime會帶上群裡最近的幾條訊息作為上下文。

無論私聊還是群聊，每次執行的提示詞還會列出所回覆訊息的飛書 ID：`chat_id`、`chat_type`、`message_id`、訊息在話題中時的話題 `thread_id`，以及傳送者的 `open_id`。這些是飛書的 ID，不是 Multica 的 ID；Agent 如果有自己的飛書訪問權限，可以用它們查到原訊息或工作階段。`open_id` 只在目前連線的 Bot 所屬應用內有效。Multica 沒有記錄到的 ID 不會出現。

### 建立任務

傳送：

```text
/issue 修复登录后的跳转问题
Safari 登录成功后仍然停留在登录页。
```

第一行作為標題，其餘內容作為描述。只傳送 `/issue` 不會建立任務；Bot 會回覆用法提示。

## 接收 Agent 生成的圖片和檔案

部署啟用附件回傳後，Agent 回覆中的文字與受支援圖片會在同一條飛書訊息中混排，圖片上傳完成後更新原訊息；檔案另發到同一工作階段。沒有正文的圖片回覆可直接傳送圖片訊息。圖片上限為 10 MB；不受支援、過大或被飛書明確拒絕的圖片會按檔案傳送，檔案上限為 30 MB。此功能需要服務端設定物件儲存，並授予飛書應用資源上傳權限。傳送失敗或無法確認送達時，附件仍保留在 Multica 的回覆中；請求重發前，請先檢查目前工作階段。

## 管理連線

開啟 **設定 → 訊息渠道**，按平臺檢視已連線的 Agent。點選 Agent，進入其詳情頁的 **訊息渠道**。Agent 所有者和工作區 owner/admin 可以在這裡開啟 Bot 的管理選單，斷開連線。

中斷連線後，Bot 不再接收新訊息，已有的對話和稽核記錄不會隨之刪除。

## 自行託管設定

Multica Cloud 無需額外設定。自行託管部署需要先設定一個用於加密 Bot 憑證的金鑰：

```dotenv
MULTICA_LARK_SECRET_KEY=<base64 编码的 32 字节密钥>
```

可以這樣產生：

```bash
openssl rand -base64 32
```

重啟 API 服務後，再從 Agent 的 **訊息渠道** 頁面連線 Bot。該金鑰需要長期儲存：更換或丟失後，已有憑據無法解密，需要重新連線。

`MULTICA_LARK_HTTP_BASE_URL` 和 `MULTICA_LARK_CALLBACK_BASE_URL` 只用於代理、測試等特殊部署，正常情況下不需要設定。

## 常見問題

- **沒有繫結按鈕**：確認目前帳號是 Agent 所有者、工作區 owner 或 admin，並檢查自託管金鑰是否已設定。
- **二維碼失效**：關閉彈窗後重新發起連線。
- **Bot 要求繫結帳號**：開啟繫結連結並使用該工作區的 Multica 帳號登入。
- **Bot 不執行**：檢查 Agent 是否已歸檔，以及它使用的[執行時](/daemon-runtimes)是否線上。
- **Bot 完全不回覆**：應用必須透過長連線推送事件，Multica 沒有 webhook 接收地址。開啟飛書開發者後臺的 **事件與回撥 → 事件設定**，確認訂閱方式是使用長連線接收事件而不是請求地址，`im.message.receive_v1` 已訂閱，並且包含該設定的版本已釋出（企業需要稽核時還要透過稽核）。配成請求地址的應用照樣能繫結、顯示 **等待第一條訊息**，但一條訊息都收不到。
