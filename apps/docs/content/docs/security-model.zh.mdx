Agent 開始執行時，常駐程式會將 AI 程式開發工具（Codex、Claude Code 等）作為子程序啟動。了解這個程序能存取哪些內容，就能掌握整個安全模型。

## 安全邊界取決於執行常駐程式的使用者

預設情況下，每次執行都擁有**執行常駐程式的作業系統使用者的完整權限**。該使用者能讀寫的檔案，這次執行都能讀寫；該使用者的憑證，這次執行都能使用；網路存取也不受限制。

Multica 不保證提供檔案系統沙箱。目前只有一個範圍很窄的例外：在 Windows 上明確啟用 Codex 原生沙箱。但哪些平台和設定組合實際會啟用沙箱屬於相容性細節，可能隨工具版本改變。請一律將每次執行視為沒有沙箱，並在常駐程式之外建立安全邊界。

<Callout type="warning">
Multica 不會替你隔離檔案系統。如果常駐程式以你的個人帳號執行，執行工作就能讀取你的 SSH 私鑰、修改 shell 設定或刪除檔案。隔離必須來自你為常駐程式設定的外部邊界。
</Callout>

這是刻意的設計。Agent 需要安裝相依套件、執行建置、使用你的雲端 CLI；這些工具都假設自己面對一般的 home 目錄。不完整的檔案系統沙箱會以很難排查的方式妨礙工作，例如工具顯示"尚未登入"，或悄悄使用錯誤的帳號；同時，它仍無法保護最重要的內容：阻止執行工作讀取憑證並透過網路傳送出去。

所以 Multica 不假裝自己是邊界。請在它外面加一層。

## 推薦部署方式

以下依隔離程度由低至高排列，請選擇適合你基礎架構的方式：

1. **專用 Unix 使用者。** 建立 `multica` 使用者，只提供 Agent 需要的儲存庫和憑證，並以該使用者執行常駐程式。你的個人帳號不會受影響。
2. **容器。** 在容器中執行常駐程式，只掛載 Agent 需要的目錄和金鑰。
3. **虛擬機器。** 隔離程度最高，但需要額外準備一台電腦。

無論選擇哪種方式，都應將該環境可存取的憑證視為 Agent 可能使用的憑證：盡量縮小 token 權限範圍，優先使用專用部署金鑰而非個人 SSH 私鑰，也不要將無關的正式環境憑證留在該使用者的 home 目錄中。

## Multica 確實隔離的部分

以下隔離確實存在，但用途是增加便利性和縮小影響範圍，**不能**防止執行工作主動突破隔離：

- **每次執行使用獨立工作目錄。** 每次執行在 `~/multica_workspaces/` 下有自己的 workdir，因此同時進行的工作不會修改同一份 checkout。
- **每次執行使用獨立的 Agent 狀態。** Codex 執行會使用執行專屬的 `CODEX_HOME` 儲存設定、工作階段和 skill，不會污染你的 `~/.codex/`。
- **執行專屬的 API token。** 交給執行工作的 `MULTICA_TOKEN` 由伺服器綁定至該 Agent 和該次執行，因此無法透過 Multica API 冒用你或其他 Agent 的身分。

## 不能當作安全邊界的項目

- **程式開發工具內建的沙箱與核准設定。** Multica 會在無人值守的情況下執行 Agent，因此會自動回應核准要求。預設情況下，檔案系統沙箱也處於關閉狀態：Codex 使用 `sandbox_mode = "danger-full-access"`，Claude Code 使用 `--permission-mode bypassPermissions`。例外是 Windows：如果你明確設定 Codex 原生沙箱（`windows.sandbox = "unelevated"` 或 `"elevated"`），Multica 會遵守這項選擇，讓這些執行使用 `workspace-write`。適用時可以啟用，但這只涵蓋一個平台上的一種工具，不會改變你應如何限制常駐程式使用者的權限。
- **你的 `HOME` 目錄結構。** 執行工作會繼承常駐程式使用者實際使用的 `HOME` 和 `XDG_*` 變數，因此 `gh`、`aws`、`kubectl`、`gcloud`、`glab` 等主機 CLI 在執行工作中的行為會和你在 shell 中相同。這也表示該 home 目錄中的所有內容都能被存取。

<Callout>
在 Linux 上，Codex 過去會在 `workspace-write` 沙箱中執行，並使用重新導向的執行專屬 `HOME`。這套機制已移除：它會讓主機 CLI 在執行工作中無法使用既有設定，而且它只限制寫入，從未能阻止執行工作讀取並外傳憑證。現在 Linux 的預設行為與 macOS、Windows 相同。
</Callout>

## 查看執行工作使用的模式

執行工作以無沙箱方式啟動時，常駐程式會記錄 warn 等級的日誌：

```bash
multica daemon logs --lines 200 | grep "codex sandbox"
```

要確認 Codex 實際使用的設定，可以查看該次執行的 `CODEX_HOME` 中 `config.toml` 的受管理區塊。`# BEGIN multica-managed` 和 `# END multica-managed` 之間的內容由常駐程式在每次執行時寫入。
