## 連線 Bot

智慧體所有者或工作區 owner/admin 可以把智慧體接入釘釘。一個智慧體對應一個釘釘 Bot。

<Steps>
<Step>

### 建立 Stream 模式機器人 [#1-建立-stream-模式機器人]

1. 在[釘釘開放平臺](https://open-dev.dingtalk.com)建立一個**企業內部應用**。
2. 開啟機器人能力，其中**訊息接收模式**設為 **Stream 模式**。

</Step>
<Step>

### 給機器人授權 [#2-給機器人授權]

預設已新增"機器人發訊息許可權"（`qyapi_robot_sendmsg`）。如需在 Multica 平臺顯示 Bot 名稱，需手動新增"釘群基礎資訊管理許可權"（`qyapi_chat_manage`）。

</Step>
<Step>

### 獲取應用憑證 [#3-獲取應用憑證]

進入**憑證與基礎資訊**頁面，複製 **Client ID（AppKey）** 和 **Client Secret（AppSecret）**。

</Step>
<Step>

### 把Agent接入釘釘 [#4-把Agent接入釘釘]

1. 回到 Multica，開啟 **智慧體 → _你的智慧體_ → 訊息渠道**。
2. 點選 **新增訊息渠道**，再選擇 **釘釘**。
3. 填入 **AppKey** 和 **AppSecret** 後提交。

</Step>
<Step>

### 關聯釘釘帳號與 Multica 平臺帳號 [#5-關聯釘釘帳號與-multica-平臺帳號]

在釘釘上跟 Bot 私聊，或者在群裡 @ Bot，觸發一次關聯請求。Bot 會在私聊裡發來一個連結（有效期約 15 分鐘），點選後看到連線成功的提示即完成關聯。

</Step>
</Steps>

## 在釘釘中交代工作 [#在釘釘中給Agent交代工作]

### 私訊

直接給 Bot 發訊息即可。Agent處理完成後，把結果回覆到私聊裡。

### 群組聊天

把 Bot 加入釘群，再傳送 `@your-bot <消息>`。每次追問都要重新 @，Bot 只處理 @ 它的訊息。

### 傳送圖片

私訊和群組聊天都支援圖文混排訊息，圖片支援 PNG、JPEG、GIF、WebP 和 BMP；每則訊息最多 4 張，每張不超過 10 MB。目前不支援檔案和語音訊息。

群聊中的圖文混排訊息裡，@ Bot 產生的文字也會作為訊息內容發給Agent。要去掉其中的 Bot 名稱，需新增"釘群基礎資訊管理許可權"（`qyapi_chat_manage`）。

### 引用訊息繼續追問

使用釘釘的引用功能選取一則訊息，再輸入本輪內容；群組聊天中仍需 @ Bot。Multica 會把釘釘回呼提供的、受支援的引用內容放在本輪訊息前，作為 Agent 的上下文。引用中的 `/issue`、`/new` 或 `/clear` 只是引用內容，不會作為本輪指令執行。

### 訊息處理回饋

Multica 收到釘釘訊息後，會嘗試在原訊息上新增釘釘的 `收到` 表情，表示訊息已交給Agent；Agent處理完成、回覆成功發到釘釘後，`收到` 換成 `Done`；任務被取消時，撤回 `收到` 表情。

表情回饋依賴釘釘介面，不保證即時更新。判斷結果時請結合 Bot 回覆和 Multica 中的執行記錄。

### 使用 `/issue` 建立任務

傳送 `/issue <标题>` 或者 `/issue <标题>{换行}<详细描述>`，會建立一個新 Multica 任務，並自動指派給這個 Bot 繫結的Agent。同一條訊息裡的圖片會作為附件加到該任務中。和普通訊息不同，`/issue` 指令不會在 Multica 的[對話](/chat)中留下記錄。

### 使用 `/new` 新建 Chat

傳送 `/new` 會建立一個新的空 Multica Chat，後續釘釘訊息會路由到新 Chat。傳送 `/new <消息>` 會建立新 Chat，並把訊息作為第一輪。之前的 Chat 仍儲存在 Multica 中，可以繼續使用。

### 使用 `/clear` 清空目前上下文

傳送 `/clear` 會保留目前 Multica Chat，並把新的 Agent 可見上下文應用到下一則訊息。傳送 `/clear <消息>` 會把訊息作為邊界後的第一輪。完整 Chat 歷史仍會顯示在 Multica 中。

## 管理連線

- 在**智慧體 → _你的智慧體_ → 訊息渠道**頁面，智慧體所有者、工作區 owner/admin 可以在此連線釘釘，或者斷開連線。連線上釘釘後，這裡會顯示 Bot 名稱和已成功處理過訊息的釘群，以及 Bot 在釘群內的活躍狀態資料，有智慧體讀許可權的工作區成員都能看到這些資訊。最近 90 天沒有成功處理訊息的群會歸入**長期未活躍**，展開時再載入。
- **設定 → 訊息渠道** 按平臺列出你有讀許可權的已連線智慧體。點選智慧體，進入其 **訊息渠道**，檢視 Bot 的群活動或管理連線。斷開後 Bot 停止接收訊息，安裝記錄仍會保留用於審計。工作區 owner/admin 還可以忘記某個群。忘記只會從列表中移除該群，不會刪除對話和訊息。如果已關聯釘釘帳號的工作區成員以後在該群再次 @ Bot，且 Multica 成功接收這條訊息，群會重新出現。


## 自託管設定 [#自部署設定]

Multica Cloud 使用者可跳過本節。自行託管部署需要先設定一個用於加密釘釘 `AppSecret` 的金鑰：

```dotenv
MULTICA_DINGTALK_SECRET_KEY=<base64-encoded 32-byte key>
```

可以這樣產生：

```bash
openssl rand -base64 32
```

重新啟動 API 服務後，再連線釘釘。該金鑰需要長期儲存：更換或丟失後，已有 token 無法解密，需要重新連線。

帳號繫結連結使用 `MULTICA_APP_URL`，未設定時回退到 `FRONTEND_ORIGIN`；它需要指向成員可以存取的 Multica 位址。
