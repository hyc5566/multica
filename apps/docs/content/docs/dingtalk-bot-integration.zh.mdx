把[Agent](/agents)接入釘釘後，Agent 所在工作區的成員可以私聊 Bot、在群裡 @ Bot，或用 `/issue` 指令直接建立 Multica [任務](/issues)。對話和執行記錄會儲存到 Multica 工作區。

<Callout type="info">
釘釘整合[由社區維護](/community-maintained)，不提供官方支援 SLA。遇到問題請提交到 [GitHub 任務](https://github.com/multica-ai/multica/issues)。
</Callout>


## 連接 Bot

Agent 建立者或工作區 owner/admin 可以將 Agent 接入釘釘，Agent 跟釘釘 Bot 是 1:1 的連接關係。

## 1. 建立 Stream 模式機器人

1. 在[釘釘開放平臺](https://open-dev.dingtalk.com)建立一個**企業內部應用**。
2. 開啟機器人能力，其中**消息接收模式**設為 **Stream 模式**。

## 2. 給機器人授權

預設已新增“機器人發消息權限”（`qyapi_robot_sendmsg`）。如需在 Multica 平臺顯示 Bot 名稱，需手動新增“釘群基礎資訊管理權限”（`qyapi_chat_manage`）。

## 3. 獲取應用憑證

進入**憑證與基礎資訊**頁面，複製 **Client ID（AppKey）** 和 **Client Secret（AppSecret）**。

## 4. 把 Agent 接入釘釘

1. 回到 Multica，開啟 **Agent → _你的 Agent_ → 能力 → 整合**。
2. 點擊**連接釘釘**。
3. 填入 **AppKey** 和 **AppSecret** 後提交。

## 5. 關聯釘釘帳戶與 Multica 平臺帳戶

在釘釘上跟 Bot 私聊，或者在群裡 @ Bot，觸發一次關聯請求，你會在 Bot 私聊對話框中收到一個連結（有效期約 15 分鐘），點擊連結後看到連接成功的提示即大功告成。


## 在釘釘中給 Agent 交代工作

### 私聊

直接給 Bot 發消息即可。Agent 處理完任務後，會將結果回覆至私聊對話框中。

### 群聊

把 Bot 加入釘群，再傳送 `@your-bot <消息>`。每次追問都要重新 @，Bot 只處理 @ 它的消息。

### 傳送圖片

私聊和群聊都支援圖文混排消息，圖片支援 PNG、JPEG、GIF、WebP 和 BMP；每條消息最多 4 張，每張不超過 10 MB。暫不支援檔案和語音消息。

注意，群聊中的圖文混排消息，@ Bot 產生的內容也會作為消息內容的一部分傳送給 Agent，如果想精準剔除掉 Bot 名稱，需新增“釘群基礎資訊管理權限”（`qyapi_chat_manage`）。

### 引用消息繼續追問

使用釘釘的引用功能選中一條消息，再輸入本輪內容；群聊中仍需 @ Bot。Multica 會把釘釘回調提供的、受支援的引用內容放在本輪消息前，作為 Agent 的上下文。引用中的 `/issue`、`/new` 或 `/clear` 只是引用內容，不會作為本輪指令執行。

### 消息處理反饋

Multica 收到釘釘消息後，會嘗試在使用者原消息上新增釘釘的`收到`表情，以表示已將消息交由 Agent 處理；Agent 處理完成、併成功將消息傳送到釘釘後，`收到`表情會被替換為`Done`；任務被取消後，會撤回`收到`表情。

表情反饋依賴釘釘介面，不保證即時更新。判斷結果時請結合 Bot 回覆和 Multica 中的執行記錄。

### 使用 `/issue` 建立任務

傳送 `/issue <標題>` 或者 `/issue <標題>{換行}<詳細描述>`，就可以建立一個新 Multica 任務，並自動指派給 Bot 連接著的 Agent。同一條消息內的圖片也會以附件的形式新增到該任務中。跟普通對話消息不一樣的是，`/issue` 指令不會在 Multica 的“[對話](/chat)”中留下記錄。

### 使用 `/new` 新建 Chat

傳送 `/new` 會建立一個新的空 Multica Chat，後續釘釘消息會路由到新 Chat。傳送 `/new <消息>` 會建立新 Chat，並把消息作為第一輪。之前的 Chat 仍儲存在 Multica 中，可以繼續使用。

### 使用 `/clear` 清空當前上下文

傳送 `/clear` 會保留當前 Multica Chat，並把新的 Agent 可見上下文應用到下一條消息。傳送 `/clear <消息>` 會把消息作為邊界後的第一輪。完整 Chat 歷史仍會顯示在 Multica 中。

## 管理連接

- 在 **Agent → _你的 Agent_ → 能力 → 整合**頁面，Agent 建立者與工作區 owner/admin 可以連線或中斷連線。連線後會顯示 Bot 名稱、成功處理訊息的群組及活躍狀態；具有 Agent 檢視權限的工作區成員都能查看。最近 90 天沒有成功處理訊息的群組會歸入**長期未活躍**，展開時才載入。
- 在**設定 → 訊息頻道 → 釘釘**頁面，可查看目前工作區內所有有檢視權限且已連線釘釘的 Agent，以及 Bot 在群組中的活躍狀態。工作區 owner/admin 可以中斷列表中任一 Agent 的釘釘連線，或將群組從列表移除。中斷連線會停止 Bot 收訊，但保留安裝紀錄供稽核；移除群組不會刪除對話或訊息。已關聯釘釘帳號的成員日後再次在群組中 @ Bot，且 Multica 成功收到訊息時，群組會重新出現。


## 自部署設定

Multica Cloud 使用者可跳過本節。自託管部署需要先設定一個用於加密釘釘 `AppSecret` 的密鑰：

```dotenv
MULTICA_DINGTALK_SECRET_KEY=<base64-encoded 32-byte key>
```

可以這樣生成：

```bash
openssl rand -base64 32
```

重啟 API 服務後，再連接釘釘。該密鑰需要長期儲存：更換或丟失後，已有 token 無法解密，需要重新連接。

帳戶綁定連結使用 `MULTICA_APP_URL`，未設定時回退到 `FRONTEND_ORIGIN`；它需要指向成員可以訪問的 Multica 地址。
