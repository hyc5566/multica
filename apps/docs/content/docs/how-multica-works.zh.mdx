把一個任務分配給Agent後，Multica 會建立一條執行，由連線電腦上的runtime領取。runtime呼叫本地 AI 開發工具，並把進度和結果寫回原來的任務。

## 一次執行的完整路徑 [#一次執行的完整鏈路]

<RunPathDemo />

1. **任務提供上下文。** 任務儲存工作說明、討論和負責人。分配給Agent後，系統會使用該Agent的指令、模型、skill 和runtime配置。
2. **Multica 建立執行。** 執行進入佇列；沒有線上runtime時，它會在佇列中等待。
3. **runtime領取這次執行。** 連線電腦上的線上runtime領取後，呼叫Agent配置的 AI 開發工具。
4. **AI 開發工具在本地執行。** 工具讀取工作目錄、執行命令並生成結果。
5. **結果寫回任務。** 進度、留言和結果顯示在任務的時間線與執行日誌中。

任務、Agent、執行和執行環境的完整清單與關係，請參閱[核心概念](/concepts)。

## 資料和執行的界線

| Multica | 連接的電腦 |
|---|---|
| 工作區、任務、留言和狀態 | AI 程式開發工具及其憑證 |
| Agent 設定與 skill | 程式碼目錄和本機檔案 |
| 執行狀態、紀錄和結果 | 實際檔案變更與命令執行 |

這項界線在 Multica Cloud 和自行託管的部署中都相同。

<Callout type="warning">
有一個例外：儲存在 Agent `custom_env` 的內容會存放在 Multica 伺服器，並在執行時傳給執行環境。請勿將不應離開電腦的祕密資訊寫入 `custom_env`。
</Callout>

## Agent 的觸發方式

Agent不會自己開始工作，每次執行都由一個明確的動作觸發：分配任務、在留言中 @Agent、直接對話，或自動化。怎麼選、有哪些通用規則，見[讓Agent開始工作](/triggering-agents)。

## 執行結束與任務完成 [#執行結束與任務完成]

執行日誌顯示"已完成"，只表示這一次執行已經結束。任務仍然可以繼續討論、補充要求或再次觸發Agent；任務是否完成，看實際工作進展和它的狀態。
