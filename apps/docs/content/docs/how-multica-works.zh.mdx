把一個任務分配給 Agent 後，Multica 會建立一次執行，由連接電腦上的執行環境領取。執行環境調用本地 AI 編程工具，並把進度和結果寫回原來的任務。

## 一次執行的完整鏈路

![一次執行的流程圖：左側 Multica 區域負責記錄與調度，任務觸發建立執行；右側"你的電腦"區域中，守護程序領取執行、啟動 AI 編程工具、讀寫工作目錄；過程消息實時流回執行日誌，最終結果由守護程序寫回任務](/images/docs/how-a-run-works.webp)

1. **任務提供上下文。** 任務儲存工作說明、討論和負責人。分配給 Agent 後，系統會使用該 Agent 的指令、模型、skill 和執行環境設定。
2. **Multica 建立執行。** 執行進入隊列；沒有在線執行環境時，它會在隊列中等待。
3. **執行環境領取本次執行。** 連接電腦上的在線執行環境領取後，會調用 Agent 設定的 AI 編程工具。
4. **AI 編程工具在本地執行。** 工具讀取工作目錄、執行命令並生成結果。
5. **結果寫回任務。** 進度、留言和結果顯示在任務的時間線與執行日誌中。

任務、Agent、執行和執行環境的完整清單與關係，見[核心概念](/concepts)。

## 資料與執行的邊界

| Multica | 連接的電腦 |
|---|---|
| 工作區、任務、留言和狀態 | AI 編程工具及其憑據 |
| Agent 設定與 skill | 程式碼目錄和本機檔案 |
| 執行狀態、執行記錄和結果 | 實際的檔案修改與命令執行 |

這條邊界在 Multica Cloud 和自託管中相同。

<Callout type="warning">
有一個例外：儲存到 Agent `custom_env` 的內容會存放在 Multica 伺服器端，執行時傳給執行環境。不希望離開你電腦的 secret，不要寫進 `custom_env`。
</Callout>

## Agent 的觸發方式

Agent 不會自己開始工作，每次執行都由一個明確的動作觸發：分配任務、在留言中 @Agent、直接對話，或自動化。四種方式的選擇和通用規則見[讓 Agent 開始工作](/triggering-agents)。

## 執行結束與任務完成

執行日誌顯示"已完成"，只表示這一次執行已經結束。任務仍然可以繼續討論、補充要求或再次觸發 Agent。任務是否完成，以實際工作進展和它的狀態為準。
