將任務指派給 Agent 後，Multica 會建立一次執行，並由連線電腦上的執行環境領取。執行環境會呼叫本機的 AI 程式開發工具，再把進度和結果寫回原任務。

## 一次執行的完整流程

![一次執行的流程圖：左側 Multica 區域負責記錄與排程，任務觸發建立執行；右側"你的電腦"區域中，常駐程式領取執行、啟動 AI 程式開發工具並讀寫工作目錄；進度訊息即時送回執行日誌，最後由常駐程式將結果寫回任務](/images/docs/how-a-run-works.webp)

1. **任務提供執行所需資訊。** 任務保存工作說明、討論和負責人。指派給 Agent 後，系統會套用該 Agent 的指令、模型、skill 和執行環境設定。
2. **Multica 建立執行。** 執行會進入佇列；如果沒有執行環境在線，就會留在佇列中等待。
3. **執行環境領取工作。** 連線電腦上的執行環境上線後會領取執行，並呼叫 Agent 設定的 AI 程式開發工具。
4. **AI 程式開發工具在本機執行。** 工具讀取工作目錄、執行命令並產生結果。
5. **結果寫回任務。** 進度、留言和結果會顯示在任務時間軸與執行日誌中。

任務、Agent、執行和執行環境的完整清單與關係，請參閱[核心概念](/concepts)。

## 資料和執行的界線

| Multica | 連接的電腦 |
|---|---|
| 工作區、任務、留言和狀態 | AI 程式開發工具及其憑證 |
| Agent 設定與 skill | 程式碼目錄和本機檔案 |
| 執行狀態、紀錄和結果 | 實際檔案變更與命令執行 |

這項界線在 Multica Cloud 和自行託管的部署中都相同。

<Callout type="warning">
有一個例外：儲存在 Agent `custom_env` 的內容會存放在 Multica 伺服器，並在執行時傳給執行環境。請勿將不應離開電腦的祕密資訊寫入 `custom_env`。
</Callout>

## Agent 的觸發方式

Agent 不會自行開始工作，每次執行都由明確動作觸發：指派任務、在留言中 @提及 Agent、直接聊天，或透過自動化。四種方式的選擇及共通規則請參閱[讓 Agent 開始工作](/triggering-agents)。

## 執行結束與任務完成

執行日誌顯示"已完成"，只代表這次執行已結束。任務仍可繼續討論、補充要求或再次觸發 Agent。任務是否完成，要看實際進度和任務狀態。
